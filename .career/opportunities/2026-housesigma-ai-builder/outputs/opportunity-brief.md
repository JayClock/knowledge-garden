## 项目排序

1. **项目 1：AI 辅助领域建模与 API 设计平台**。作为主要项目，证明模糊需求收敛、AI 协作、审核与下游契约消费。
2. **项目 2：HATEOAS 与 TypeScript SDK**。证明根因判断、前后端协作、存量改造、兼容验收与可复用工程交付。
3. **项目 3：企业级低代码工作流引擎**。证明复杂前端与执行内核能力，展开依赖顺序、分支汇合与上下文隔离。
4. **项目 4：企业级前端监控 SDK 与数据采集系统**。证明从排障问题倒推事件设计、多框架采集、端侧上报与后端异步处理能力，并以系统响应性能提升 50% 说明已确认成果。

自我介绍保留全部四个项目，各自说明问题、动作或能力角色。工作流与监控 SDK 按两个独立项目表达。

## 已冻结的选材依据

- 所有职业内容来自本包选用的 confirmed claims；招聘要求只决定选材和表达。
- 领域建模按当前增量建模、范围确认、有效检查交接、API 校验与静态向量派生表达；技术栈采用 Electron、React、React Flow、Pi SDK、OpenAPI，本岗位材料不选用 MCP 同步分支或 FM JSON 技术栈列项。
- 全部项目的 Monorepo 统一采用 Nx + pnpm；工作流和监控技术栈消费源码核对后的 confirmed claims。HATEOAS 按用户于 2026-10-21 指定的清单统一为 TypeScript、React Hooks、HAL / HAL-FORMS、Zod、Nx + pnpm、Vite、Vitest、MSW、Testing Library、TypeDoc；源码快照的其他依赖不自动进入当前技术栈或扩大职责范围。
- HATEOAS 服务端 API 表达由本人参与契约设计并与后端共同落地。工作流 SSE 服务端推送与前端接入由本人实现，其他 API 与 PostgreSQL／Prisma 持久化仍由后端同事负责。
- 监控 SDK、NestJS 数据接收、Kafka 异步处理与 ClickHouse 存储查询由本人实现；系统响应性能提升 50% 沿用已确认原口径，测量方法作为技术追问补证。
- 工作流按普通业务工作流表达。库销存 Agent 是领域建模的真实应用案例，保持各项目语境独立。
- 公开 SDK 的 34 个测试文件、233 项通过测试属于公开仓库口径，与生产 workflow 回归测试分开。

- HATEOAS 项目介绍中的“80% 功能模块、相关任务成本减半”保留在原稿待确认，本岗位包继续使用已确认的导航、业务动作与公开 SDK 验证结果。CRM 电话销售作为领域模型到 API 的设计示例，真实应用仍采用已确认的采购履约案例。

这些信息用于内部选材与核对，对外正文以正向动作和自然协作关系呈现。
