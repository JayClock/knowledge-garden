## 领域建模：2 分钟版本

这个项目解决的是业务讨论难收敛、讨论结果难维护的问题。团队原来依赖会议和白板，和 AI 讨论时也容易不断增加候选。我设计了建模 Skill 和领域建模平台，把业务理解记录为模型，再用于 API 契约与测试数据生成。

对于有权责约定的业务，工作流从人提供的真实约定和主要履约进入。AI 围绕谁承担责任、提出什么要求、用什么凭证证明结果逐项澄清，并检查异常履约和后续责任。模型把参与方、对象、关系和规则组织成结构化资产。

一个关键点是区分生成模型和业务审核。实际使用的版本会在 Discovery 保留人类输入、AI 补充及来源，让模型可以反向追溯。AI 补充内容可以先写成 Rule，模型经过人类审核与修改、通过后，才进入后续 API 和测试数据生成。

平台还提供结构化 Proposal 的定位、预览和逐项采纳或拒绝，通过草稿、审核与版本发布管理模型演进。发布模型用于形成 RESTful API 候选、OpenAPI 草稿和正常、异常测试数据，为前后端提供明确契约。

平台通过 MCP 同步固定修订的快照，本地校验后，经授权更新托管文件，冲突时保留当前模型。

在真实库销存 Agent 场景中，我们从采购合同建模发货、收货、退货和履约凭证，跑通模型到接口消费的路径。平台由内部业务、产品和研发持续使用，交付通过单元、契约、E2E 测试与人工审核验证。

## HATEOAS 提取词

多端状态与权限重复｜资源关系与动作模板｜SDK 和 React 消费层｜增量改造与后端协作｜动态表单｜回归验收｜公开 npm 包

## HATEOAS：2 分钟版本

这个项目从低代码平台的多端一致性问题开始。PC 和移动端各自维护权限、状态与按钮规则，服务端规则变化后，端侧容易漂移。我设计并实现了 HATEOAS TypeScript SDK 和 React 消费层，让多端消费同一套资源关系与动作契约。

SDK 用 follow 导航关系，用 action 消费 HAL-FORMS 模板，分开处理网络请求、协议解析与资源消费。业务页面根据服务端 properties 生成校验与表单描述。

推进时，重点是让后端协作方看到增量改造成本和数据更新风险可控。我们先做工作区导航试点，在响应里增加 links 和 templates，保持表结构、原有请求参数和保存接口响应不变，PC 和移动端改为 SDK 消费，同时保留 BFF 迁移退路。我负责模型、契约与客户端实现，并和后端协同落地 API 表达。

验收分开进行。导航用 MSW 模拟有、无 workflow relation 的响应，在 Vitest 中渲染组件、检查 DOM。保存和发布则用 AI 辅助生成端到端测试，前后端实现后回归；保存场景以相同输入对比原有响应 JSON，检查兼容性。

SDK 还处理请求去重、资源缓存及依赖失效传播。通用消费层后来抽离为两个 npm 包，建立构建、类型检查、测试和自动发布流程；公开版本有三十四个测试文件、二百三十三项通过测试。

## 工作流提取词

画布配置到实际执行｜统一协议｜DFS 与 Kahn｜条件分支与公共汇合｜独立上下文｜节点插件｜变量与公式 AST｜后端 SSE 接入

## 工作流：2 分钟版本

这个项目是低代码平台的普通业务工作流能力，让用户通过拖拽节点和配置条件组合流程。我负责统一协议、可视化编辑器、变量与公式编辑器，以及 TypeScript 执行引擎。

首先要让画布配置和运行时使用同一份定义。协议记录节点、配置与连线；引擎构建邻接表、反向邻接表和入度表，用 DFS 检测环路、Kahn 算法规划拓扑执行顺序。每次运行创建独立上下文，按节点 ID 保存输出，避免不同运行的数据混在一起。

比较难的是条件分支与公共汇合。未选分支需要跳过，但两条路径可能连接同一个下游。如果无差别递归排除，会把公共节点也删掉。我检查汇合节点的其他活跃入边，只要还有有效前驱就保留，所有入边都失效时才继续向下排除。

节点扩展通过注册表与基类完成，把配置校验、变量解析、计时和错误结果统一起来，具体业务放在执行器。节点失败先返回统一失败结果，引擎再停止后续执行并收束工作流结果。

编辑侧用 React Flow 完成编排，Tiptap 把变量引用做成不可拆分标签，保存为表达式，运行时从本次上下文取值。公式解析器将表达式转成记录稳定字段 ID 的 AST，保存时校验，节点执行时求值。

最后，我和后端共同制定协议，接入 SSE 展示节点状态、日志与错误，通过测试运行面板检查配置和路径，完成从编排到执行反馈的核心链路。

## 监控 SDK：2 分钟版本

我独立负责前端监控 SDK 的采集与上报侧，从下游验收和排障需要回答的问题，倒推事件、上下文与关联标识。页面慢、请求失败与运行时错误需要不同证据，统一协议要支持这些判断。

SDK 用 pnpm Monorepo 拆成 core、browser 和 React、Vue 适配包。core 保留事件协议、插件、队列与 Transport；browser 封装浏览器采集；框架适配包处理生命周期。采集逻辑与发送策略分开，多种技术栈复用同一套协议。

性能侧通过 PerformanceObserver 和 Web Vitals 采集 FCP、LCP、CLS、TTFB 与 INP；异常侧监听全局错误和未处理的 Promise 拒绝。DOM、Fetch、XHR 和导航的采集提供操作、请求及页面上下文。

采集保持宿主业务的调用、返回值与请求行为，围绕排障需要保留上下文，发送交给统一队列与 Transport。

事件先进入本地队列，按时间间隔、数量阈值或路由变化批量发送，减少零散请求，再结合失败重试和弱网处理，平衡实时性、请求开销与可靠性。生产 Sourcemap 上传后与构建版本对应，供压缩异常堆栈还原到源码位置。

SDK 覆盖平台的前端业务模块，支持 Vanilla、React 和 Vue。后端及大数据团队负责数据服务和控制台，我通过稳定的事件协议与他们对接，让采集和上报结果能够用于运行诊断。
