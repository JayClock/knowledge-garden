# 自我介绍

- **工作流与 HATEOAS**：画布、变量与公式｜执行与日志｜前后端权限判断重复｜资源关系与动作契约｜统一 SDK

- **监控与工程**：性能与异常｜采集上报｜Sourcemap｜Nx + pnpm

## 完整版本

面试官你好，我有 5 年以上的前端开发经验，主要用 React，过去做的主要是复杂的 B 端系统。除了前端开发，我也擅长借助 AI，把工作往上下游延伸，更好地和不同岗位的同事配合。

比如做低代码系统时，我主要负责工作流引擎，从前端的流程画布、变量和公式编辑，到执行引擎和运行日志都有涉及。在这个过程中，我发现权限一复杂，前后端就需要各自维护一套判断逻辑，后端规则一变，前端也要跟着改。所以我推动引入了超媒体资源契约，和后端一起设计资源关系和动作契约，让服务端告诉前端，当前有哪些操作可以做。我也编写了统一的 SDK，让前端通过同一套方式访问资源、调用这些操作。

但在和后端讨论接口时，我又发现，接口怎么设计，首先取决于大家对业务的理解。而我们之前主要靠头脑风暴来讨论业务，沟通成本比较高，也不一定每次都能讨论清楚。所以我进一步落地了一套以合同上下文为起点的统一建模方法，借助 AI 把合同参与方各自的权责，以及履约过程逐阶段梳理清楚，把讨论结果逐步梳理成结构化的业务模型。模型经过检查和人类审核后，再用来生成 API 契约和测试数据。支撑前后端开发。

另外，为了方便开发同事定位问题，我还设计过内部监控的数据采集和上报，覆盖性能和异常信息，并用 Sourcemap 把异常堆栈还原到源码位置。工程上，我使用 Nx + pnpm 组织多包项目。

这些经历里，我的出发点一直是前端开发，但遇到问题时，我会再往上下游多看一步，和相关同事一起把业务理解、接口设计和实际开发衔接起来。这也是我希望继续发挥的优势。
