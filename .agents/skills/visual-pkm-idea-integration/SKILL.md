# Idea Integration Board 教练

## 目标

让 IIB 保存用户亲自形成的项目上下文。AI 帮助检查和维护空间，但不能用自动分类取代用户把材料放在一起时发生的思考。

## Human First Expression

用户先完成三个动作：

1. 写下一个中心项目、书籍或持续问题；
2. 亲自选出第一批必须进入房间的材料；
3. 做一次不必整齐的初步摆放，并说明至少一个位置选择。

如果用户只有“帮我建一个 IIB”，AI 只给空白启动提示，不搜索全库或生成完整分区：

```text
这个板围绕：
我首先想放进来的材料：
我会把……放在中心／旁边，因为：
我重新打开时最需要恢复的是：
```

## 分工

### 人类决定

- 板的边界和当前焦点；
- 哪些材料值得进入；
- 空间邻近、大小和连接的意义；
- 哪些洞见成熟；
- 哪些元素移动、删除、归档或晋升。

### AI 在初始板后建议

- 用户范围内可能遗漏或重复的真实文件；
- 布局中的冲突、遮蔽和上下文恢复风险；
- 候选聚类及其不同解释；
- IIB、Knowledge Map、Idea Mixer 和原子卡之间的边界；
- 下一次复查问题。

建议统一标记为 `AI 建议，待确认`。AI 不把空间邻近自动解释为关系。

## 与其他结构的边界

- **IIB**：围绕一个长期项目或问题的活工作区。
- **Knowledge Map**：少而稳定的关系和阅读路径。
- **Idea Mixer**：短期、轻量的意外碰撞。
- **Knowledge Note**：可独立复述的一项成熟命题。

IIB 可以容纳这些对象的引用，但不取代它们。

## 工作流

### 1. 人类建立初始房间

先聚集，不急着分类。人类从来源、笔记、草图、媒体、目标、疑问和当前输出中选择第一批材料，并亲自摆放。

优先链接或嵌入现有文件，不复制正文制造第二份事实来源。

### 2. 人类解释空间

用户至少解释：

- 中心是什么；
- 什么被放在一起以及为什么；
- 什么暂时不知道放哪里；
- 当前希望从板上做出什么决定。

没有解释的邻近只算暂定摆放。

### 3. AI 做第二遍检查

AI 才可以读取用户指定范围并提出：

- 可能遗漏的材料；
- 一项最值得测试的聚类；
- 一条可能被误读的连接；
- 一块可以移出视野的低频细节；
- 一个恢复上下文所缺的入口。

不要一次重构整块板。让用户亲自移动、组合和删除。

### 4. 人类重排并观察

用户根据建议选择是否移动。每次重排后先由用户说明看见了什么新模式，再由 AI 继续提问。

需要澄清单个复杂结构时调用 `visual-pkm-spatial-mapping`；成熟命题需要视觉正面时调用 `visual-pkm-concept-visualization`。

### 5. 周期复查

用户先回答：

- 当前焦点变了吗？
- 哪个聚类开始稳定？
- 哪项假设失效？
- 哪些材料不再相关？
- 哪个洞见值得晋升？

AI 再根据实际文件指出证据和风险，不替用户做取舍。

## 控制混乱

优先提出小范围动作：

1. 保留一个当前焦点；
2. 把低频细节移到来源或文字背面；
3. 把稳定结构提炼为 Map；
4. 把成熟命题提炼为 Note；
5. 把纯碰撞移到 Mixer。

所有移动和删除由用户确认。

## 文件实现

只有用户确认并明确要求执行后：

- `.canvas` 使用 `json-canvas`；
- Excalidraw 通过 Obsidian 插件维护，不手工修改 compressed-json；
- 保留用户已有布局、链接和 Embedded Files；
- 工作中的 IIB 留在用户指定位置，不自动进入稳定 Maps；
- 新出现的分类和关系必须再次确认。

## 默认回应格式

```markdown
## 你的 IIB 起点

## AI 建议，待确认
- 可能遗漏：
- 可测试的局部聚类：
- 一项混乱风险：

## 请你亲自移动／加入／移出

## 下次复查问题
```

## 完成检查

- 用户是否先选材料并完成初步摆放？
- AI 是否在用户空间表达之后才搜索和聚类？
- 邻近与明确关系是否区分？
- 用户是否亲自解释重排带来的发现？
- IIB 是否仍围绕一个项目或问题？
- 未经确认是否没有移动、删除或落盘？
