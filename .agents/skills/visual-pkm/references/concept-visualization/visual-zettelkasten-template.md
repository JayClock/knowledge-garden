# Visual Zettelkasten 知识卡约定

## 适用范围

创建新的 `Knowledge/Notes/` Visual Main Note，或为已有知识卡生成 Excalidraw 视觉正面时使用。项目模板位于 `content/Templates/知识卡.md`；意义选择遵守[Human First Expression 检查点](human-guided-checkpoints.md)，绘制与落库遵守[Visual Main Note 直接写入与 icon 自动提取](visual-main-note-write.md)。

本约定只规定知识接口。Visual Spec、联想、素材检索、配色过程、反馈日志和 icon 提取记录不写入知识卡正文。

## 正面与背面

- **视觉正面**：AI 根据用户文字说明生成的完整手绘 Excalidraw 构图，压缩一个原子命题并提供第一眼理解。主体、动作和关系优先由已有 icon、原生 pictogram 与空间语法承载；构图使用不对称、尺度差异和有机路径，文字只保留必要的短消歧标签。
- **文字背面**：核心观点、自己的解释、条件、证据、来源、上位问题和少量有方向的语义连接，为视觉增加精度与上下文。

视觉和文字是同一想法的两种接口，不能互相替代，也不要逐句重复。视觉不负责图解整张卡；文字不负责逐项描述画面。

## 意义与生产决定

用户决定：

- 核心命题；
- 自己的解释；
- 明确表达的视觉偏好和禁用项；
- 对成品的文字反馈；
- 最终核心措辞、`sources`、`up` 和知识连接。

AI 可以决定：

- 用户未说明的构图、对象、层级、比例和局部样式；
- 哪些短标签是读图所必需；
- 怎样把文字反馈转成可编辑视觉；
- 成品中哪些原生语义 group 值得自动提取为 icon。

AI 的决定属于可撤销的视觉实现，不自动成为用户偏好或知识主张。用户通过查看成品和文字反馈校准结果。

## 原子卡规则

- 一张卡只捕捉一个可以独立复述的想法。
- 内容放不下时先收缩视觉范围，再拆卡。
- 用持续问题组织卡片，而不是只按宽泛主题归档。
- 来源说明材料从哪里来，不自动构成卡片关系。
- 连接需要方向和推进作用；“因为／但是／因此”优于“然后”。
- 卡片应当便携、可复用，并能进入不同地图或叙事。

## 模板位置的职责

| 位置 | 作用 | 完成判断 |
|---|---|---|
| `title`／H1 | 为一个概念或命题命名 | 名词、名词短语或动名词，且两处一致 |
| abstract | 保存用户确认的核心主张 | 可独立复述，并与视觉正面一致 |
| 正文 | 用自己的话增加条件、意义与精度 | 不是来源摘抄、画面复述或过程日志 |
| `sources` | 记录材料来源 | 目标真实存在，不能代替语义关系 |
| `up` | 锚定持续问题、上位概念或地图 | 由用户确认，本卡确实推进它 |
| 知识连接（可选） | 显式写出带理由的关系 | 每条有方向、理由和真实目标 |
| Drawing | 保存一个完整视觉正面 | 能独立呈现核心命题，且保持原生可编辑 |

## 分层落盘顺序

### 1. 确认命题和目标

1. 用户提出或确认唯一核心命题；
2. 现有卡记录真实路径；
3. 新卡确认标题，搜索同名、aliases 和近义卡；
4. 用户发出生成／执行请求后进入写入。

### 2. 收集文字视觉说明

用户尽可能描述主体、动作、关系、构图、风格、颜色、标签和禁用项。说明可以不完整；AI 把未说明部分作为可修改的视觉实现补足。用户不需要提交绘图。

### 3. 确定视觉框架

AI 结合当前命题说明对比、隐喻、过程、单一图像和场景五种框架。用户可以选择，也可以授权 AI 根据文字说明选择。框架决定关系和空间语法。

### 4. 直接生成 Visual Main Note

完整执行[第 4 步直接生成完整视觉](direct-visual-generation.md)：

- 完整读取并执行[Icon First 视觉生成规则](icon-first-generation.md)；
- 使用 `/tmp/visual-pkm-concept-visualization/<slug>/visual-spec.json` 描述手绘 `composition_plan`、Icon First `representation_plan` 与完整构图；
- 通过 `scripts/write_visual_main_note.py` 检查主要语义表达和全部文字必要性，再完成内部 dry-run；
- 获得生成授权后直接写入目标知识卡；
- 新卡使用 `Templates/知识卡.md` 创建最小知识背面；
- Drawing 中直接出现完整主体、动作、关系和必要短标签；
- 现有正文、frontmatter、links 和非本轮场景元素保持不变；
- Visual Main Note 不添加可见的满幅背景矩形或外边框。

### 5. 文字反馈与视觉迭代

用户查看成品后，用文字提出保留、删除、移动、改色、改标签、换隐喻或改变强调的要求。AI 以相同 `visual_id` 更新视觉；只替换本轮 AI 元素。

每轮至少检查：

- 第一眼读法；
- 去除标题后的意义；
- 延迟后的清晰度；
- 视觉与核心命题是否一致。

### 6. 自动提取 icon 与校准两面

用户确认视觉成品后，AI 自动判断可提取 group。合格组件应上下文独立、原生、完整、可复用且不重复；完整构图、背景、关系线、本卡专属文字、已有 icon 和失去上下文就失义的局部不落库。

使用 `scripts/extract_visual_icons.py` 从插件保存后的 Drawing 机械提取，命名为：

```text
Icon - 关键词1, 关键词2 - 来源.excalidraw
```

每个组件必须是纯原生、单公共 group，不含 image／frame／embeddable。文件名是唯一索引，不建立注册表。

随后：

1. 用户确认最终 abstract；
2. 文字背面补充图像未承载的精度、条件、证据和意义；
3. 核对 `sources`；
4. 用户确认 `up`；
5. 执行[知识卡语义连接规则](card-connections.md)；
6. 删除模板提示、空节和占位内容。

## 配色

配色服务于用户文字意图、核心关系和可读性。项目语义色板是可选方案，不是生成、提取或完成 Gate。已有和自动提取的 icon 保留自身颜色；icon 内部颜色不进入项目色板审计。

只有用户明确要求统一项目视觉语言时，才通过插件／API应用[项目配色参考](palettes.md)。

## 完成检查

- **单意**：abstract 是否只有一个可判断主张？
- **两面一致**：视觉正面与文字背面是否表达同一个原子命题？
- **视觉完整**：Drawing 是否已经呈现主体、动作和关系，而不是用标题框代替？
- **Icon First**：是否先搜索本地 icon，再选择原生 pictogram、几何关系或必要文字？
- **手绘构图**：是否避免等宽卡片、完美网格和机械居中，并通过不对称、尺度差异或有机路径组织画面？
- **去文字**：隐藏全部文字后，是否仍能读出核心方向、对比或循环？
- **必要文字**：每个文字元素是否都有独立消歧理由？
- **用户输入**：核心命题和明确视觉约束是否来自用户？
- **AI 边界**：未说明细节是否只作为视觉实现，没有写成用户声音？
- **反馈闭环**：用户是否查看成品并用文字反馈或确认？
- **自动提取**：是否只从确认成品提取上下文独立且不重复的组件？
- **原生性**：新 icon 是否纯原生、单公共 group，并通过校验？
- **互补**：文字是否增加条件、证据、来源、连接与精度，而不是逐句说明画面？
- **独立**：不打开来源和链接，是否仍能理解？
- **锚定**：`up` 是否由用户确认并真正被本卡推进？
- **推进**：每条链接能否用“因为／但是／因此”解释？
- **清洁**：生产记录、模板提示、空节和悬空链接是否已删除？
