# Human First Expression 检查点

## 原则

概念可视化由用户决定“这张卡真正要表达什么”。用户通过文字提供核心命题和尽可能具体的样式说明；AI 可以在这些边界内决定构图、对象、层级和未说明的生产细节，直接生成完整视觉并写入 Visual Main Note。

Human First 保护的是意义归属，而不是绘图劳动：

```text
用户核心命题与文字视觉意图
→ AI 完整绘制并写入
→ 用户观看成品并用文字反馈
→ AI 迭代
→ 成品确认后 AI 自动提取可复用 icon
```

AI 的视觉实现不能反过来成为用户的核心命题，也不能把 AI 选择的风格、实例或标签写成用户已经表达的偏好。生成时遵守 Icon First 与手绘构图：AI 可以搜索和选择 icon、绘制原生 pictogram、采用不对称与有机路径并压缩标签，但这些仍是可撤销的生产决定。

## 什么算 Human First Expression

至少需要以下一种意义起点：

- 用户自己写的一句工作命题；
- 用户指向自己已有的知识卡，而卡片中有明确核心观点和自己的解释；
- 用户用文字描述想呈现的动作、差异、因果或关系；
- 用户已有的关键词、视觉碎片、截图或参考图。

单纯转发来源原文、只给主题名，或让 AI 决定“这张卡究竟是什么意思”，不算用户自己的意义表达。

## 文字视觉说明

核心命题明确后，请用户尽可能描述样式，但不使用表格问卷阻塞生成。可以用一句自然语言，例如：

```text
请直接画成左右对比：左边是保护专注的半透明边界，右边是被同一边界挡住的协作请求。手绘粗线、低饱和蓝灰，冲突处用橙色，只保留两个短标签。
```

用户可以只描述一部分。AI 应当：

- 保留用户明确指定的主体、动作、关系、颜色、标签和禁用项；
- 对主要主体、动作和状态先搜索本地 icon，再选择原生 pictogram、几何关系或必要短文字；
- 对缺失细节采用一个容易修改的实现；
- 把这些补足称为 `AI 视觉实现`，而不是 `用户选择`；
- 只有一个缺口会显著改变核心读法时，才提出一个聚焦问题；
- 直接把文字说明转化为可编辑视觉。

3–5 个关键词可以帮助联想。AI 可以从用户已经写出的文字说明中提取检索词和视觉对象。

## 四个检查点

| 检查点 | 用户负责 | AI 可以做 | AI 不得做 |
|---|---|---|---|
| 1 · 核心命题与目标 | 提出／确认一个原子命题；指定现有卡或确认新卡标题 | 检查单意性、读取用户现有卡、记录目标 | 从来源替用户生成核心意义；未定标题时擅自创建新卡 |
| 2 · 文字视觉说明 | 尽可能描述主体、动作、关系、构图、样式、颜色、标签和禁用项 | 提取视觉约束，扩展联想，补足未指定的生产细节 | 把 AI 补足写成用户偏好 |
| 3 · 框架与执行 | 选择、接受或用文字调整视觉框架；提出生成请求 | 解释五种框架；收到执行请求后直接生成完整视觉并写入目标卡 | 在用户只讨论时写入 |
| 4 · 成品反馈与网络 | 查看成品并用文字反馈；确认最终核心措辞、`sources`、`up` 和关系 | 迭代同一 `visual_id`；成品确认后自动判断并提取 icon | 提前从未定稿视觉落库；替用户决定知识连接 |

## 第 3 步的框架说明

AI 仍需根据当前命题解释：

1. 对比／对立：并置差异，突出“哪里不同”；
2. 隐喻式：把抽象关系映射到熟悉机制，突出“它像什么”；
3. 过程式：组织输入、变化与输出，突出“怎样发生”；
4. 单一图像式：用主导焦点压缩关系，突出“第一眼记住什么”；
5. 场景式：用角色、环境、动作和结果，突出“谁经历什么”。

用户可以明确选择，也可以用文字说明接受 AI 根据其视觉 brief 选择一个框架。若用户授权 AI 选择，AI 必须说明采用框架及原因。

## 写入授权

以下表达视为对已确认目标和文字说明的直接生成授权：

- “生成这张视觉知识卡”；
- “按这个描述画并写进去”；
- “直接生成完整视觉部分”；
- “执行／落盘／按这个方案修改”。

授权覆盖：

- 创建或初始化已确认的 Visual Main Note；
- 直接写入完整 Excalidraw 视觉；
- 根据本轮文字反馈替换相同 `visual_id` 的 AI 元素；
- 成品确认后自动判断并落库可复用 icon。

授权不覆盖：

- 改变核心命题；
- 新增未经确认的知识背面；
- 自动决定 `sources`、`up` 或语义连接；
- 修改其他卡片、地图或 Output。

用户说“先不要修改”“只讨论”“给我看看流程”时保持只读。

## AI 自动判断 icon 的边界

成品确认后，AI 可以不询问用户，自动把上下文独立、原生、完整且不重复的语义 group 提取到 Icon Library。自动判断不等于全部拆分：完整构图、背景、关系线、专属标签、已复用 icon 和离开本卡就失义的局部都应跳过。没有合适组件时，合法结果是零个新 icon。

所有提取结果必须：

- 来自插件保存后的成品 Drawing；
- 是纯原生、单公共 group 的 `.excalidraw`；
- 使用 `Icon - 关键词1, 关键词2 - 来源.excalidraw`；
- 先搜索相似组件，避免重复；
- 不改变原知识卡；
- 不创建额外索引或注册表。

## 快速对话节奏

生成前：

```markdown
你的核心信息：……
目标知识卡：……
你的文字视觉说明：……
AI 将补足：……
采用框架：……

你已经要求直接生成；我会先做内部检查，然后通过 Excalidraw 插件把完整视觉写入目标卡。
```

生成后：

```markdown
完整视觉已写入：Knowledge/Notes/……md
请直接查看成品，用文字告诉我希望保留、删除、移动、改色、改标签或改变强调的部分。
```

定稿后：

```markdown
成品已确认。AI 已自动检查可复用组件：新建……；复用／跳过……。Icon Library 校验：……。
```
