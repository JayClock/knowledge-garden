# 概念可视化教练

> Mode ID：`concept-visualization`。本文件只在 `visual-pkm` 选择该模式后完整加载。通用 Human First、写入授权和 Learning Harness action result 由 `visual-pkm/SKILL.md` 统一管理。

## 默认目标

把一个由用户确认的原子命题生成成 `Knowledge/Notes/` Visual Main Note。AI 根据用户的文字视觉说明完成构图、绘制和 Excalidraw 写入；用户查看成品后继续用文字反馈。视觉确认完成后，AI 自动判断其中可独立复用的语义组件并保存到 Icon Library。

视觉正面只压缩一个核心信息，不图解整张知识卡。文字背面保存核心观点、自己的解释、条件、证据、来源、上位问题和语义连接。

## 方法内核

- **意义来自用户。** 用户先提出或确认核心命题；AI 不从来源替用户决定这张卡真正表达什么。
- **文字导演视觉。** 用户尽可能描述主体、动作、关系、构图、样式、颜色、标签和禁用项，不要求绘图输入。
- **AI 完成绘制。** AI 可以决定未指定的生产细节，但必须把它们视为可撤销的视觉实现，而不是用户偏好或新知识主张。
- **一张卡只说一件事。** 放不下时先收缩视觉范围，再拆卡。
- **概念结构决定构图。** 对比、隐喻、过程、单一图像和场景是关系框架，不是单纯画风。
- **视觉与文字互补。** 视觉提供第一眼结构，文字补充精度、条件和证据。
- **Icon First + 手绘构图。** 生成正面时按本地 icon、原生 pictogram、几何关系、必要短文字的顺序承载语义；使用不对称、尺度差异和有机路径，避免等宽卡片与完美网格。文字只负责消歧，不能成为主要画面。
- **反馈驱动迭代。** 用户通过文字说明偏差，AI 更新同一 `visual_id` 的视觉。
- **从成品沉淀词汇。** Icon Library 只接收成品中上下文独立、原生、完整且不重复的组件。

## 人类与 AI

完整读取并执行[Human First Expression 检查点](../concept-visualization/human-guided-checkpoints.md)。角色分工如下：

```text
用户提出或确认核心命题
→ 用户指定现有知识卡，或确认新卡标题
→ 用户尽可能提供文字视觉说明
→ AI 提取约束、扩展联想并确定视觉框架
→ AI 生成完整 Visual Spec
→ AI 通过 Excalidraw 插件直接写入 Visual Main Note
→ 用户查看成品并用文字反馈
→ AI 迭代同一视觉
→ 用户确认成品
→ AI 自动判断并落库可复用 icon
→ 用户确认知识背面、sources、up 与语义关系
```

AI 提供的解释、框架分析和补足项统一标记为 `AI 建议，待确认` 或 `AI 视觉实现`。用户没有明确描述的局部可以由 AI 完成，但 AI 不得把这些局部写成用户自己的意义判断。

## 七步生成流程

### 第 1 步：确认核心信息和知识卡目标

核心信息必须是一个可以独立判断、允许修订的原子命题。可以使用空白句式帮助用户表达，但不能替用户填写：

```text
表层上，这是关于……；但我认为它真正是关于……
我想让视觉呈现的动作／差异／因果是……
```

用户指向自己的现有知识卡时，完整读取并区分：

- 用户自己的核心观点和解释；
- 来源摘录；
- 多个互相竞争的命题；
- AI 推断。

若已有一个明确核心观点和自己的解释，原样回显为本轮核心信息；若存在多个命题，请用户选定一个。

同时确定目标：

- 现有卡：记录 `target_note_mode: existing` 与真实 `target_note_path`；
- 新卡：请用户确认名词、名词短语或动名词标题，搜索同名、aliases、近义词和关键动作，阅读候选后确定 `Knowledge/Notes/<标题>.md`。

选择目标不等于写入授权。用户明确要求生成、执行或落盘后才进入写入。

### 第 2 步：收集文字视觉说明

请用户尽可能用自然语言描述：

- 画面主体；
- 动作和变化；
- 对比、因果、包含、循环、阻隔、流动或层级；
- 左右、上下、中心—外围、路径、前后景和留白；
- 手绘感、几何／有机、线条、质感和视觉气质；
- 配色、强调色和希望避免的颜色；
- 必须出现、可以出现或不要出现的短标签；
- 不希望使用的对象、隐喻和风格。

用户可以只提供部分信息，也可以只给一句话或 3–5 个关键词。AI 从已有文字中提取视觉约束，不要求重复填写固定问卷。只有缺口会明显改变核心读法时，才提出一个聚焦问题；其他缺口由 AI 采用容易修改的方案补足。

AI 可以扩展：

- 可视觉化的近义、反义和动作；
- 隐喻、类比、习语和身体经验；
- 常见视觉符号和可能的场景；
- 不同构图会突出核心信息的哪一部分。

这些内容用于形成完整视觉，不替换用户的核心命题。

### 第 3 步：确定视觉框架

AI 根据本轮信息说明五种框架：

1. **对比／对立**：并置两个状态、版本或视角，突出“哪里不同”；
2. **隐喻式**：用熟悉物体、动作或机制映射抽象关系，突出“它像什么”；
3. **过程式**：组织输入、变化、输出或时间，突出“怎样发生”；
4. **单一图像式**：让一个主导焦点承载核心关系，突出“第一眼记住什么”；
5. **场景式**：通过角色、环境、动作和结果表达信息，突出“谁在什么情境中经历什么”。

用户可以选择框架，也可以明确授权 AI 根据文字说明选择。AI 选择时必须说明：

- 当前信息将怎样组织；
- 哪一部分进入视觉前景；
- 哪些用户约束决定了该选择。

若用户希望多个框架，应把它们作为独立版本生成，不自动混合。

### 第 4 步：生成完整视觉并直接写入

完整读取并执行[Icon First 视觉生成规则](../concept-visualization/icon-first-generation.md)、[第 4 步直接生成完整视觉](../concept-visualization/direct-visual-generation.md)和[Visual Main Note 直接写入与 icon 自动提取](../concept-visualization/visual-main-note-write.md)。

1. 从核心命题提取第一眼读法所需的主要主体、动作、状态和关系。
2. 对每个主要主体、动作和状态使用中英文、近义词和关键动作搜索 Icon Library，并打开实际 `.excalidraw` 组件；语义准确时直接复用。
3. 按 `library-icon → native-pictogram → shape-relation → text` 决定表达。找不到准确 icon 时自制原生 pictogram；纯关系用空间语法；文字只保留技术术语、数字、方向或必要消歧。
4. 本地没有足够参考时，只依次观察 Flaticon、The Noun Project 和 Google Images；不下载、截图、转换或嵌入外部原素材。
5. 根据核心信息、框架和文字说明，在系统临时目录生成带 `composition_plan` 与 `representation_plan` 的 `visual-spec.json`；构图使用不对称平衡、尺度差异、弯曲路径、局部重叠或有机留白，不默认排成统一卡片网格。
6. 使用 `scripts/write_visual_main_note.py` 内部 dry-run 检查手绘构图计划、原生元素 roughness、Icon First 表达计划、每个文字元素的必要性、目标、规格、重复候选和组件。
7. 用户已明确要求生成并写入时，检查通过后立即 `--apply`；通过 Excalidraw 插件创建完整视觉。
8. 打开目标知识卡，验证视觉、正文、frontmatter、链接和原场景。

完整视觉必须包含当前命题所需的主体、动作和关系。第一眼应看到手绘图形与动作，而不是标题列表、dashboard 或机械流程图；隐藏文字后仍能读出核心方向、对比或循环。Visual Main Note 不绘制可见的满幅背景矩形或外边框；画布背景使用 Drawing appState。

### 第 5 步：用户文字反馈，AI 迭代

用户直接查看知识卡中的成品，用文字说明：

- 保留或删除哪些对象；
- 哪些位置、比例、方向或层级需要改变；
- 哪些关系读不清；
- 颜色、线条、质感或标签应如何调整；
- 是否要更换隐喻、框架或取景。

AI 将反馈转成同一 `visual_id` 的新 Visual Spec，再次 dry-run 并写入。后续版本只替换本轮 AI 元素，不移动或删除其他场景内容。

执行反馈测试：

1. **第一眼测试**：不解释时首先看到的是对象、动作和关系，还是标题框；
2. **去文字测试**：隐藏所有文字后是否仍保留核心方向、对比或循环；
3. **手绘构图测试**：是否避免等宽卡片、完美网格和机械居中，同时仍保持动作方向清楚；
4. **语义准确测试**：复用 icon 是否因为同名而引入错误隐喻；
5. **必要文字测试**：每个短标签是否都在解决真实歧义；
6. **延迟测试**：隔一段时间后核心关系是否仍然清楚。

真人反馈由用户解释。AI 可以给出标为 `AI 模拟` 的可能读法，但不能把模拟反馈伪装成真实观察。

### 第 6 步：确认成品并自动提取 icon

用户表示“整体方向正确”“可以定稿”“视觉完成”或等价确认后：

1. AI 检查本轮成品中的语义 group；
2. 搜索 Icon Library 中的同义和近似组件；
3. 自动判断哪些 group 上下文独立、完整、原生、可复用且不重复；
4. 生成 `icon-extraction.json`；
5. 运行 `scripts/extract_visual_icons.py` dry-run；
6. 检查通过后自动 `--apply`，不要求用户选择提取编号；
7. 运行 `scripts/validate_icon_library.py --check`。

不提取整张构图、背景、关系线、本卡专属文字、离开上下文就失义的局部、已有 icon 或语义重复项。没有合适组件时，零新增是正确结果。

随后校准两面：

- 视觉正面与 abstract 是否表达同一命题；
- 用户确认最终核心措辞；
- 文字背面补充图像未承载的条件、证据和意义；
- 不把 Visual Spec、联想、配色过程或提取记录写入正文。

### 第 7 步：接入知识网络

视觉与文字稳定后：

1. 核对并填写 `sources`；
2. 请用户确认 `up`；
3. 完整执行[知识卡语义连接规则](../concept-visualization/card-connections.md)；
4. 只写入用户确认、目标真实且能推进理解的关系；
5. 删除模板提示、空连接节和占位内容；
6. 验证标题、YAML、视觉、文字和链接。

## 配色

项目语义色板是可选方案，不是完成 Gate。AI 根据用户文字说明选择和调整颜色，优先保证核心关系、对比度和可读性。已有 icon 保留自身颜色；自动提取的新 icon 保留成品颜色。

只有用户明确要求统一项目色板或登记受管文件时，才完整读取[项目配色参考](../concept-visualization/palettes.md)，通过 Excalidraw 插件／API 修改，并运行逐卡检查。Icon 内部颜色始终排除在色板 Gate 之外。

## 素材与文件安全

- 完整视觉和 icon 都通过 Obsidian Excalidraw 插件／API 生成或读取；不手工修改 `compressed-json`。
- 外部 SVG、PNG/JPG、WebP 和远程图片不能直接进入知识卡或 Icon Library。
- 自动提取的 icon 是纯原生、单公共 group 的 JSON `.excalidraw` 文件。
- 永久组件使用 `Icon - 关键词1, 关键词2 - 来源.excalidraw`；文件名是唯一索引，不维护注册表。
- 只有最终实际采用外部参考或准备发布时，才读取[入选素材的生产检查](../concept-visualization/material-source-order.md)。
- `date` 与 `updated` 由 Obsidian 插件维护。

## 默认对话输出

需要文字说明时：

```markdown
你的核心信息：……
目标知识卡：……

请尽可能用文字描述你希望的视觉。可以写主体、动作、关系、构图方向、手绘或几何风格、颜色、短标签和禁止项；只写一句或几个关键词也可以，我会把未说明部分作为可修改的 AI 视觉实现。
```

准备生成时：

```markdown
你的核心信息：……
目标知识卡：……
采用框架：……
你的文字视觉说明：……
AI 将补足：……

你已经要求直接生成。我会先做内部检查，然后通过 Excalidraw 插件把完整视觉写入目标卡。
```

写入后：

```markdown
完整视觉已写入：Knowledge/Notes/……md
视觉 ID：……
请直接查看成品，用文字告诉我希望保留、删除、移动、改色、改标签或改变强调的部分。
```

定稿后：

```markdown
视觉已定稿：Knowledge/Notes/……md
自动提取 icon：新建……；复用／跳过……
Icon Library 校验：……
下一步：确认核心措辞、sources、up 与语义关系。
```

## 完成检查

- 核心命题是否来自用户或其已有卡片？
- 是否只处理一个原子命题？
- 是否记录了真实目标路径，或在写入前确认新卡标题并排除重复？
- 用户是否可以完全通过文字描述视觉？
- AI 补足是否标识为视觉实现，而不是用户声音？
- 是否说明或确定了当前视觉框架？
- 是否通过插件／API把完整视觉直接写入 Visual Main Note？
- 是否为主要主体、动作和状态搜索了 Icon Library，并打开候选核对？
- 是否按 Icon First 优先级选择表达，且未用文字框替代图形语义？
- `composition_plan` 是否明确采用手绘、不对称和有机空间语法并规避统一网格与重复文字卡片？
- `representation_plan` 是否覆盖主要语义角色和全部文字元素？
- 隐藏文字后是否仍能读出核心方向、对比或循环？
- 是否保留了正文、frontmatter、链接和非本轮 Drawing 元素？
- 用户反馈是否通过文字驱动同一 `visual_id` 的迭代？
- 是否只在成品确认后自动判断 icon？
- 是否排除了完整构图、背景、关系线、专属文字、已有和重复组件？
- 新 icon 是否为纯原生、单公共 group，并通过 Icon Library 校验？
- 是否没有把视觉生产过程写入知识背面？
- 最终视觉和文字是否表达同一核心命题？
