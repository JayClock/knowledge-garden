# 经历发现与长期文档

## 开局

先用现有上下文判断，不把分诊变成另一张问卷。

| 情况           | 下一步                                 | 避免                                   |
| -------------- | -------------------------------------- | -------------------------------------- |
| 材料多、不紧急 | 先读出时间线、强线索和缺口，选一段深挖 | 重新询问简历已经写明的学校、公司和时间 |
| 材料少、不紧急 | 拉粗时间线，再选代表事件               | 要求完整 STAR 或量化成绩才开始         |
| 材料多、紧急   | 先看 JD，选最有支撑的经历核实          | 先整理完整职业史才服务岗位             |
| 材料少、紧急   | 问目标岗位和一段相关经历，边确认边交付 | 为赶时间虚构指标或职责                 |

有材料时可以说：“我先看到三条线索……其中这段只写了技术栈，我想先补清楚你实际解决的问题。”

没材料时可以说：“先不用准备完整简历。你最近一段工作是什么？有没有一件你觉得最能代表自己的事？”

## 递进问题库

只选当前缺失且值得问的问题；用户已经答过就跳过。

1. 背景：“当时为什么要做？不做会影响什么？”
2. 边界：“你直接负责哪部分？谁决定方向，谁负责其他模块？”
3. 动作：“你先做了什么？后来为什么调整？”
4. 取舍：“最难的是哪里？你考虑过哪些办法，为什么选这个？”
5. 验证：“后来怎么判断做成了？有验收、测试、运行记录或实际变化吗？”
6. 成长：“现在回头看，你会保留什么、改掉什么？”

不要问“你主导后提升了多少”这类同时预设职责和结果的问题。没有失败故事不强求事故，没有数字不把经验判为无价值。

## 小版本与收口

每约四个关键问题或信息已足够时，给出轻量小结，而不是完整简历：

```text
当时的问题是……
你直接做的是……，团队其他部分是……
目前能确认的是……
还需要核实的是……

你先纠正这段、继续挖一个难点，或先用已确认部分服务当前岗位？
```

用户开始疲惫、当前目标已能被支撑或时间有限时暂停。把剩余问题留给下一轮，不能通过推测补齐成果。

## 职业经历文档

本仓库固定输出到 `content/Knowledge/Outputs/职业经历.md`，通过 `config.paths.career_history` 定位。它是可持续审阅的通用经历文档，不跟随不同 JD 反复换定位。

按已有事实组织，缺失部分不造占位经历：

- 职业时间线：教育、工作、角色和重要转折；
- 代表经历：背景、个人动作、核心机制、交付结果与应用情况，顺序随经历自然变化；不设立专门的免责式边界小节；
- 成长与反思：用户确认的选择、失败、认识变化；
- 来源链接：链接实际存在的项目材料，内部使用 wikilink。

待补问题统一保存到 `positioning.open_questions`，默认不作为职业经历文档的章节；仅在用户明确要求时展示摘要，写问题，不把未确认成果写成正文事实。

避免每段套用同一技术栈模板，也不要求所有经历都有数字。manifest 承担 claim 依赖记录，正文不堆内部 ID。

### 人工修改处理

1. 写入前读取当前全文及 Git diff，并逐段对照 claims。已提交的人工修改也要识别。
2. 分开处理纯措辞、事实补充、事实纠正与疑问批注。纯措辞可以保留；事实变化进入核对。
3. 用户本轮明确确认的修改记录为 user_confirmation；来源或意图不明则保持 candidate／contested，提出最小确认问题。
4. 不用旧账本覆盖新增段落。未解决段落保留并注明待确认，文档 manifest 保持 stale；未经授权不搬移或删除用户文字。
5. 在冲突解决、事实落账且文档同步后才设 current。current 文档的已确认正文只消费 confirmed claims。
6. 下游简历、面试包仍从 confirmed claims 选材，不能把职业经历中的批注当作事实。

### 跨会话继续

`positioning.open_questions` 使用可读字符串保存未解项，每项包含：经历、问题、已知内容、关联 claim（如有）、优先原因、下一步。例如：

“监控接入｜待确认验收方式｜已确认接入，未确认使用方｜关联 project.telemetry｜影响当前岗位回答｜用户查找验收记录后继续。”

继续补充时以 `positioning.open_questions` 为未解问题入口，不因职业经历文档没有待补章节就丢弃或重新生成这些问题。解决后移除或收束对应问题；若用户曾明确要求在文档中展示摘要，也同步更新，避免反复询问。

## 边界

只有经历整理与保存得到授权时才创建文档。初始化只配置路径，不生成空白职业史、不虚构个人内容。已有文件无 manifest 时先核对，不因文件存在而自动认定可信。
