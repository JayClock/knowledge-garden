# Visual Zettelkasten 知识卡约定

## 适用范围

创建新的 `Knowledge/Notes/` 知识卡，或把已有卡片调整为可独立理解、可复用且有方向连接的 Visual Main Note 时使用。项目模板位于 `content/Templates/知识卡.md`，意义选择同时遵守[人类主导的快速检查点](human-guided-checkpoints.md)。

本约定只规定知识接口。视觉联想、方向比较、素材搜索、LEGO 规格、配色和 ETC 属于思考或生产过程，不写入知识卡正文。

## 正面与背面

- **视觉正面**：一个草图、场景或关系结构，压缩一个原子命题并提供第一眼理解。它可以包含主体、动作和关系，也可以包含让机制、差异、角色或结果变得可见的少量具体实例、状态和短标签。
- **文字背面**：核心观点、自己的解释、条件、证据、来源、上位问题和少量有方向的语义连接，为视觉增加精度与上下文。

普通文本卡可以没有视觉正面；用户要求 Visual Main Note 时，最终卡必须有一个明确的视觉正面。视觉和文字是同一想法的两种接口，不能互相替代，也不要逐句重复。核心信息不是对整张卡的中性一句话总结，具体内容也不必全部移到背面。

### 正反面分配权

哪些实例更生动、哪个细节最有感觉、什么值得第一眼记住，以及某个标签应留在视觉正面还是移到文字背面，都由用户通过草图、第一眼测试和真人反馈决定。AI 不自行衡量感染力、代表性、自然度、记忆点或视觉取舍，也不自动删除具体内容。

AI 只能：

- 说明一个元素在画面中承担主体、动作、关系、实例、状态或标注中的哪种功能；
- 描述保留、删除或移动该元素后可能出现的不同读法，并标记为 `AI 建议，待确认` 或 `AI 模拟`；
- 提醒完整解释、条件、证据、来源、`up` 和知识连接通常适合文字背面。

AI 必须把“保留／删除／移动／增加”的决定交还用户。

## 原子卡规则

- 一张卡只捕捉一个可以独立复述的想法。
- 内容放不下时先删减，再拆卡，不靠增加小标题隐藏复合命题。
- 用持续问题组织卡片，而不是只按宽泛主题归档。
- 来源说明材料从哪里来，不自动构成卡片关系。
- 连接需要方向和推进作用；“因为／但是／因此”优于“然后”。
- 卡片应当便携、可复用，并能进入不同地图或叙事。

## 模板位置的职责

| 位置 | 作用 | 完成判断 |
|---|---|---|
| `title`／H1 | 为一个概念或命题命名 | 名词、名词短语或动名词，且两处一致 |
| abstract | 第 1 步保存工作命题，第 6 步更新为最终主张 | 可独立复述，并与视觉正面一致 |
| 正文 | 用自己的话增加条件、意义与精度 | 不是来源摘抄、画面复述或过程日志 |
| `sources` | 记录材料来源 | 目标真实存在，不能代替语义关系 |
| `up` | 锚定持续问题、上位概念或地图 | 由用户确认，本卡确实推进它 |
| `知识连接`（可选） | 显式写出带理由的关系 | 每条有类型、方向、理由和真实目标 |

## 分层落盘顺序

### 第 1 步：记录知识卡目标

1. 用户先用自己的话提出唯一但可修订的工作命题；不能从 AI 候选中直接挑选代替首轮表达。
2. 用户直接指定现有知识卡时，完整读取并记录实际路径为 `target_note_mode: existing` 与 `target_note_path`；该卡已有明确核心观点和自己的解释时，可以作为本轮工作命题。
3. 用户没有指定知识卡时，只记录 `target_note_mode: new` 与 `target_note_path: pending`，第 1–4 步不创建文件。
4. 选择或读取现有知识卡只确定承载目标，不等于授权修改；第 5 步初始化前仍需明确授权。

### 第 2–4 步：保持正文安静

核心信息明确后，用户先列出 3–5 个关键词，AI 再扩展近义、反义、隐喻、习语和符号；第 3 步由 AI 逐一解释五种视觉框架的基本逻辑、用于当前信息时怎样组织以及各自突出什么，再由用户选择；第 4 步根据框架寻找实际图像并固定生成临时 HTML。用户在浏览器预览、选择或重组可模仿组件，但不在本步绘制。AI 扩展项和 HTML 只是联想原料，不替用户决定最终方向。第 2–4 步不要求人类草图；关键词、联想、框架、HTML 和素材灵感全部留在对话或系统临时目录，不更新知识正文。

### 第 5 步：初始化知识卡、嵌入素材、首次草图与视觉正面

用户从第 4 步 HTML 贴回入选编号后，完整执行[第 5 步知识卡与 Excalidraw 初始化](excalidraw-note-preparation.md)：

- `existing`：回显第 1 步记录的实际路径，获得授权后直接通过 Excalidraw 插件初始化该卡，不再询问承载方式或更换路径；
- `new`：请用户确认名词短语标题，搜索同名、aliases 和近义卡；排除重复并获得授权后，使用 `Templates/知识卡.md` 在 `Knowledge/Notes/` 创建只含标题、H1、用户已确认 abstract、空 `up` 与 `sources` 的最小卡片，再通过插件初始化 Drawing；
- 对用户实际入选的 icon：所有永久 icon 都必须是已描摹为原生元素的纯 JSON `.excalidraw` 组件。本地 `.excalidraw` 通过结构校验后按现有颜色直接复用；入选的 `/tmp/` SVG、PNG/JPG 或其他图像参考不复制、不封装到 Vault，而是按用户确认的外观（包括颜色）通过插件／API 描摹为原生 `.excalidraw` 组件；随后把所有入选组件作为彼此独立的 image reference 松散嵌入目标卡初始视图。新建或首次初始化的 Drawing 可以把画布背景设为 `--concept-color-canvas`，已有 Drawing 保留当前背景；新建永久组件采用 `Icon - 关键词1, 关键词2 - 来源.excalidraw` 文件名，并由 Icon Library 自动发现；外部来源追溯仍需另行授权后登记。

不创建独立 Concept Visual 文件，也不提供纸笔或 Vault 外绘制分支。初始视图只包含无语义的入选素材托盘，不添加 AI 文字、箭头、关系或完整构图。验证知识卡能够以 Excalidraw 视图打开且组件重新加载可见后，用户在该笔记中移动、缩放、组合并补画视觉组件，完成第一张约五分钟的粗草图；用户亲自决定主体、动作、关系，以及是否保留少量具体实例、角色、状态和短标签，AI 不替用户做感性取舍。不能把 HTML 或初始素材托盘直接当成最终构图。探索版本可以暂时并存，但不是多个知识节点，也不需要全部保留到最终卡。

### 第 6 步：校准两面

1. 执行第一眼、延迟和去文字测试。
2. 用户选择、合并或重画最终视觉正面。
3. 用户确认最终核心措辞，更新 abstract。
4. 由用户确认正反面分配后完成文字背面，补充图像没有承载的精度、条件、证据、来源与意义；AI 不把所有具体内容自动移到背面。
5. 若视觉揭示新解释，返回联想、框架或草图，而不是维持旧文字。
6. 由用户确认最终配色。项目语义色板是可选的统一方案，不限制其他颜色；已描摹 icon 的内部颜色不进入色板 Gate。只有用户明确要求统一或登记受管文件时，才对画布背景与本卡原生非 icon 元素通过插件完成语义映射并运行逐卡配色命令。

### 七步完成后：接入知识网络

1. 核对并填写 `sources`。
2. 请用户确认 `up`。
3. 完整执行[知识卡语义连接规则](card-connections.md)，搜索并阅读候选。
4. 只写用户确认且能够推进思路的关系。
5. 删除模板提示、未使用示例、空连接节和占位内容。
6. 验证视觉、文字、链接、标题与 YAML；时间属性交给插件。

新知识卡默认到第 5 步才创建；知识卡与 Drawing 的初始化及入选素材嵌入只是建立容器和可操作零件，不代表 AI 已完成视觉，也不代表文字背面先于视觉完成。

## 连接的最小写法

正文优先：

```markdown
本卡建立在[[前提卡]]之上，因为它提供了……；进一步导向[[后续卡]]，因为……。
```

正文不适合承载时：

```markdown
## 知识连接

- 建立在：[[前提卡]]——它提供本卡成立的前提。
- 导向：[[后续卡]]——本卡进一步产生这一结论或行动。
```

不要填满关系类型。少量能推动思路的连接优于链接堆积。

## 完成检查

- **单意**：abstract 是否只有一个可判断主张？
- **两面一致**：视觉正面与文字背面是否表达同一个原子命题，而不是把一句总结与整张卡机械分开？
- **正面充分**：用户认为必要的具体实例、角色、状态和短标签是否被允许留在视觉正面？
- **人类取舍**：保留、删除、移动与增加细节的决定是否来自用户，而不是 AI 对感染力、代表性或记忆点的自行衡量？
- **互补**：文字是否增加条件、证据、来源、连接与精度，而不是逐句说明画面？
- **独立**：不打开来源和链接，是否仍能理解？
- **锚定**：`up` 是否由用户确认并真正被本卡推进？
- **溯源**：`sources` 是否是真实材料？
- **推进**：每条链接能否用“因为／但是／因此”解释？
- **清洁**：过程记录、模板提示、空节和悬空链接是否已删除？
