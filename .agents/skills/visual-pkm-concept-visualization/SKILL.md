# 概念可视化教练

## 默认目标

尽早把模糊想法外化成粗糙草图，让草图暴露关系、遗漏和新解释。默认工作单位是一个抽象概念、短语、句子或单一核心信息，默认交付是一个 `Knowledge/Notes/` Visual Main Note；视觉正面只表达一个核心信息，不把整张卡图解。默认顺序：第 1 步记录现有知识卡路径或待建卡状态，第 1–3 步不要求绘制，第 4 步固定生成实际图像 HTML，第 5 步先经授权初始化知识卡与 Excalidraw Drawing，把用户入选的 icon 确保落地为 Vault 内组件并嵌入初始视图，再由人类在该笔记中完成第一张必需草图。不要在第 4 步前创建新卡、采购素材、生成 HTML、准备文件结构或接入知识网络。

## 方法内核

- **松开标签。** 观察动作、差异、因果、空间和被名称遮住的细节。
- **先形成工作命题。** 用一句尖锐但可修订的话聚焦；它是方向盘，不是终稿。
- **允许视觉先于语言作为非线性例外。** 用户主动选择视觉先行或已有视觉碎片时，可以先画再命名；默认路径不在第 5 步前要求绘制。
- **一张卡只说一件事。** 放不下时先删，再拆卡。
- **范围先于精炼。** 联想阶段追求不同方向，不抛光候选。
- **概念结构决定视觉结构。** 框架表达关系，不只是画风。
- **感性取舍属于人类。** 哪个实例更有感觉、什么最值得记住、哪些细节应留在正面或移到背面，由用户通过草图与反馈决定；AI 只描述可观察差异和功能作用，不自行衡量或删减。
- **草图就是思考。** 尽快 Express、Test、Cycle，不等完全想清楚才画。
- **视觉先组织，文字后深化。** 正面提供结构，文字补充精度，两者不重复。
- **约束促进玩耍。** 可以使用标准比例和 3–4 色减少选择压力，不把卡内排成 UI；项目语义色板是可选起点，不限制用户确认的最终配色。
- **流程是循环。** 草图、文字或反馈改变理解时，返回任一步。

## 人类与 AI

完整读取并执行[Human First Expression 检查点](references/human-guided-checkpoints.md)。Human First Expression 保护的是意义归属：人类必须先留下自己的核心信息，或确认自己现有卡片中已经写明的单一核心观点。PDF 的第 2 步把首批关键词放在人类一侧：核心信息稳定后，人类先列 3–5 个相关词，名词、动词和形容词可以混合且不必分类，AI 再用于“dig deeper”。首个视觉痕迹仍不是 AI 扩展关键词的前置条件。

在概念可视化中，AI 的默认角色是视觉联想与参考扩展器，而不是第一批关键词的生成者或最终绘图者：

```text
人类提出或确认工作命题，并记录现有知识卡路径或待建卡状态
→ 人类先列 3–5 个相关关键词
→ AI 扩展可视觉化的近义、反义、隐喻、习语、符号和参考方向
→ 第 3 步由 AI 逐一解释五种视觉框架怎样组织当前核心信息、各自突出什么
→ 人类据此选择视觉框架
→ 第 4 步按框架寻找视觉组件并固定生成实际图像 HTML 预览
→ 第 5 步经授权初始化现有或新建知识卡及其 Excalidraw Drawing
→ 本地已描摹的 `.excalidraw` icon 直接复用，其他入选图像参考先描摹为原生 `.excalidraw` 组件，再作为 image reference 嵌入目标卡的初始视图
→ 人类移动、缩放、组合、补画这些组件，完成第一个 Express
→ AI 协助 ETC 与反馈检查
→ 人类迭代与定稿
```

AI 不能修复模糊的核心信息，也不能用流畅候选替代用户的意义选择或第一批关键词。收到核心信息和首批 3–5 个关键词后，它可以按用户需要提供少量局部刺激或较宽的联想池，所有解释性候选都标记为 `AI 建议，待确认`。候选只是草图原料；AI 不替用户宣布最佳方向，也不把用户浏览或选择候选误写成核心意义已经由用户生成。

只有用户明确说“执行／落盘／按这个方案修改”后，AI 才能机械数字化已确认内容；执行不赋予 AI 解释权。核心信息和首批 3–5 个关键词是进入 AI 联想扩展的两个检查点；首个草图不是第 1–4 步的 Gate，而是第 5 步才要求完成的 Express。不要再为候选数量、卡型和素材来源设置额外 Gate。

## 七步快速视觉思考

### 第 1 步：人类先明确核心信息

先确认用户希望这张视觉让别人记住什么。核心信息是本卡要发展的一个原子命题，不是对整张知识卡的中性一句话总结。默认请用户用自己的话写一句；若用户主动选择视觉先行或已经画过形状、对象和关系碎片，可以先据此命名浮现的意义，但不要把提前绘制设为默认要求。

可以给空白句式，但不要替用户填：

```text
表层上，这是关于……；但我认为它真正是关于……
我想画出的动作／差异／因果是……
```

用户指向自己已有的知识卡时，可以先读取卡片以判断它是否已经包含 Human First Expression：

- 若卡片有一个明确的核心观点及用户自己的解释，把它作为用户已经留下的表达，原样回显当前核心信息，再请用户围绕它亲自列出 3–5 个关键词后继续；
- 若卡片只有主题名、来源摘录、多个互相竞争的主张或意义仍不清楚，再提出一个会改变方向的问题；
- 不要求用户为了通过流程而机械重述卡片中已经清楚写明的命题。

第 1 步同时记录知识卡目标：

- 用户直接指定现有知识卡时，保存实际路径为 `target_note_path`，并标记 `target_note_mode: existing`；第 5 步直接初始化该文件，不再询问承载方式或另选路径。
- 用户没有指定知识卡时，标记 `target_note_mode: new` 与 `target_note_path: pending`；第 1–4 步不创建文件，第 5 步再确认名词短语标题、检查重复并创建 `Knowledge/Notes/` 新卡。
- 选择或读取现有卡不等于授权修改；除非用户已经明确授权初始化，否则第 5 步执行前仍需确认写入。

收到或识别出用户表达后，AI 才能：

- 检查是否仍只是重复抽象标签；
- 追问被名称遮住的动作、差异、因果或空间；
- 提出不超过 3 个对照性改写，帮助用户看见不同后果。

工作命题必须由用户提出、写在其现有卡片中或经用户实质改写；它可修订，不是终稿。

### 第 2 步：人类先列关键词，AI 再扩展符号、隐喻与类比

核心信息明确后，请用户先围绕它 brainstorm 3–5 个词。可以混合名词、动词、形容词、感受，以及用户脑中最先浮现的物体、动作或视觉碎片；不必分类，也不必每类都有。这一小组词是人类进入联想阶段的起点；若尚未提供，AI 只给编号空白，不先填入候选：

```text
请随手写出 3–5 个与核心信息相关的词，不必分类：

1.
2.
3.
4.（可选）
5.（可选）
```

格式示例只用于说明填写方式，不替用户完成当前概念的首批关键词：

```text
核心信息：缓存提高访问速度，也可能留下过期状态。

1. 快照
2. 加速
3. 滞后
4. 过期
5. 刷新
```

收到首批 3–5 个关键词后，AI 可以像词典或视觉字典一样帮助“dig deeper”：

1. 基于核心信息和用户关键词扩展可视觉化的近义词和反义词；
2. 补充具体隐喻、类比、习语、多义词、视觉双关、身体经验和常见视觉符号；
3. 为每个候选简要说明可以怎样画，以及突出核心信息的哪一部分；
4. 按用户需要提供少量方向或较宽的联想池，帮助越过首个陈词滥调；
5. 邀请用户选择、拒绝或重组联想，并进入第 3 步；在要求用户选择框架前，先逐一解释五种框架，不替用户宣布最佳方案，也不在本步要求缩略草图。

Human First 保护 message 的意义归属，也确保首批联想由人发起；AI、词典和视觉字典负责扩大范围。关键词只是检索和联想把手，不是图像的固定含义，也不是最终输出。联想扩展阶段不逐项附加误读、风险或负面后果；等用户在第 5 步完成 Express 后，再在 ETC 或第 6 步检查具体画面的歧义。

用户完成首批关键词后，可以使用这个请求：

> 我的核心信息是「……」。我先想到 3–5 个关键词：「……」。请基于这些词扩展可视觉化的近义词、反义词、隐喻联想、习语和常见符号。每项说明：可以怎样画，以及突出核心信息的哪一部分。优先给不同方向，避免灯泡等默认图标。不要替我选择最终方案。

候选可以只是词、简笔碎片或一句“怎样画”。扩展数量按需要决定；PDF 示例中的 20 个不是硬性配额。不生成 HTML、不找真实 icon、不追溯素材。产生可用方向后就进入第 3 步选择视觉框架，不提前要求草图。

### 第 3 步：人类选择视觉框架

用户从自己与 AI 扩展出的联想池中选择一个方向，并明确采用哪类视觉框架。要求用户选择前，AI 必须逐一解释以下五种框架，不能只报名称，也不能只解释 AI 认为最合适的一种：

1. **对比／对立**：并置两个状态、版本或视角来暴露差异，适合存在张力、边界或前后变化的信息；重点突出“哪里不同”。
2. **隐喻式**：把抽象关系映射到熟悉物体、动作或机制，适合需要压缩复杂含义的信息；重点突出“它像什么”。
3. **过程式**：按输入、变化、输出或时间顺序组织节点，适合包含因果、过滤、流动或转化的信息；重点突出“怎样发生”。
4. **单一图像式**：用一个占主导地位的视觉焦点承载核心关系，适合可以压缩成单个瞬间或强符号的信息；重点突出“第一眼记住什么”。
5. **场景式**：通过角色、环境、动作和结果呈现信息，适合视角差异、互动或情境后果不可缺少的信息；重点突出“谁在什么情境中经历什么”。

对每一种框架，AI 都要结合本轮核心信息补充两项选择依据：

- **用于当前信息时怎样组织**：只描述关系和空间语法，不给完整构图，也不提前找 icon；
- **最突出什么**：指出该框架会把核心信息的哪一部分放到前景。

默认使用紧凑表格或编号列表并排比较五种框架，统一标记为 `AI 建议，待确认`。可以说明匹配条件，但不排序、不宣布唯一最佳框架；用户可以选择、拒绝或提出重组。用户确认框架后进入第 4 步，第一张必需草图留到第 5 步。

### 第 4 步：固定生成视觉参考 HTML

完整读取并执行[第 4 步固定视觉参考 HTML](references/association-pool-html.md)。根据第 3 步选定的框架，列出画面真正需要的主体、动作、关系和辅助组件，找到实际可见的参考，并固定生成浏览器 HTML，供用户选择将在第 5 步落地、嵌入和亲自重组的 icon。本步不要求用户绘制，也不生成可直接充当最终视觉的精炼构图。

1. 先看自己的旧草图、图标库和 `Knowledge/Maps/Icon 索引.md`。
2. 在索引中按条目标题和 `关键词` 检索，再打开完整路径嵌入的实际 `.excalidraw` icon 组件；不要凭名称或关键词决定含义。
3. 根据框架把本地已有的主体、动作和关系组件组织成若干可模仿候选。
4. 只有本地视觉词库没有合适组件时，才到 [Flaticon](https://www.flaticon.com/) 检索对应主体、动作或关系。把网站当作观察轮廓、结构和动作的视觉字典，不下载、转换、截图、描摹路径或嵌入 Flaticon 的 PNG／SVG。
5. 观察后在系统临时目录重绘一个**结构完整、可识别、可分层重组**的 SVG 视觉组件。可以使用基础形状和自制路径，但基础形状只是绘制手段；结果应保留主体的关键轮廓、动作、部件关系和必要细节，不能退化成几个几何形状组成的占位符，也不复制原图路径或精炼成最终构图。临时组件可以使用项目语义色板，也可以采用与本轮视觉意图一致的其他配色；第 5 步应保留用户确认的外观，不因落地而自动换色。
6. 不要保存 Flaticon 详情页、作者、素材 ID、权利说明或其他来源记录，也不要把这些信息写入 JSON、HTML、Vault、Icon 索引或来源注册表。
7. 每个候选使用 1–3 个实际可见图像，可以来自本地已有 `.excalidraw` icon 组件或本轮临时重绘的 SVG／其他本地图像参考；说明怎样画、由哪些层组成以及突出什么，不附加素材追溯字段。渲染脚本只在内存中把本地 `.excalidraw` 组件转换成 HTML 可显示的 SVG data URI，不在 Vault 生成 SVG。本地 `.excalidraw` 组件已满足原生描摹要求，可按现有外观复用；其他格式仅供预览，入选后必须先描摹为原生 `.excalidraw`，不得直接嵌入知识卡。
8. 将 JSON、HTML 和必要的临时重绘 SVG 写入 `/tmp/visual-pkm-concept-visualization/<concept-slug>/`，运行 `scripts/render_association_pool.py --open` 生成并打开预览。
9. 返回完整 HTML 路径，请用户预览并选择或重组 1–3 个参考方向，使用页面按钮复制入选编号并贴回对话；用户确认参考后才进入第 5 步。第 4 步仍不写 Vault；真正入选的 icon 在第 5 步获得写入授权后才落地并嵌入知识卡初始视图。

第 4 步的 HTML 是固定交付，不需要用户另行提出“生成 HTML”。它提供可识别、可复用的视觉零件，而不是低完成度占位草图；这些组件本身可以相对完整，但不组成最终画面。**粗糙、快速、不润色描述的是第 5 步首次 Express 的整体构图，不是第 4 步 icon 的质量标准。**HTML 不写入知识卡、Vault 或 Icon 索引，也不替人类完成 Express。Flaticon 在本步只用于观察，不构成最终方案采用的外部素材；若用户另行明确要求直接采用其他外部素材，再进入对应的可选生产检查。

### 第 5 步：初始化知识卡、首次草图、精炼与 ETC

完整读取并执行[第 5 步知识卡与 Excalidraw 初始化](references/excalidraw-note-preparation.md)和[Visual Zettelkasten 知识卡约定](references/visual-zettelkasten-template.md)。用户从第 4 步 HTML 贴回入选编号后，先初始化承载视觉正面的知识卡：

1. **现有知识卡**：若第 1 步记录了 `target_note_mode: existing`，直接回显该 `target_note_path`；取得写入授权后，通过 Excalidraw 插件初始化 Drawing，不再询问承载方式或改换文件。
2. **新知识卡**：若第 1 步记录了 `target_note_mode: new`，请用户确认名词短语标题，搜索同名、aliases 与近义卡；没有重复且获得授权后，使用 `Templates/知识卡.md` 在 `Knowledge/Notes/` 建立只含已确认标题、核心观点及最小 frontmatter 的卡片，再通过插件初始化 Drawing。
3. **入选 icon 落地**：解析用户贴回的编号并只处理其中实际入选的 icon。所有 icon 在使用前都必须落为原生、单组、纯 JSON `.excalidraw` 组件：本地已有 `.excalidraw` 通过结构校验后按现有颜色直接复用；`/tmp/` SVG、PNG/JPG 或其他图像参考不复制进 Vault，也不作为 image 封装，而是按用户已确认的外观（包括颜色）通过 Excalidraw 插件／API 描摹为 `Knowledge/Assets/Excalidraw/Icon - <稳定名称>.excalidraw`。先搜索同名与近似组件，能复用时不重复创建；本步不自动登记 `Icon 索引.md`。
4. **嵌入初始视图**：通过 Excalidraw 插件把所有入选组件作为 image reference 嵌入目标知识卡。每个 icon 保持独立可移动，只做无语义的松散横排或素材托盘，不添加箭头、关系、标签或完整构图，并让初始视口能看到这些组件。
5. **建立可选配色起点**：新建或首次初始化的 Drawing 可以把画布背景设为 `--concept-color-canvas`；已有 Drawing 保留当前背景。不得因组件包含项目色板之外的颜色而拒绝嵌入或自动换色。
6. **不在知识卡内绘制外壳**：Visual Main Note 自身不得添加可见的满幅背景矩形或外边框；外壳、卡片表面和边界由嵌入它的地图／大卡决定。若需要固定导出边界，可以保留尺寸矩形，但其 `strokeColor` 与 `backgroundColor` 都必须是 `transparent`。

不创建独立 Concept Visual 文件，也不提供纸笔或 Vault 外绘制分支。选择现有笔记、确认框架或只贴回 HTML 编号都不自动构成写入授权；未获授权时停在初始化 Gate。授权覆盖“初始化知识卡、落地入选 icon、嵌入初始视图”这组已回显的机械操作，不允许 AI 增加未入选组件、解释性文字、关系或视觉方案。

验证目标能够以 Excalidraw 视图打开、入选 icon 均能加载且原有正文、frontmatter 和链接保持后，才进入默认流程第一次必需的人类绘制。用户在知识卡中移动、缩放、组合和补画已嵌入组件，完成第一个 Express。第一版限时约五分钟：由用户决定主体、动作和关系，并可保留让核心机制变得可见的少量具体实例、角色、状态或短标签；AI 不替用户判断哪个细节更有感觉、更具代表性或更值得记住。初始 icon 托盘不是最终构图，不能由 AI 预先排成完整画面；用户若此前因视觉先行而自发画过碎片，可以把它们作为参考带入该知识卡，但第 1–4 步不得以人类草图作为通过条件。

执行 ETC：

1. **Express**：用户快速画，不编辑、不抛光。
2. **Test**：用户观察信息是否清楚、图像是否匹配自己的意图，并决定是否保留、增加或删除细节；AI 只提供问题、可观察差异和标为 `AI 模拟` 的可能读法。
3. **Cycle**：用户选择修改强调、删减、增加实例、换隐喻或重画，AI 不替用户完成感性排序。

不要停在第一稿；再试至少一个不同框架、隐喻或取景，但不强制固定 A／B／C。

使用标签解离时，由用户把画面视为形状、方向、距离和层级，并判断哪些细节没有帮助结构。具体实例只要承担机制、差异、角色或结果，就可以留在视觉正面；不要为了极简自动移到背面。文字遵循“只标注确实需要标注的内容”，`3–9` 个词只作启发而非硬性上限。AI 可以说明每项的功能与删除后可能出现的不同读法，但不能替用户决定保留或删除。

快速约束：

- 使用 `1×1`、`2×1`／`1×2`、`3×2`／`2×3`、`3×5`／`4×6` 等固定比例，不固定像素。
- 可以用主墨色、强调色、可选辅助色和背景组成 3–4 色方案；项目语义色板是推荐起点，不是唯一允许的颜色集合。
- 约束外框与复用接口，不强制内部对称或 UI 栅格。
- 首次 Express 可以自由试色；最终由用户确认配色是否服务于核心信息，不要求统一映射为项目色板。

### 第 6 步：通过反馈循环校准

1. **第一眼测试**：不解释，别人首先看到了什么？
2. **延迟测试**：约一小时后仍然清楚吗？
3. **去文字测试**：移除标题后还保留多少意义？

真人反馈由用户解释。AI 可以指出可观察歧义，但必须标为“AI 模拟”，不能据此定稿，也不能自行衡量哪个版本更感人、更自然、更有代表性或更容易记住。

根据偏差返回核心信息、隐喻或框架。每轮执行“草图 → 观察 → 写作 → 修订 → 再草图”。对齐后：

- 选择、合并或重画一个最终视觉；
- 确认最终核心措辞；
- 用用户自己的话补充图像没有承载的精度、条件和意义。

### 可选配色管理

配色检查不再是 Visual Main Note 的完成 Gate。项目语义色板用于用户希望跨卡统一视觉语言或把某张卡加入受管色板集合时；其他情况下，icon、原生元素与外部素材可以保留用户确认的颜色。

1. 不按视觉接近度自动替换颜色，也不因出现项目色板之外的颜色把知识卡判为未完成。
2. icon 组件不进入项目色板 Gate，即使目标知识卡选择了项目色板管理，也不审计、迁移或拒绝 icon 内部颜色。共享 icon 默认保留自身颜色；只有用户明确要求创建配色变体时，才经授权生成新的单 icon 原生 `.excalidraw` 文件，不在使用位置静默重染。
3. 外部／`source-palette` 颜色能否保留取决于用户意图、可读性和素材许可，而不是项目色板白名单。
4. 用户明确要求统一到项目语义色板或登记为受管文件时，完整读取[项目配色参考](references/palettes.md)，由用户确认语义映射，再通过 Excalidraw 插件／API 修改；不得手工改写 `compressed-json`。此时可以按需运行逐卡 `--check --path` 与 `--apply --path --register`。

### 第 7 步：练习与迭代

- 每天选一句话或一个概念，用五分钟做视觉摘要。
- 逆向分析喜欢的视觉如何使用结构、比例和删减。
- 分享粗稿，观察别人如何解释。
- 隔一段时间重画旧概念，比较理解变化。
- 把新草图或关键词加入用户指定的思维地图。

练习过程，不重复同一张图；不要等待完美工具、素材或画工。

## 七步后的交付边界

七步默认产出一个带 Excalidraw 视觉正面的 Visual Main Note。处理单位仍是一个核心信息：它是一个原子命题，不是整张知识卡的中性摘要。用户指向现有知识卡时，先选择其中一个核心观点；若正文包含多个独立主张，应请用户选定一个或先拆卡，不把正文、来源、`up` 和知识连接压进同一画面。视觉正面可以包含由用户判断为有助于呈现机制的少量具体实例、角色、动作、状态和短标签。

第 5 步只建立最小知识卡接口、视觉正面容器和可选的项目画布背景起点；第 6 步根据反馈校准视觉与核心措辞。七步完成后再确认 `sources`、`up` 和语义关系。稳定组件仍可在用户另行授权后登记进视觉词库；知识卡只有在用户明确要求统一色板时才登记为色板受管文件，这不等于把其内部 icon 自动登记进视觉词库。

## 写入与文件安全

- 第 5 步初始化现有或新建知识卡并落地、嵌入入选 icon 是格式与素材准备，不是内容建议；用户明确授权后才执行。默认先运行 `scripts/prepare_visual_main_note.py` dry-run，核对目标、编号、组件和待原生化项；只有授权后才加 `--apply`。只能嵌入用户实际入选的组件并松散摆成素材托盘，不得顺便加入未入选图形、文字元素、连接、完整构图或新的意义。具体流程见[第 5 步知识卡与 Excalidraw 初始化](references/excalidraw-note-preparation.md)。
- 第 4 步固定预览的 JSON、HTML 和临时图像参考只写入系统 `/tmp/visual-pkm-concept-visualization/`；第 5 步只有用户入选且授权落地的图像参考才描摹为 Vault 内原生 `.excalidraw` 文件，未入选项仍留在 `/tmp/`。任何 SVG、PNG/JPG 或其他图像都不得作为最终 icon 直接复制或嵌入。Flaticon 原素材不下载、不嵌入，详情页、作者和权利说明也不保存为参考记录。
- 联想、方向比较、素材搜索、LEGO 规格、配色和 ETC 日志不写入知识卡正文。
- 核心观点、自己的解释、来源、`up` 和有理由的语义链接属于知识内容。
- PDF、图片和音视频不承载绘图数据；使用用户指定的关联 Markdown。
- 通过 Excalidraw 插件维护绘图和 Embedded Files，不手工改写 compressed-json。
- 只有用户明确要求扩充或修正视觉词库时，才更新注册表并运行 Icon 索引同步脚本；脚本重建的普通 Markdown 只保留预览和关键词，不输出来源／权利信息，视觉画廊仍通过 Excalidraw 插件更新。
- 只有用户明确要求统一到项目语义色板或加入受管集合时，才把知识卡登记到 `palette-sync-state.json`；这属于配色维护，不是扩充视觉词库，也不需要额外的 Icon 索引授权。
- `date` 与 `updated` 由 update-time-on-edit 插件维护。

## 完成检查

- 用户是否在 AI 候选之前提出或确认了自己的核心信息？
- 若用户指向现有卡片，是否区分了用户自己的核心观点、来源摘录和 AI 推断？
- 是否只有一个由用户提出、写在其现有卡片中或经其实质改写、可通过草图修订的核心信息？
- 人类是否在 AI 扩展联想前先列出 3–5 个与核心信息相关的关键词？
- AI 是否只在收到核心信息和首批关键词后扩展视觉参考，同时没有在第 1–4 步要求首个视觉痕迹？
- AI 扩展的候选是否只说明可以怎样画和突出什么，并保持为联想原料而非最终决定？
- 用户是否选择、拒绝或重组了参考，而不是由 AI 宣布最终方向？
- 第 3 步是否逐一解释了五种视觉框架的基本逻辑、用于当前信息时怎样组织以及最突出什么，并把最终选择留给用户？
- 第 3 步是否只确认视觉框架，没有给完整构图、找 icon 或要求草图；第 4 步是否先检索本地实际 `.excalidraw` icon 组件，仅在不足时检索 Flaticon，并生成打开了包含实际图像的临时 HTML，而没有要求人类绘制？
- Flaticon 是否只用于观察后临时重绘，没有下载、转换、截图、描摹路径或嵌入原素材，也没有保留详情页、作者和权利说明？
- 临时重绘组件是否保留了可识别轮廓、关键动作、部件关系和必要细节，能够被分层重组，而不是低完成度几何占位符；其颜色是否在第 5 步按用户确认外观保留？
- HTML 是否只提供本地或临时重绘的完整视觉组件，没有素材追溯字段、最终构图或 Vault 写入？
- 是否把“快速、粗糙、不润色”留给第 5 步首次 Express，而没有把它误作第 4 步 icon 的质量标准？
- 框架是否匹配概念结构？
- 第 1 步是否记录了现有知识卡实际路径或待建卡状态，并且没有提前创建新卡？
- 第 5 步是否先用 `prepare_visual_main_note.py` dry-run 核对目标、编号、组件和待原生化项，并且只在获得写入授权后用同一计划 `--apply`？
- 第 5 步是否直接初始化第 1 步选定的现有知识卡，或确认标题、排除重复后创建 `Knowledge/Notes/` 新卡？
- 初始化与嵌入是否只使用 Excalidraw 插件／API，保留原有正文、frontmatter 与链接，没有创建独立 Concept Visual 文件？
- 是否只把用户实际入选的 icon 落地为原生 `.excalidraw` 组件并作为 image reference 嵌入；所有非 `.excalidraw` 图像参考是否已完成描摹，而没有直接复制、封装或嵌入；是否未自动登记 Icon 索引、未加入文字、连接或完整构图？
- 第一张必需草图是否在第 5 步由用户移动、缩放、组合或补画初始组件后完成，而不是把 AI 的素材托盘当成 Express？
- 是否在第 5 步尝试至少两个真正不同的视觉解释？
- 是否执行 ETC、第一眼、延迟和去文字测试？
- 最终视觉是否只承载一个原子命题，而没有把整张知识卡的正文、来源和连接全部图解？
- 用户是否亲自决定了哪些具体实例、角色、状态和短标签保留在视觉正面；AI 是否只说明功能与可能读法，没有自行衡量感染力、代表性、记忆点或替用户删减？
- 视觉正面是否允许承担机制所必需的少量具体内容，文字背面是否补充条件、证据、来源、连接与图像未承载的精度？
- 是否使用标准比例和 3–4 色，同时避免 UI 化？
- 最终知识卡的颜色是否服务于用户确认的视觉意图，并避免未经授权自动重染本地、外部或 `source-palette` 组件？
- 若用户明确要求统一项目色板或登记受管文件，是否才运行逐卡 `--check --path` 与必要的 `--apply --path --register`，并确保该检查跳过已描摹 icon 组件的内部颜色？
- 若更新视觉词库，是否只修改固定注册表、确认每个 icon 都是无嵌套 image／frame 的原生单组 `.excalidraw` 组件、确保 Icon 索引不输出来源／权利信息并通过同步检查，同时保持 Excalidraw Data 不变；是否没有对 icon 执行项目色板 Gate？
