# Visual PKM Skills 使用手册

本文件是人类查阅入口。自动触发以各 Skill 的 `SKILL.md` frontmatter `description` 为准；项目级规则以 `content/AGENTS.md` 为准。

## 共同协议：Human First Expression

所有 Skill 使用同一顺序：

```text
人类先阅读／回忆／表达／画第一稿
→ AI 核对、追问、提出反例和局部建议
→ 人类重读、移动、改写或重画
→ AI 再测试
→ 人类决定
→ 明确授权后 AI 才机械落盘
```

Human First Expression 可以很短、很错、很粗糙，但必须来自人类。单纯转发来源、只说主题名，或从 AI 候选中选择，都不能代替核心意义的首轮生成式思考。概念可视化中，用户提出或在自己的现有卡片中已经写明核心信息后，亲自列出 3–5 个相关词；这些词可以混合名词、动词、形容词、感受或视觉碎片，不必分类，也不必每类都有。AI 再扩展符号、隐喻、类比和视觉参考。第 3 步由 AI 逐一解释五种视觉框架怎样组织当前信息、各自突出什么，再由人类选择；第 4 步固定生成包含实际图像的临时 HTML 供人类预览和选择；第 5 步经授权初始化现有或新建知识卡的 Excalidraw Drawing，把入选 icon 确保落地为 Vault 内 `.excalidraw` 组件并嵌入初始素材托盘，再由人类在该笔记中组合和补画第一张草图。视觉正面可以保留让机制可见的具体实例、角色、状态和短标签；保留、删除与正反面分配由人类判断，AI 不自行衡量感染力、代表性或记忆点。视觉先行只作为用户主动选择的非线性例外。

AI 输出中的解释、候选和诊断应标记为 `AI 建议，待确认`。只有“执行／落盘／按这个方案修改”等明确授权才允许改文件，且授权只覆盖已确认内容。

## AI 辅助概念绘图

在单一概念可视化中，AI 默认扩展视觉联想和参考，不替人类决定最终含义或构图：

```text
人类提出工作命题，并记录现有知识卡路径或待建卡状态
→ 人类先用编号列表写 3–5 个相关词，不按词性分类
→ AI 扩展可视觉化的近义、反义、隐喻、习语、符号和参考方向
→ AI 说明每项可以怎样画、突出什么
→ 第 3 步由 AI 逐一解释五种框架用于当前信息时怎样组织、突出什么
→ 人类据此选择视觉框架
→ 第 4 步按框架寻找实际 icon／视觉组件并固定生成 HTML 预览
→ 第 5 步经授权初始化知识卡与 Excalidraw Drawing
→ 入选 icon 落地为 Vault 内 `.excalidraw` 组件并作为独立 image reference 松散嵌入
→ 人类在该知识卡中移动、缩放、组合和补画后完成第一张草图
→ AI 只描述 ETC 中可观察的差异、元素功能和可能读法
→ 人类判断感染力、代表性、记忆点、细节取舍与正反面分配
→ 人类迭代视觉并确认最终配色
→ 如需跨卡统一视觉语言，再选择性映射到项目色板并登记受管文件
→ 视觉与文字对齐后定稿
```

完成核心信息和首批关键词后，可以这样请求：

> 我的核心信息是「……」。我先想到 3–5 个关键词：「……」。请基于这些词扩展一组可视觉化的近义词、反义词、隐喻联想、习语和常见符号。每项说明：可以怎样画，以及突出核心信息的哪一部分。优先给不同方向，避免灯泡等默认图标。不要替我选择最终方案。

关键词填写格式：

```text
请随手写出 3–5 个与核心信息相关的词，不必分类：

1.
2.
3.
4.（可选）
5.（可选）
```

格式示例仅用于说明，不替用户填写当前概念：

```text
核心信息：缓存提高访问速度，也可能留下过期状态。

1. 快照
2. 加速
3. 滞后
4. 过期
5. 刷新
```

候选数量按实际需要决定。AI 候选只是草图原料；联想扩展阶段不逐项附加误读、风险或负面后果。出现可用方向后进入第 3 步选择框架，而不是继续累积候选或提前要求 Express；具体画面的歧义留到用户在第 5 步完成草图后检查。

### 第 3 步框架选择说明

要求用户选择前，AI 必须结合当前核心信息逐一解释五种框架，不能只报名称或只介绍一个候选：

| 框架 | 基本逻辑 | 主要帮助人类判断什么 |
|---|---|---|
| 对比／对立 | 并置两个状态、版本或视角 | 哪里不同，是否存在张力、边界或变化 |
| 隐喻式 | 用熟悉物体、动作或机制映射抽象关系 | 这个想法像什么 |
| 过程式 | 用输入、变化、输出或时间顺序组织 | 事情怎样发生 |
| 单一图像式 | 用一个主导焦点承载核心关系 | 第一眼应该记住什么 |
| 场景式 | 用角色、环境、动作和结果呈现 | 谁在什么情境中经历什么 |

每一种框架还要说明“用于当前信息时怎样组织”和“最突出什么”，但不提供完整构图、不找 icon，也不替用户宣布唯一最佳框架。

### 视觉正面、文字背面与人的感性判断

核心信息是知识卡中的一个原子命题，不是对整张卡的中性一句话总结。视觉正面可以包含主体、动作和关系，也可以包含让机制、差异、角色或结果变得可见的少量具体实例、状态和短标签；完整解释、条件、证据、来源、`up` 和知识连接通常留在文字背面。

哪些实例更生动、什么最值得第一眼记住，以及某个细节或标签应保留、删除还是移动到另一面，由用户通过草图、第一眼测试和真人反馈决定。AI 只能说明元素功能、可观察差异和标为 `AI 模拟` 的可能读法，不能自行衡量感染力、代表性、自然度或记忆点，也不能替用户删减。

## 选择矩阵

| 你正在做什么 | 使用 | 先由人类留下什么 |
|---|---|---|
| 读完材料后核对理解 | `visual-pkm-deep-reading` | 阅读复述、疑问、粗略结构或候选命题 |
| 把一个抽象概念、句子或现存卡中的单一观点发展为带 Excalidraw 视觉正面的 Visual Main Note | `visual-pkm-concept-visualization` | 自己提出或现存卡中已有的明确核心观点，以及自己先列的 3–5 个关键词 |
| 把已确认的 `.excalidraw` icon 组件加入 Icon Library／视觉词库 | `visual-pkm-concept-visualization` | 已确认组件、关键词与来源 |
| 改进思维导图、概念图、Brick Road 或 Idea Atlas | `visual-pkm-spatial-mapping` | focus question、思考动作和最小粗图 |
| 建立或维护项目／书籍思考总部 | `visual-pkm-idea-integration` | 中心问题、第一批材料和初步摆放 |
| 找关系、反例、比较项或修复检索 | `visual-pkm-knowledge-exploration` | 首轮回忆、比较或检索失败路径 |
| 把多张卡组成 BoaP、Storyboard 或演讲 | `visual-pkm-narrative-composition` | Take a Stand、第一批卡和粗故事 |
| 审计知识系统或决定下一步 | `visual-pkm-system-review` | 真实失败、目标、范围和禁止改动项 |

## 决策树

```text
你面对的是长材料吗？
├─ 是，而且你还没亲自读 → 先读，不调用 AI 摘要
├─ 是，而且已有自己的复述 → deep-reading
└─ 否
   ├─ 只有一个观点／一张卡 → concept-visualization
   ├─ 有多个概念，需要看结构 → spatial-mapping
   ├─ 有一个长期项目和多种材料 → idea-integration
   ├─ 已有卡片，想找关系／反例／检索入口 → knowledge-exploration
   ├─ 已有立场和多张卡，想形成输出 → narrative-composition
   └─ 不知道系统哪里出了问题 → system-review
```

## 推荐组合顺序

### 阅读一本书或课程

```text
人类建立初始 IIB
→ 人类结构阅读并画 Idea Atlas 骨架
→ 人类逐章阅读、回忆和画粗视觉
→ deep-reading 核对证据与误读
→ concept-visualization 精炼用户选中的单一洞见
→ knowledge-exploration 扩大关系和反例
→ narrative-composition 组合 BoaP／Storyboard
→ system-review 根据真实使用失败做复查
```

地图和原子卡是双向循环：Atlas 可以先于卡片出现，卡片也可以随后被重组进多个地图。

### 把现存卡更新为 Visual Main Note

使用 `visual-pkm-concept-visualization`：

1. AI 读取用户指定的现有卡片，区分核心观点、自己的解释、来源摘录和 AI 推断，同时记录实际路径为第 5 步唯一初始化目标；
2. 卡片已有一个明确核心命题时可以作为本轮核心信息；只有多个独立主张或意义不清时，才请用户确认或先拆卡；整张卡不是可视化对象，读取或选择它也不等于授权修改；
3. 用户围绕核心信息，用编号列表亲自写出 3–5 个相关词，不要求按词性分类；
4. AI 基于这些词扩展符号、隐喻、类比和视觉参考；
5. 第 3 步由 AI 逐一解释五种视觉框架的基本逻辑、用于当前信息时怎样组织以及最突出什么，再由人类选择；本步不要求构图、icon 或草图；
6. 第 4 步按框架寻找实际 icon／视觉组件，固定生成并打开系统临时目录中的 HTML，供用户预览、选择和重组；用户复制入选编号贴回对话，HTML 不生成最终构图，第 4 步也不写入 Vault；
7. 第 5 步回显第 1 步记录的卡片路径；先运行 `scripts/prepare_visual_main_note.py` dry-run，核对目标、编号、组件与待描摹项。获得“初始化并嵌入”授权后才加 `--apply`，通过 Excalidraw 插件初始化该卡的 Drawing，保留 frontmatter、正文、`sources`、`up`、有效链接和原场景；所有永久 icon 都必须是已描摹为原生元素的纯 JSON `.excalidraw` 组件。本地 `.excalidraw` 通过结构校验后直接复用，入选 SVG、PNG/JPG 或其他图像参考按确认外观描摹成 Vault 内原生 `.excalidraw` 组件并用 `--icon-map` 传给脚本，不复制、封装或直接嵌入源图，并统一按 `Icon - 关键词1, 关键词2 - 来源.excalidraw` 命名，由 Icon Library 自动发现；文件名是唯一索引，不另建 Markdown 清单、JSON 注册表或逐项元数据；
8. 把所有入选组件作为彼此独立的 image reference 松散放入初始素材托盘；新建或首次初始化的 Drawing 可以使用项目 `--concept-color-canvas` 作为默认背景，已有 Drawing 保留当前背景。知识卡自身不添加可见的满幅背景或外框；需要固定导出边界时使用描边与填充都为 `transparent` 的尺寸矩形，由父级地图／大卡决定可见外壳。验证重新打开可见后，由人类在该知识卡中移动、缩放、组合和补画，完成第一张约五分钟的粗草图；用户可以保留让核心机制可见的少量具体实例、状态和短标签；
9. AI 只描述元素功能、可观察歧义、差异和可能读法；人类判断感染力、代表性、记忆点、细节取舍、正反面分配与最终配色，并选择最终视觉；
10. 项目语义色板是可选的统一方案，不是定稿 Gate。已描摹 icon 的内部颜色始终排除在色板审计和迁移之外；只有用户明确要求统一视觉语言或登记受管文件时，才对画布背景与本卡非 image 原生元素通过 Excalidraw 插件完成语义映射并运行逐卡配色命令。

推荐提示词：

```text
请使用 visual-pkm-concept-visualization 读取 [[实际卡片名]]。
如果卡片已有一个明确核心观点，请把它作为本轮核心信息并原样回显，不要把整张卡图解；同时记录这张卡的实际路径，作为第 5 步唯一初始化目标。我随后会先列 3–5 个关键词；收到后再基于这些词扩展视觉参考方向，说明怎样画和突出什么。接着逐一解释对比、隐喻、过程、单一图像和场景五种框架用于当前信息时怎样组织、各自突出什么，再让我选择；第 4 步固定生成并打开包含实际图像的临时 HTML，供我预览和选择。我贴回入选编号后，请先回显目标路径并等待我回复“初始化并嵌入”；获得授权后通过 Excalidraw 插件初始化 Drawing，把入选 icon 确保落地为 Vault 内原生 `.excalidraw` 组件，并作为彼此独立的 image reference 松散放入初始素材托盘，不添加文字、箭头、关系或完整构图，然后让我在该卡中移动、缩放、组合和补画第一张草图。具体实例、状态和短标签是否保留在视觉正面由我决定；只说明它们的功能和可能读法，不要替我衡量、删减或分配正反面，也不要替我决定最终方案。
```

### 没有现成知识卡时创建 Visual Main Note

第 1 步只记录 `target_note_mode: new`，不提前创建文件。用户从第 4 步 HTML 贴回入选编号后，第 5 步执行：

1. 请用户确认一个名词、名词短语或动名词标题；
2. 搜索标题、aliases、近义词和关键动作，阅读候选并排除重复；
3. 回显拟创建路径 `Knowledge/Notes/<标题>.md`、已确认核心信息，以及“初始化 Drawing、落地入选 icon、嵌入初始素材托盘”的操作；
4. 用户回复“初始化并嵌入”后，使用 `Templates/知识卡.md` 创建只含最小 frontmatter、H1 和 abstract 的卡片；
5. 通过 Excalidraw 插件初始化 Drawing，删除模板占位内容和插件新增的纯工作流标签；复用或原生重建入选 `.excalidraw` 组件，并作为独立 image reference 松散嵌入；
6. 验证初始素材托盘重新打开可见后，再由用户在该卡中组合和绘制第一张草图。

不创建独立 Concept Visual 文件，也不提供纸笔或 Vault 外绘制分支。

### 已有很多卡，但不知道怎样组织

先判断问题：

- 想回答一个明确问题、澄清概念关系：`visual-pkm-spatial-mapping`；
- 想保存整个项目上下文：`visual-pkm-idea-integration`；
- 想寻找盲点和意外连接：`visual-pkm-knowledge-exploration`；
- 想表达一个立场和故事：`visual-pkm-narrative-composition`；
- 连问题是什么都不清楚：先向 `visual-pkm-system-review` 提交一次真实失败。

## 相邻 Skill 的边界

### Deep Reading vs Concept Visualization

- Deep Reading 核对用户对来源的理解。
- Concept Visualization 发展一个已经由用户提出的命题。
- 自己尚未理解原文时，不进入概念可视化。

### Spatial Mapping vs Idea Integration

- Map 围绕一个 focus question 表达结构。
- IIB 保存一个长期项目的多模态上下文。
- 不要把临时材料全部塞进稳定 Knowledge Map。

### Idea Integration vs Knowledge Exploration

- IIB 是长期总部。
- Idea Mixer／Compass 是短期探索装置。
- 空间邻近不自动成为语义链接。

### Spatial Mapping vs Narrative Composition

- Map 解释概念如何组织。
- Narrative 解释用户为什么要以某个顺序讲述。
- “章节顺序”不是叙事，“然后”也不是充分关系。

### System Review vs 文件清理

- System Review 从真实检索、理解或应用失败出发。
- 单纯统一字段、格式化 Markdown 或批量整理目录，不应触发它。

## 不应自动串联的行为

- AI 不应读完来源后自动建卡、画 Atlas、补链接并生成 BoaP。
- 一个 Skill 的完成不自动授权下一个 Skill。
- 每次跨 Skill 都需要新的 Human First Expression。
- AI 不应为了完成流程制造空卡、弱链接、虚假反例或无意义地图。

```text
.agents/skills/<skill-name>/evals/trigger-evals.json # 触发边界测试
content/AGENTS.md                             # 项目级路由和安全规则
```
