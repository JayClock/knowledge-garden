# 项目口语练习

把项目介绍当事实底稿与展开素材，不把逐字背诵当目标。训练的是在时间限制内提取主线、解释机制、回应追问和被打断后继续。生成一份流畅答案、读过几遍和字符时长检查都不是用户已经练会的证据。

## 1. 启动与恢复

1. 确认项目、实际底稿路径及其 manifest，读取正文和相关 confirmed claims，核对职责与完成状态。若底稿没有 manifest 或存在事实冲突，先在对话中说明需要核对的具体点；未经授权不自动修复文件。
2. 用户没有指定时，项目介绍默认 2 分钟，自我介绍默认 90～120 秒；不要求先有 JD。项目不明确时只问练哪个项目，不发完整问卷。
3. 询问只影响行动的缺失信息：是否第一次练、采用录音转写还是文字回答、是否授权保存。可以先练再决定是否保存；“更新 Skill”不授权写练习或修改讲稿。
4. “继续练习”先运行 `practice_log.py status`，读取对应日志的原始回答、观察和唯一下一步。通用练习不读取其他岗位的下一步；有岗位时显式传 opportunity。没有记录就如实说这是第一轮。
5. 首轮回答前运行只读 `snapshot`，把底稿和相关 claims 的版本保留在会话上下文。恢复时如果 `needs_rebaseline` 为 true，先核对变化，不能沿用旧稿当现行事实；旧回答和评语仍保留为历史。
6. 向用户只显示本轮目标、一个问题、目标时长和提示程度。不要预先展示底稿答案、完整提取词、评分或一串追问。

Agent 从 Git 根目录运行（遵守 `CAREER_STATE_DIR`）：

```bash
python <career-assets>/scripts/practice_log.py snapshot \
  --state-dir <state-dir> --repo-root <git-root> \
  --manifest manifests/<project-interview-manifest>.json

python <career-assets>/scripts/practice_log.py status \
  --state-dir <state-dir> --repo-root <git-root> --project-id <project_id>
# 已有岗位练习另加 --opportunity-id <id>；不传则只恢复通用练习。
```

如果底稿还未受管，先按材料入口经授权建立 manifest，再保存依赖该底稿的练习；仍可先做不落盘的对话练习。

## 2. 一轮 20～25 分钟的动作

### 诊断尝试

先让用户不看全文口述一次，不提供标准答案。第一次可以卡住、漏点甚至讲不完；如果用户明确尚未熟悉材料，可先熟悉一次，再如实将尝试记为 `full`，不假称脱稿。

用户可自行计时并录音，把转写和实际用时发来；不能接收音频时说明限制，改收转写。不要声称在等待消息时已计时，也不自动读取、上传或转写本地录音。

### 按卡点补提示

收到回答后先引用一两处具体表现，区分：

- 提取困难：知道但想不起，以提取词帮助复述。
- 结构或表达问题：绕远、主语不清、术语堆叠，调整组织和句长。
- 机制理解缺口：能说名称但解释不了因果，以一个具体追问检验。
- 事实或证据缺口：新增个人职责、完成状态、数字或案例，转 `career-evidence` 核对；练习中不自动确认。

只选一个主要卡点，隐藏全文，用已有提取词或更少的事实锚点再讲。保持用户原始回答与 AI 建议分开；不把 AI 改写稿覆盖成用户口述。

### 逐题追问

每次只问一题，等用户回答后再决定下一问，一轮通常 2～3 问。围绕刚才回答验证问题来源、个人动作、技术机制、替代方案、实现与验证，不机械把整个问题库念完。

不在问题后附参考答案。用户请求提示时先给最小提示；用户明确要示范时可以给，但示范后的复述属于有提示练习，隔天再无提示复测。

### 局部重讲与收束

针对唯一主要卡点，要求用户重讲 30～90 秒的一段，或重答同一道题。对比原话判断是否改善，不只凭“听起来顺了”判通过。没有重讲就记未验证，用户疲惫或中断时及时收口。

结束只给：一个有效表现、一个主要卡点、这次重讲结果、下一次唯一任务。下一步明确任务、目标时长和提示程度；存在事实阻塞则下一步是核对事实，而不是继续打磨回答。

## 3. 提示撤除、延迟复测与打断

```text
熟悉全文（按需）→ 提取词复述 → 无提示口述
→ 随机追问 → 被打断后继续 → 30 秒／2 分钟／5 分钟切换
```

这不是每次从头跑的流水线。新轮优先执行上次下一步，通常隔天复测同一卡点；未复测不能把当场有提示的改善当成稳定能力。需要时请用户回来练，不擅自创建日程或任务。

文本异步对话无法真正中途打断：可以约定用户分段发送，在段落间插问；不要把这种模拟说成实时打断表现。音频只在实际可访问且可分析时用于声音反馈。

## 4. 反馈依据

分别看主线结构、机制解释、事实一致性、现场表达，不默认给综合分。每条观察注明来自用户自评还是 AI 判断，引用原话、用户报告或可验证录音位置，解释与下一步分开。

- 只有文字或转写：可判断内容、结构和技术含义；不能据此断言语气自然、停顿合适、语速稳定或紧张程度。
- 实际时长只来自用户计时或已读取的媒体元数据。未计时用 null／unknown；字数估算只能作为估算，不能填实测。
- 转写中的 Yjs、Awareness、revision 等识别错误先与用户核对，不能直接认定技术理解错误。
- 没有记录的口误、故障、客户与数字不补写；一次卡住不证明没做过，也不触发缩小 confirmed claim。
- 练习成功只表示本轮任务的可观察表现；连续两次间隔练习、无提示复述及追问表现可支持提高难度，不能保证面试通过。

## 5. 授权记录

格式见 `career-assets/references/state-schema.md` 的 practice 部分。每轮是一条 JSONL，追加到 `<state-dir>/practice/<project_id>/sessions.jsonl`；不覆盖历史，不写入 Vault 项目介绍，不进入 `feedback.jsonl`，不创建虚构岗位。

经用户授权后，把会话中首轮前取得的 source 快照、实际回答、提示程度、计时来源、观察、唯一调整和下一步整理为临时 JSON，再运行：

```bash
python <career-assets>/scripts/practice_log.py record \
  --state-dir <state-dir> --repo-root <git-root> --input /tmp/practice-session.json
python <career-assets>/scripts/state_lint.py \
  --state-dir <state-dir> --repo-root <git-root>
```

`record` 只追加一条已验证记录，不修改 claims、manifest、opportunity 或讲稿。底稿在练习期间变更时保留原快照并提示需要重建基线，不能在保存时把旧回答冒充新版本练习。

- `completed`：本轮约定动作已执行，有实际回答、观察和一个主要调整；是否重讲成功仍由记录证据决定，不等于掌握。
- `interrupted`：保存已发生的尝试与停止位置，不补造回答、追问或重讲；允许尚无尝试，仍留下唯一下一步。
- 只有用户概述表现时用 `self_report`，不能当逐字转写；只有音频引用且未分析时只保存引用，不生成听感评价。
- 下一次通过 `resumes_session_id` 链接上轮同项目、同岗位上下文记录。未授权保存时只在对话中给相同的简短收束，跨会话恢复能力取决于是否有记录。

## 最短开场示例

> 本轮先练协同建模平台的 2 分钟脱稿介绍。请先不看全文，讲清项目解决的问题、你负责的部分和一个关键难点。自行计时，把原始口述转写和用时发来；卡住也先讲完，我收到后再逐题追问。

这是练习指令，不是参考答案。用户回答前停在这里等待，不继续替用户作答。
