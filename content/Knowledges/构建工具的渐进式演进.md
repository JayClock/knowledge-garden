## 核心判断

构建工具的渐进式演进，本质上是**处理时机**和**处理粒度**的变化：从 Webpack 式的构建前预整合，走向 Vite 式的开发时按需编译，再进一步变成由插件、Monorepo 和资源加载策略共同组成的能力调度系统。

它要解决的核心问题是：**在正确的时间，以正确的方式，处理正确的代码**。

---

## 这个主题下我目前知道的内容

### 1. Webpack：构建阶段的预整合

Webpack 的设计哲学是：**提前分析，整体打包**。

它通过静态分析依赖图谱，在构建阶段把 JavaScript、CSS、图片、字体等资源统一转换、整合并输出为生产可用的 bundle。它的优势是生态成熟、能力完整、产物可控；代价是开发启动和增量反馈容易变慢。

Webpack 的渐进式能力主要体现在两个方面：

- **代码分割与动态导入**：把所有代码预先纳入构建图谱，但允许部分代码在运行时按需下载。
- **插件与 loader 机制**：在基础打包流程上逐步叠加 CSS、TypeScript、JSX、压缩、分析等能力。

相关概念：[[../Cards/Webpack 的预整合打包思想的定义|Webpack 的预整合打包思想的定义]]

### 2. Vite：开发阶段的按需编译

Vite 把渐进式思想从“生产产物优化”推进到了“开发体验优化”。

它利用现代浏览器对原生 ES Modules 的支持，让浏览器直接请求模块；开发服务器只在请求发生时即时编译对应模块。这样，构建工具不再需要在启动时预先打包整个应用，而是可以按浏览器访问路径逐步处理代码。

Vite 的开发流程可以概括为：

1. 浏览器请求入口模块。
2. Vite 开发服务器接收请求。
3. 服务器即时编译该模块并返回 ESM。
4. 浏览器继续解析 import，触发下一批模块请求。
5. 编译链条随着实际访问路径渐进展开。

但 Vite 并不是完全放弃打包。生产阶段仍然需要借助 Rollup 一类的打包能力，来获得压缩、兼容性、代码分割和资源调度能力。

相关概念：[[../Cards/Vite 用原生 ESM 实现开发阶段按需编译|Vite 用原生 ESM 实现开发阶段按需编译]]

### 3. 插件系统：构建能力的渐进增强

构建工具的插件系统体现了一种典型的渐进增强思想：基础构建流程只解决最核心的问题，额外能力通过插件逐步叠加。

例如：

- 基础 JavaScript 转换是核心能力。
- TypeScript 支持是类型语言增强。
- JSX / Vue SFC 支持是框架语法增强。
- CSS 处理、压缩、分析、资源优化是工程化增强。

因此，构建工具不只是一个“打包器”，更像一个**增强能力调度中心**：它根据项目需要，把不同转换、分析、优化能力编排到构建流程中。

相关概念：[[../Cards/构建工具插件系统体现渐进增强的方法|构建工具插件系统体现渐进增强的方法]]

### 4. Monorepo：构建优化进入架构层

当项目规模扩大后，构建优化不再只发生在单个应用内部，也会进入包边界、依赖关系和工程组织方式之中。

Monorepo 通过 workspace、包内 exports、按需导入、任务缓存和依赖图分析，让构建工具能够只处理真正受影响的包或模块。这使渐进式构建从“模块级按需处理”进一步扩展到“架构级按需集成”。

它的关键变化是：

- 从单应用构建，扩展到多包协同构建。
- 从代码分割，扩展到包边界设计。
- 从局部资源优化，扩展到依赖图和任务图优化。

相关概念：[[../Cards/Monorepo 把构建优化推进到架构层面的渐进集成|Monorepo 把构建优化推进到架构层面的渐进集成]]

## 这个主题可以拆成哪些部分

构建工具的渐进式演进可以拆成四个维度：

| 维度 | 变化 | 代表现象 |
|---|---|---|
| **时机维度** | 从构建前统一处理，到开发时 / 请求时按需处理 | Webpack → Vite |
| **粒度维度** | 从应用级 bundle，到模块级、包级、甚至函数级处理 | ESM、代码分割、按需导入 |
| **体验维度** | 从功能完整优先，到反馈速度和开发体验优先 | 快速启动、精确 HMR |
| **架构维度** | 从单体应用构建，到多包、多应用协同构建 | Monorepo、任务缓存、依赖图 |

这些维度共同指向一个趋势：构建工具越来越少地“提前做完所有事情”，越来越多地“根据实际需要调度能力”。

## 实际项目中的应用要点

### 分层构建配置

实际项目中，可以把构建配置分为基础层、开发增强层和生产增强层：

- **基础层**：定义所有环境共享的构建目标和基本转换规则。
- **开发增强层**：关注启动速度、代理、调试、sourcemap、HMR。
- **生产增强层**：关注压缩、缓存、分包、预加载、产物分析。

这种配置方式的重点不是“配置更多”，而是让不同阶段只启用真正需要的构建能力。

---

### 渐进式资源加载

构建工具最终服务的是运行时资源调度。代码分割、动态导入、预加载和懒加载，本质上都是在回答同一个问题：

> 哪些代码必须立即加载，哪些代码可以稍后加载，哪些代码只有在用户触发某个场景时才加载？

因此，渐进式构建不只发生在 build 阶段，也会延伸到浏览器加载、路由切换、组件渲染和用户交互路径中。

## 暂时结论

构建工具的渐进式演进不是简单地从 Webpack 替换为 Vite，而是构建思想的迁移：

> 从“提前预测并整合所有代码”，转向“根据开发、构建、加载和架构场景，按需调度必要能力”。

Webpack 代表了构建阶段的预整合范式；Vite 代表了开发阶段的按需编译范式；插件系统让构建能力可以渐进增强；Monorepo 则把构建优化推进到工程架构层面。

因此，构建工具演进的核心不是工具名称变化，而是处理时机、处理粒度和能力调度方式的变化。
