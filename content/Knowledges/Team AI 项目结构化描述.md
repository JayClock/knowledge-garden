# Team AI 项目结构化描述 (面试专项版)

 需求背景介绍

**项目概述**：本项目旨在打造一个面向软件交付场景的本地优先、可私有化部署的 **AI 原生协作工作台**。系统集成了 Web 控制台与基于 Tauri 的桌面运行时，通过 Rust 本地控制平面承载项目管理、任务看板、智能体编排与全链路可观测性，实现了从目标拆解到执行回流的闭环。

**业务需求**：企业落地 AI 的核心痛点在于如何构建稳定的上下文（Context）。传统的 AI 聊天无法形成持续的生产力，本项目旨在将 Goal、Task、Spec、Session 等零散对象组织成结构化事实，让 AI 能够基于项目级上下文进行持续协作。

**核心业务需求**：
- **项目级协作建模**：围绕 Project、Task、Session、Trace 建立完整的数据生命周期闭环。
- **看板式执行推进**：支持多阶段看板流转，并集成 AI 辅助的任务策略校验与自动分发。
- **多智能体编排**：支持角色 (Role)、专家库 (Specialist) 与工作流 (Workflow) 的可视化拖拽编排。
- **本地优先架构**：利用 Rust 与 SQLite 构建高性能本地控制平面，确保数据隐私与离线工作能力。
- **全链路监控**：提供 Token 统计、节点耗时分析与执行轨迹 (Trace) 回放。

**技术需求**：
- **核心建模**：采用 **Smart Domain DDD**，通过 Association Object 解决模型纯度与数据库查询性能的冲突。
- **API 设计**：采用 **HATEOAS Level 3**，实现资源自发现与动作驱动的前端交互。
- **混合栈架构**：基于 Next.js/React 19 构建前端，服务端由 Java (领域模型) 与 Rust (本地运行时) 协同驱动。
- **工程化方案**：基于 Nx 与 Turborepo 的多语言 Monorepo 治理方案。

 简历描述示例

**初级/中级 - AI 协作平台前端开发**：
参与开发可视化应用编排平台，基于 React 19 和 Vite 实现项目工作台与任务看板。封装 HATEOAS 资源客户端，通过语义链接导航实现前后端解耦，并集成 Tiptap 实现支持变量引用的 Prompt 编辑器。

**中级/高级 - AI 应用引擎全栈开发/架构设计**：
主导设计并实现基于 Smart Domain DDD 的本地优先 AI 协作平台。采用 Association Object 模式解决复杂领域建模下的性能挑战；基于 Rust/Axum 构建高性能本地运行时控制平面；通过 HATEOAS Level 3 实现自描述 API，显著提升了系统的可观测性与 Agent 可访问性。

 面试问题与核心思路

**如何设计一个既符合 DDD 语义又兼顾 N+1 查询性能的领域模型？**
- **思路**：摒弃贫血模型，采用 **Smart Domain**。不让实体直接暴露 List 集合，而是建模为 **Association Object**（关联对象），将一对多关系封装在独立领域对象中，配合 HATEOAS 实现资源的渐进式延迟加载。

**为什么这个项目同时采用 Java 和 Rust 两套后端？如何做权衡？**
- **思路**：Java 侧主要负责复杂的业务领域建模（利用 Spring 生态和 DDD 支持）；Rust 侧则作为本地桌面运行时（Tauri Core），处理高性能 IPC、本地数据持久化与智能体底层通信。

**如何让 AI 协作从“聊天”升级为“项目级”生产力？核心难点是什么？**
- **思路**：核心是将非结构化的对话转化为结构化的 **Project Context**。
- **难点**：多粒度上下文的精确注入（Token 管理）；任务依赖关系的拓扑排序与动态更新；以及执行证据（Trace）的自动化回流与验证。

**Monorepo 架构在多语言混合项目中起到了什么作用？**
- **思路**：通过 Nx 实现统一的任务编排（Build/Test/Lint）。在保证各个子包（Java/Rust/TS）独立演进的同时，通过统一的 Schema 定义实现跨语言的数据模型一致性。
