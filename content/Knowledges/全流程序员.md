# 全流程序员

全流程序员不是沿技术栈扩展能力，而是沿软件交付的知识流扩展上下文理解能力。它关注从真实问题、业务分析、方案设计、任务分解、编码测试，到上线运营这一整条流中，知识如何被创造、传递、消费并最终变成业务价值。

## 背景脉络

- [[./微服务|微服务]]、BFF、微前端让系统的交付边界变小，前后端之间被 API 分隔，业务能力和 User Journey 不再天然处在同一个交付单元里。
- [[./程序员的职业素养|程序员的职业素养]]强调工程能力不只是写代码，也包括理解业务上下文、协作、长期可维护性和持续交付。
- [[./知识工程师|知识工程师]]把软件开发理解为知识的创造、传递和消费；全流程序员正是从知识传递的角度重新定义程序员能力边界。
- [[../Cards/统一语言的核心概念和应用要点是什么？|统一语言的核心概念和应用要点是什么？]]帮助业务人员与开发人员沿知识流共享上下文，是全流能力的重要实践。

## 能力方向

- 分析和建模：理解业务问题、业务语言、领域模型和问题边界。
- 任务分解：理解架构如何指导需求拆解和组件协作。
- 测试和编码：把问题转化为可验证、可维护的代码。
- 上线和运营：理解部署、监控、埋点、运维反馈对编码决策的约束。
