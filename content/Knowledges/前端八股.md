## 核心判断

- 前端八股不是题库目录，而是一套面试中反复考察的「基础概念 → 实现机制 → 工程应用」知识索引。
- 复习优先级应从高频基础概念开始，再进入框架、工程化与手写题；每个题目都要能落到一个可复用的概念卡片或实现卡片。
- 复杂手写题不只考记忆，还要能说明边界条件、测试用例和为什么这样实现。

## 这个主题要回答的问题

- 面试官通常借前端八股判断哪些底层能力：语义化、布局、类型系统、原型机制、异步、网络、浏览器安全还是工程化？
- 哪些题目只是需要快速回忆，哪些题目需要沉淀为可复用的实现机制卡片？
- 遇到手写题时，如何从「能写出来」推进到「能说明边界和测试」？

## 主题结构

- HTML 负责页面结构语义：重点不是标签背诵，而是能解释结构对可访问性、SEO 和维护性的影响。
- CSS 负责布局与渲染规则：盒模型、外边距、BFC、定位、对齐和响应式布局共同决定页面如何被排布。
- JavaScript 负责语言机制与运行时行为：类型判断、相等比较、值与引用、原型链、深拷贝和数组判断是高频基础。
- 框架与工程化负责把基础机制组织成项目能力：[[./React|React 面试主线]]、[[./Webpack|Webpack 构建主线]]和项目设计问题应放在更大的工程语境中理解。
- 网络与浏览器原理负责解释运行环境：HTTP 状态码、虚拟 DOM、Diff、XSS 等问题连接了协议、渲染、安全和性能。
- 手写题负责检验抽象与边界意识：Promise、深比较、instanceof、new 等实现题都要补充测试思路。

- React 面试题应进入框架心智模型，而不是散落在基础题中：[[./React|React 面试入口]]。

- 虚拟 DOM 的重点是用 vnode 和 patch 支撑数据驱动视图：[[../Cards/虚拟 DOM（Virtual DOM）的核心概念和应用要点|虚拟 DOM 的存在理由]]。

### 网络、浏览器与安全

- XSS 的核心是恶意脚本进入并执行，防护要从输入、输出和执行环境同时考虑：[[../Cards/XSS 攻击的原理和防护方式|XSS 原理与防护]]。
