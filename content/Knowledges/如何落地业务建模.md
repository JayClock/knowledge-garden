# 两关联一循环
## 模型与软件实现关联
1. 模型的好坏直接影响了软件的实现
2. 模型的好坏直接影响了统一语言
3. 模型的好坏直接影响传递效率与成本
## 统一语言和模型关联
### 什么是统一语言
1. 统一语言与领域模型关联，且统一语言被多方认可，才算统一语言
2. 统一语言只能在使用中被确立
### 为什么需要统一语言
1. 模型将业务维度隐藏了，对业务方显得不够直观
2. 对于未提取的知识，超出了模型的表单能力。因此统一语言是非常必要的
### 统一语言的好处
1. 统一语言实际上赋予了技术人员定义业务的权利
2. 统一语言为技术方和业务方提供了一种更好的协同方式的可能性。
### 现实场景
代码重组与重构时，我们就是在改变模型。**却鲜少让业务知晓这种反馈，业务也没有机会验证这种改变是否在合理的方向上**。这就导致一个非常现实的问题。技术不断通过修改实际的业务模型，而业务方却无法按照技术方改变后的业务概念去思考问题。随着时间的累积，双方对业务模型的认知差异会越来越大，最终导致双方互相看不爽（业务侧觉得技术能力不行，技术侧觉得业务需求离谱）
## 提炼知识的循环
### 循环流程（和 Refactoring 与 TDD 的对比）

| Cycle                                                | Refactoring       | TDD            |
| ---------------------------------------------------- | ----------------- | -------------- |
| 通过语言讨论需求                                             | 发现坏味道，明确改变方向      | 构建一个失败测试表明需求变化 |
| 发现模型中的缺失或者不恰当的概念，<br>然后精炼模型，以反映业务的实际情况               | 尝试消除坏味道以改进目前状况    | 修改代码实现         |
| 对模型的修改会引发统一语言的改变，<br>再以试验和头脑风暴的态度，使用新<br>的语言验证模型的正确性 | 通过坏味道是否消失判断改进是否成功 | 通过测试仪证明需求变化完成  |
