# 全栈工程师简历候选人回答逐字稿

关联：[[职业经历]]、[[全栈工程师简历]]、[[全栈工程师简历追问地图]]。

这些文件按“候选人能直接说出口”的方式写，不是知识点清单。建议按“复杂前端与多端一致性 → HATEOAS 资源契约 → 建模与 RESTful API → 可执行模型与实时协同 → AI 工程化”的能力演进理解，不要把项目背成彼此无关的技术名词。

> [!warning] 使用边界
>
> - 生产事实以 [[职业经历]] 和 [[全栈工程师简历]] 为准。
> - 标记为“架构延展”或明确属于他人实现的协作链路，只能用于讨论方案，不能说成个人已经上线的成果；协同建模项目中的 Yjs 前端绑定、Awareness、NestJS WebSocket 服务和 PostgreSQL 持久化属于本人直接实现。
> - 示例代码只解释机制；订单、审批、Webhook 等示例不自动代表真实业务。
> - 没有记录的用户数、项目规模、效率比例和故障案例不临场补数字。

## 回答节奏建议

- **30 秒版**：先讲业务问题，再讲你的核心设计，不要先堆名词。
- **2 分钟版**：补一层架构和一个真实边界，比如错误、兼容、性能、测试。
- **深追版**：承认取舍，讲当时怎么验证，而不是说“最佳实践就是这样”。
