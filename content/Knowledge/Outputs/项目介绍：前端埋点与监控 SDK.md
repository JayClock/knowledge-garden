# 项目介绍：前端埋点与监控 SDK

## 提取词

下游证据倒推 ｜ Monorepo与插件协议 ｜ 零侵入请求代理 ｜ 本地队列与退避重试 ｜ executionId业务日志串联

## 5 分钟主讲

我先介绍一下这个项目的背景。作为低代码平台前端架构的基础设施，监控 SDK 跑在所有业务应用中。过去很多前端做监控容易陷入一个误区，就是对着浏览器 API“能采什么就采什么”，结果上报了一堆无用的字段，真正线上出故障时依然看不出是哪个业务环节坏了。我在做这个 SDK 时，确立的核心设计原则是：**绝不从 API 倒推采集，而是从下游验收和排障究竟需要什么证据，来倒推事件、上下文和关联标识**。我直接负责 SDK 的核心架构、采集插件、多框架适配与端侧上报全链路。

在架构设计上，SDK 基于 Monorepo 做了非常清晰的职责解耦：Core 包保持纯粹与框架无关，只负责统一的事件协议、插件生命周期与 Transport 上报；Browser 包封装 PerformanceObserver、全局错误监听、DOM、Fetch 与 XHR 等 Web API；上层再针对 React、Vue 和 Vanilla 提供适配包，抹平框架生命周期的差异。性能、异常、请求和操作行为全部作为独立插件可插拔注册。这样新增一个采集指标无需在各个框架重复写，调整上报策略也不会侵入具体的采集逻辑。

但在工程落地时，监控 SDK 面临的最大挑战是如何做到**极低的性能开销与真正的零业务侵入**。监控代码绝对不能反噬宿主业务：在性能侧，我们通过 PerformanceObserver 采集 Web Vitals（如 FCP、LCP、CLS、INP 和 TTFB），Observer 的回调只做最轻量的内存指标记录，复杂的聚合计算与网络发送绝不占用主线程渲染时机；在请求代理侧，对 Fetch 和 XHR 做切面拦截时，只记录 URL、耗时、状态码和必要链路头，必须严格透传原始参数、返回值和 Promise 状态，绝不破坏业务原有的异步时序，更不能在拦截时消费 stream 导致业务无法再次读取响应体；而且采集层必须做严格的全局错误隔离，即使 SDK 自身报错，原业务请求也必须照常执行或原样抛错。

在网络传输与错误还原上，每个事件立即上报会产生海量零散请求并阻塞网络带宽，因此事件先进入本地内存队列。队列结合时间间隔、数量阈值或路由跳转批量打包发送，并结合指数退避算法处理弱网重试；在页面卸载时结合 sendBeacon 提升终结态上报成功率。对于生产环境被混淆压缩的报错，在 CI/CD 构建阶段生成并上传 Sourcemap 资产并与版本号严格对齐，在线上堆栈捕获时按行列号精准反解为源码文件与行数。

为了真正验证监控对复杂业务的诊断价值，AI Flow 工作流引擎是一个典型的落地案例：为了区分用户究竟是在工作流连线校验、测试运行还是发布环节失败，我为这三个关键业务路径注入了自定义追踪事件；而具体节点成功失败、耗时与堆栈错误由 TypeScript 执行引擎日志精确负责。两端通过同一个 executionId 深度串联，打通了“用户在前端点了什么”到“引擎在底层执行了什么”的完整可观测闭环。

这个 SDK 的核心价值不是采得更多，而是把下游需要的判断变成稳定的证据契约。统一事件、队列和 Transport 构成了稳定基线，多框架适配与自定义事件按环境逐层增强，打通了从前端操作路径到后端引擎事实的全链路追踪闭环。

## 2 分钟版本

我负责监控 SDK 的采集与上报侧。设计时不是先看浏览器能采什么，而是先确认后续验收和运行诊断需要依据什么证据，再定义通用指标、业务事件、必要上下文和关联标识。

AI Flow 是一个实际接入实例。为了区分用户是在工作流校验、测试运行还是发布环节失败，我为三个关键路径添加自定义事件；节点状态、耗时和错误仍由执行引擎日志记录，前端路径和节点证据通过 `executionId` 关联。

SDK 使用 pnpm Monorepo 拆分 core、browser 和 React／Vue 适配包。core 定义插件协议、统一事件和 Transport，browser 封装 PerformanceObserver、全局错误、DOM、Fetch 和 XHR，框架适配包只处理生命周期差异。性能侧采集 Web Vitals，异常侧覆盖全局 error、`unhandledrejection` 和业务自定义错误；所有代理都必须保留原始业务语义。

事件先进入本地队列，再按时间、数量或路由变化批量发送，并结合失败重试处理网络异常；生产堆栈通过构建版本和 Sourcemap 还原。服务端数据存储与监控控制台由后端及大数据团队负责，我专注保障端侧采集与上报的高可靠与低侵入。

## 30 秒版本

我负责监控 SDK 的采集和上报侧，把“系统怎样证明契约被正确执行”固化为事件、上下文和关联标识。AI Flow 接入时，我为校验、测试运行和发布添加自定义事件，并通过 `executionId` 关联节点执行日志；通用性能、异常、请求与操作数据则由多端适配包共同消费同一协议。

## 渐进式架构视角

统一事件、队列和 Transport 是核心基线，browser、React、Vue、Vanilla 和业务自定义事件按环境逐层增强。监控不能成为宿主业务的必要前提，因此代理必须保留原始语义，采集和发送失败要被隔离，确保了监控基础设施在复杂多端环境下的高内聚与容灾弹性。
