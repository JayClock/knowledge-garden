## 完整版本

面试官你好，我有五年以上开发经验，主要使用 React 和 TypeScript，定位是全栈偏前端的平台工程师。我习惯从上下游一起看交付：上游需要定义清楚什么业务契约，中间如何消费与执行，最后怎样提供证据进行验证。

在易校做低代码平台时，PC 和移动端各自维护状态机容易导致规则漂移。我推动引入 HATEOAS，把“资源当前能做什么”收敛回服务端；我负责 TypeScript SDK 与 React 消费层，并与后端协同落地接口，让多端统一消费同一份契约，通用消费层后续也开源为独立 npm 包。

这类契约离不开上游业务模型。在鼎歆，我设计并实现了 AI 辅助领域建模平台，以双层循环 Harness 组织真实约定澄清与模型增量维护。桌面端修改本地文件并按轮次刷新图谱，配套框架区分模型检查与人工范围确认，再设计和校验 API、派生文档与静态测试向量；模型也可通过 MCP 同步到本地。

在执行侧，我负责普通业务工作流的协议、React Flow 画布、Tiptap 变量与公式 AST，以及 TypeScript 执行引擎。通过 DFS 判环、Kahn 拓扑调度和分支剪枝连接配置与执行，并实现 SSE 服务端推送和前端日志，以执行 ID 和节点 ID 定位运行过程。

在运行诊断侧，我负责监控 SDK 与数据采集后端。从排障需要倒推统一事件，用多框架适配、队列和重试组织采集上报，再通过 NestJS 接收、Kafka 异步处理和 ClickHouse 存储查询，并接入 Sourcemap 上传与版本映射来定位源码。

这四个项目贯穿着同一条主线：把业务理解转化为明确契约，再通过复杂平台、执行引擎与监控闭环保证确定性落地。我的优势就在于能把业务建模、复杂前端与执行验证完整连起来。
