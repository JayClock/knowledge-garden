# 自我介绍

面试官你好，我有 6 年多开发经验，相比单纯拓展技术栈成为全栈工程师，我更擅长思考上游的工作会如何影响我的任务，以及我的任务又会如何影响之后的流程。

比如我设计的 HATEOAS 资源动作契约，及其 ts 消费层，核心原因便是发现要解决多端一致性的问题，必须都上游后端的 api 设计出手，把前端散落的判断逻辑，收敛至 api 接口中。

在实践过程中，发现 restful api 的设计，需要有良好的业务模型支撑，于是又开发了以履约建模法为核心的全栈建模平台，把整个系统的参与方、权责关系对象沉淀为前端与后端共同审核的语义契约，主要实现的是可视化模型记录、审核发布与契约导出，AI 生成的 Proposal 由用户逐项确认后进入模型草稿，平台还将多表模型定义导出为一致的 FM 快照，通过 MCP 交给本地同步程序完成下载、校验和文件更新。

这种理解上下游定义契约的形式，可以用于任何系统汇总，比如在低代码工作流引擎中，我用 WorkflowDefinition、节点 Schema 和变量协议连接编辑器与 TypeScript 执行引擎，再通过 `executionId` 关联测试、发布路径和节点日志

除了前后端之间的契约，前端与设计之间也有契约。设计 DSL 建立产品设计与前端实现之间的契约，以 Schema、revision、Visual Harness 和只读 MCP 控制生成与消费。
