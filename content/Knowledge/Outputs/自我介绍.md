## 完整版本

面试官你好，我有五年以上开发经验，主要使用 React 和 TypeScript，定位是全栈偏前端的平台工程师。我习惯从上下游一起看交付：上游需要定义清楚什么业务契约，中间如何消费与执行，最后怎样提供证据进行验证。

在易校做低代码平台时，PC 和移动端各自维护状态机容易导致规则漂移。我推动引入 HATEOAS，把“资源当前能做什么”收敛回服务端；我负责 TypeScript SDK 与 React 消费层，并与后端协同落地接口，让多端统一消费同一份契约，通用消费层后续也开源为独立 npm 包。

这类契约离不开上游业务模型。在鼎歆，我设计并实现了 AI 辅助领域建模平台，以 Evidence 建模方法为基础，把参与方、权责与事件记录为结构化资产；AI 提案由人工逐项审核发布，正式模型向下游导出 API 契约和测试数据，并通过 MCP 同步到本地。

在执行侧，我负责低代码工作流引擎，用统一协议连接配置与执行。端侧负责 React Flow 画布、Tiptap 变量与公式 AST 解析，引擎侧自研 DAG 拓扑调度与分支剪枝算法，并通过 executionId 与 SSE 实时推送执行日志，打通编排到执行的闭环。

在验证层面，我独立负责前端监控 SDK 采集与上报侧。我坚持从排障需要倒推事件模型，以 Monorepo 抹平 React/Vue 框架差异，通过本地队列、退避重试和 Sourcemap 还原，为全业务线提供高可靠、零侵入的运行证据底座。

这四个项目贯穿着同一条主线：把业务理解转化为明确契约，再通过复杂平台、执行引擎与监控闭环保证确定性落地。我的优势就在于能把业务建模、复杂前端与执行验证完整连起来。
