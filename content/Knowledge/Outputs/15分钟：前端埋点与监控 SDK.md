## 2 分钟项目介绍

我负责监控 SDK 的采集与上报侧。设计时不是先看浏览器能采什么，而是先确认后续验收和运行诊断需要依据什么证据，再定义通用指标、业务事件、必要上下文和关联标识。

AI Flow 是一个实际接入实例。为了区分用户是在工作流校验、测试运行还是发布环节失败，我为三个关键路径添加自定义事件；节点状态、耗时和错误仍由执行引擎日志记录，前端路径和节点证据通过 `executionId` 关联。

SDK 使用 pnpm Monorepo 拆分 core、browser 和 React／Vue 适配包。core 定义插件协议、统一事件和 Transport，browser 封装 PerformanceObserver、全局错误、DOM、Fetch 和 XHR，框架适配包只处理生命周期差异。性能侧采集 Web Vitals，异常侧覆盖全局 error、`unhandledrejection` 和业务自定义错误；所有代理都必须保留原始业务语义。

事件先进入本地队列，再按时间、数量或路由变化批量发送，并结合失败重试处理网络异常；生产堆栈通过构建版本和 Sourcemap 还原。NestJS 数据服务、Kafka、ClickHouse、查询后端和控制台由其他同事负责。当前只讲消费需求、事件设计和关联机制，不补下游使用方式或量化收益。

## 5 分钟主讲法

### 1. 先从下游需要的判断倒推证据

埋点不是按照浏览器 API“能采什么就采什么”。我会先确认后续验收或运行诊断要区分哪些环节、依据什么结果行动，再定义事件、必要上下文和关联标识。AI Flow 中的校验、测试运行和发布事件就是这种业务自定义采集；`executionId` 用来连接用户路径与执行引擎日志。

### 2. 再控制 SDK 自身风险

监控是接入所有业务页面的基础设施。它需要覆盖足够多的信息，但采集回调不能阻塞渲染，代理不能改变请求行为，上报也不能制造大量网络开销。消费需求决定采什么，低侵入和可靠性决定怎样采。

### 3. 包边界和插件协议

core 保持框架无关，只定义 SDK 生命周期、插件、事件协议和 Transport。browser 封装 Performance、Error、DOM、Fetch 与 XHR 等 Web API。React、Vue 和 Vanilla 复用同一套采集逻辑，适配包只处理各自的初始化和生命周期。

性能、异常、操作和请求采集作为独立插件注册，最终输出统一事件。Transport 只关心怎样发送。这样新增采集项不需要在每个框架复制实现，调整发送策略也不会修改所有插件。

### 4. 性能和异常怎样采集

PerformanceObserver 与 Web Vitals 负责 FCP、LCP、CLS、TTFB 和 INP。指标要回到用户体验解释：内容什么时候出现、主要内容何时完成、布局是否稳定、服务端响应多快、交互是否及时。Observer 回调只做轻量记录，聚合和网络发送放到后续队列。

全局 error 和 `unhandledrejection` 覆盖运行期异常，业务可以补充自定义错误。事件携带页面、版本、位置和堆栈等上下文，不能只保存一段字符串。

### 5. 请求代理不能伤害业务

Fetch／XHR 代理只记录 URL、耗时、状态码和错误上下文，必须保留原始参数、返回值、Promise 状态和异常语义。读取 response body 也要谨慎，直接消费 stream 可能让业务无法再次读取。

监控逻辑需要错误隔离。即使采集代码失败，原请求也要照常完成或按原语义抛错。

### 6. 队列平衡实时性和请求开销

每个事件都立即发送会产生大量小请求，所以事件先进入本地队列。队列可以按时间间隔、数量阈值或路由变化触发批量上报。批量会增加延迟和关闭页面时的丢失窗口，因此不同事件需要不同策略。

当前可以确认批量和失败重试，但没有 `sendBeacon`、IndexedDB 持久离线队列等项目证据，这些不进入成果。

### 7. Sourcemap 还原生产异常

生产 JavaScript 被压缩和混淆，堆栈只能指向产物位置。构建阶段需要生成并上传 Sourcemap，并与应用版本和产物文件关联；监控侧再根据行列号还原源码位置。映射文件用于受控处理，不直接暴露给终端用户。

### 8. 协作边界和结果

我的工作覆盖核心包、浏览器包、React／Vue／Vanilla 适配、采集插件、统一协议、本地队列和 Sourcemap 链路。SDK 覆盖低代码平台中的不同功能和技术栈，并已在 AI Flow 中用于校验、测试运行和发布事件，再通过 `executionId` 关联执行日志。

NestJS、Kafka、ClickHouse、查询后端和控制台由其他同事实现。当前没有可核验的下游使用方式、事件量、上报成功率、采集开销或故障定位收益，因此只讲证据设计、实现与关联机制。
