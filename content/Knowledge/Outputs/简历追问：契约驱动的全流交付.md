# 简历追问：契约驱动的全流交付

关联：[[简历回答逐字稿：契约驱动的全流交付]]、[[全栈工程师简历追问地图]]。

## 面试官真正想确认

“契约驱动”是否来自真实协作问题，能否说明契约的知识来源、权威方、结构、消费方、验证方式和变更边界，而不是把已有项目统一换成一个抽象口号。

## 总追问链

### 1. 契约从哪里来

- 当时哪些角色或系统在重复解释同一份知识？
- 原来的歧义具体落在状态、权限、动作、字段、布局还是执行顺序？
- 为什么普通文档、前端配置或接口封装不足以解决？
- 谁有权确认契约，谁只能提出候选？

### 2. 契约怎样表达

- 为什么选择领域模型、HAL、Schema、WorkflowDefinition 或设计 DSL？
- 哪些部分要求编译期约束，哪些必须运行时校验？
- 契约如何表达版本、生命周期、关系、动作和失败？
- 怎样避免契约退化成字段清单、按钮数组或技术类型？

### 3. 契约怎样被消费

- 前端、后端、运行时和 Agent 分别消费什么？
- 消费端还需要保留哪些展示或交互决定？
- 哪些业务合法性不能在多个消费者中重新实现？
- 新契约或新能力加入时，旧消费者怎样处理？

### 4. 契约怎样验证与演进

- 用了哪些单元、契约、E2E、日志、监控和人工审核？
- 怎样区分契约本身错误、消费者实现错误和运行环境失败？
- 失败应该返回实现、契约还是业务模型？
- 哪些结果已有证据，哪些仍缺规模和量化口径？

## 领域建模平台：前端与后端契约

- 前后端原来分别在哪里解释业务对象、生命周期和动作？
- 8X Flow 怎样形成双方可审核的结构，而不只是画图？
- 模型如何进入 RESTful URI、relation、OpenAPI 草稿和测试数据？
- 为什么发布模型仍不能自动成为正式接口契约？
- 前端和后端发生分歧时，以模型、OpenAPI 还是实现为准？如何裁决？
- Yjs 收敛、模型版本和人工审核分别保证什么？
- 实际业务接口在从模型导出到前后端审核落地的全流程是怎样的？

## Figma AI：产品设计与前端契约

- 产品设计与前端交接时，哪些信息最容易从视觉稿中丢失？
- 设计 DSL 怎样表达图层、布局、变量和资产关系？
- 产品设计、AI、Canvas 编辑器和前端各自拥有什么权力？
- DesignPatch、ownership 和 revision 为什么属于契约治理，而不只是技术实现？
- MCP 当前提供了什么消费路径？为什么只读？
- 外部 Agent 生成 React 组件与产品内完整代码生成有什么区别？
- Design ↔ Code 双向同步的核心难点与架构演进路径是什么？

## HATEOAS：运行时前后端契约

- 领域建模平台与 HATEOAS 分别位于契约生命周期的哪一段？
- `_links`、`_templates` 和资源状态各自表达什么？
- relation 为什么不能退化成按钮名称？
- TypeScript SDK 怎样消费动态契约，同时保留运行时检查？
- 前端为什么仍然拥有交互呈现权，但不能重新实现业务状态机？
- 服务端实现与本人契约／SDK工作的边界是什么？

## AI Flow：编辑器与运行时契约

- 为什么 React Flow 节点和连线本身不足以成为执行契约？
- WorkflowDefinition、Node Schema 和变量协议怎样被编辑器与引擎共同消费？
- 哪些 UI 状态不能进入运行时？
- NodeRegistry 怎样让节点能力扩展而不破坏调度契约？
- Condition 分支和汇合节点如何维持执行语义？
- 工作流协议、前端接入与服务端 API／持久化的个人／协作边界是什么？

## 监控 SDK：证据契约

- 为什么监控事件也是契约，而不是随手埋点？
- 下游要回答什么问题，怎样倒推出事件、上下文和关联标识？
- `executionId` 怎样连接用户路径与节点执行事实？
- 为什么前端事件不能替代执行引擎日志？
- 事件协议怎样被 Vanilla、React 与 Vue 共同消费？
- 哪些下游系统属于团队链路而不是个人实现？

## 容易露馅的回答

- “契约就是接口文档／TypeScript 类型。”
- “领域建模平台是前端给后端画需求图。”
- “Figma AI 已经自动把产品设计生成完整前端页面。”
- “有 Schema 就不会出现语义错误。”
- “HATEOAS 后前端就不需要任何状态和交互判断。”
- “监控数据证明了业务收益”，但没有统计口径。
- 把 AI 候选、协作接口或团队服务端实现说成个人最终决定和个人编码成果。

## 准备证据

- 领域建模：8X Flow 模型、版本、Proposal、OpenAPI 草稿和人工审核边界；
- HATEOAS：资源响应、relation／action、SDK 消费代码和契约测试；
- AI Flow：WorkflowDefinition、Node Schema、变量协议和执行日志；
- Figma AI：设计 DSL、DesignPatch、revision、Canvas 和 MCP 读取；
- 监控 SDK：事件 Schema、`executionId`、适配包和上报队列。
