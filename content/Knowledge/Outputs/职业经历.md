## 二、核心工程能力框架

### 1. 复杂前端与编辑器架构

深度掌握现代富交互前端底座的设计与性能优化：

- **画布与图形**：基于原生 Canvas 与 React Flow 实现高响应度画布，覆盖缩放平移、视口变换、单选/多选/框选、节点拖拽挂载、Auto Layout 容器与吸附对齐。
- **变量编辑**：在 AI Flow 中使用 Tiptap 将变量引用渲染为不可拆分的标签，支持上游输出选择与执行协议序列化。
- **工程韧性**：系统性处理树形状态、浮动上下文菜单、协同状态同步与弱网环境下的异常恢复。

### 2. 上游契约与领域建模

不把前端视作被动的 API 消费者，而是主动参与上游业务建模：

- 使用 **8X Flow** 与**四色建模法**澄清业务参与方、权责关系、关键事件与生命周期。
- 将业务模型映射为 RESTful 聚合边界、URI 体系、HATEOAS relation 状态机与 HAL-FORMS 动作契约，从根源上降低端侧维护业务状态分支的复杂度。

### 3. 关联对象建模方法

设计并落地**关联对象建模方法**：

- 将传统实体间的一对多或复杂多对多关联显式抽象并建模为独立的领域对象。
- 建立稳定的接口契约以彻底隔离领域语义与底层数据访问策略，在严守聚合根边界的同时，有效防止非聚合根 Repository 的持久化逻辑泄漏，并从架构层面规避 N+1 查询风险（通用建模思想，不绑定具体技术栈，并在开源代码中完成可验证落地）。

### 4. 渐进式架构与可恢复增强

坚持**渐进式增强（Progressive Architecture）**：

- 优先稳定核心业务模型、任务路径与通信协议基石；
- 将 HATEOAS relation/action、多框架适配、节点插件及 AI Proposal 等高变化能力隔离为可插拔、可退化演进的增强层；
- 配合运行时 Schema 校验、降级退路、状态版本控制与人工确认 Gate，严格限定局部失效的爆炸半径。

### 5. 契约消费路径与验证闭环

- **消费层建设**：提供面向下游的 React 适配 Hooks、强类型 TypeScript SDK、HAL/HAL-FORMS 规范解析器及 OpenAPI 契约草稿，抹平成本。
- **全链路验证**：串联单元测试、契约测试、E2E 测试、人工评审、运行日志追踪与前端全量监控，形成“需求建模 → 契约制定 → 实现消费 → 运行反馈 → 模型修正”的完整工程闭环。

### 6. AI 确定性交付与 Agent Harness 双层循环

深刻理解 LLM 的能力边界：

- **语义与确定性分离**：将适合模型发挥的自然语言理解、候选方案（Proposal）生成，与必须由 DSL、Schema、CRDT、版本控制和质量门禁保证的确定性执行严格解耦。
- **双层循环架构**：
  - **外层循环（Plan / Gate）**：以经人工审核的业务模型、任务计划和权威状态机为前馈输入，由人类行使把关权；
  - **内层循环（Agent Pair）**：编排短生命周期任务、限制探索空间、以自动化测试和结构化日志为反馈控制，通过失败路由机制保障交付结果的高可靠性。

### 项目 4：企业级低代码 AI Flow 工作流引擎与复杂编排器（上海易校）

- **项目性质**：核心商业化平台基础设施（全栈参与，核心负责协议、执行引擎与复杂编辑器）
- **核心定位**：打造企业级低代码工作流调度引擎与可视化编排界面，支持内部员工、企业客户及研发人员编排复杂业务流与 AI 节点。

#### 架构设计与技术实现

1. **基于 Kahn 算法的执行调度内核**：
   - 独立实现 TypeScript 执行引擎：构建 `WorkflowEngine`、`GraphBuilder` 与 `ExecutionContext`；
   - 使用邻接表、反向邻接表与入度统计，基于标准 Kahn 拓扑排序算法实现高效的有向无环图（DAG）调度，并在初始化阶段进行死循环环路检测。
2. **条件分支动态剪枝算法**：
   - 设计 Condition 节点分支判定逻辑：执行期沿未命中分支向下递归遍历并排除死分支节点；
   - 引入下游汇合点入度保护机制，在剪枝过程中校验节点是否具有其他活跃入边，避免误伤公共汇合节点。
3. **微内核节点插件体系**：
   - 抽象 `NodeRegistry` 与 `BaseNodeExecutor` 标准接口，将节点输入校验、变量计算、耗时统计、错误隔离与上下文输出全面标准化，便于团队快速扩展自建节点与第三方 API 节点。
4. **Tiptap 结构化变量编辑器**：
   - 解决工作流参数引用的可读性与健壮性难题：基于 Tiptap 富文本开发专用变量节点，将 `${nodeId.variableName}` 渲染为不可拆分的结构化 Token 胶囊；
   - 支持通过 Slash (`/`) 菜单快速检索并插入上游可用变量，保存时自动序列化为规范协议，执行期递归解析嵌套变量。
5. **公式编辑器与 AST 求值链路**：
   - **公式编辑交互**：面向表单字段参与工作流计算的业务场景，实现字段与函数表达式的编辑交互，支持用户配置 `sum(金额1，金额2)` 等业务计算公式；
   - **自研解析与保存校验**：自行编写公式解析器，将表达式解析为抽象语法树（AST），并在保存时执行语法校验以拦截非法或错误公式；AST 中以稳定字段 ID 记录字段引用，将界面呈现的字段名称与底层引用标识解耦；
   - **运行时字段解析与求值**：在工作流节点执行阶段，通过全局变量按字段 ID 读取对应字段的完整信息，基于 AST 完成公式求值，实现从公式编辑、保存校验到运行时节点计算的完整闭环；编辑交互、解析校验与求值链路均由本人独立负责。
6. **数据持久化与可观测性打通**：
   - 独立设计并编写 PostgreSQL 数据库表结构，使用 Prisma ORM 落地模型定义与增删改查；
   - 全面集成前端监控 SDK，通过 `executionId` 唯一关联端侧测试运行、操作路径与后端执行引擎的 Trace 日志，并基于 DAG 拓扑顺序重构了日志 Trace 面板，彻底解决跨节点异步日志时序混乱问题。

#### 交付结果与项目边界

- **已达成成果**：打通了从工作流协议、节点 Schema、画布交互、变量绑定、公式编辑与 AST 求值、图校验、拓扑调度到状态监控的完整业务链条。
- **边界与限制**：
  - 数据模型与 Prisma 代码由个人直接编写；NestJS 接口框架与 SSE 服务端推送链路与后端同事协同完成；
  - 分布式高并发限流、跨机集群状态恢复、Loop 复杂循环语法为架构延展方向，未计入当前已完成事实；
  - 不人为编造未经统计的用户数与流程执行量。

### 项目 5：企业级前端全量监控 SDK（数据采集与上报侧）（上海易校）

- **项目性质**：平台公共基础设施（独立架构设计与核心代码实现）
- **核心定位**：服务于低代码平台全业务线的前端可观测性 SDK，以“下游故障定位与业务验收需要回答什么问题”反推事件设计，提供统一规范的事件协议。

#### 架构设计与技术实现

1. **下游驱动（Downstream-Driven）与多包工程**：
   - 告别盲目采集，紧密围绕网络排障、页面慢加载、JS 运行时崩溃与业务操作链路设计监控上下文模型；
   - 使用 pnpm 构建 Monorepo：细分为 `core`（通用调度协议、插件生命周期、内存队列）、`browser`（浏览器 API 封装）、`react` / `vue`（框架组件与生命周期集成）及 `types`。
2. **全面精准的数据采集**：
   - **性能指标**：基于 `PerformanceObserver` 接入 Google Web Vitals 标准，精准采集 FCP、LCP、CLS、TTFB 与 INP 指标；
   - **错误异常**：全面监听 `window.onerror`、`unhandledrejection` 以及资源加载错误；
   - **用户行为追踪**：透明劫持/包装 DOM 事件、原生 `Fetch` 与 `XMLHttpRequest`，在完全不侵入业务行为和返回值的原则下记录完整上下文。
3. **批量队列与弱网弹性上报**：
   - 事件先进入本地内存缓冲区，按设定的时间步长（Interval）、批次阈值或路由跳转动作批量触发上报；
   - 封装失败指数退避重试机制，有效平衡了端侧性能损耗、网络开销与数据上报率。
4. **生产 Sourcemap 还原闭环**：
   - 协同打通 CI 产物构建与 Sourcemap 版本上传管线，使得监控后台能利用映射表将线上压缩堆栈精准反解为源码行列号。

#### 交付结果与项目边界

- **已达成成果**：监控 SDK 已全面接入低代码平台所有前端模块（覆盖 Vanilla JS、React 和 Vue 多种技术栈），AI Flow 引擎是其典型的生产接入范例。
- **边界与限制**：
  - 本人负责客户端采集 SDK、上报队列与事件契约的完整落地；服务端 ClickHouse 存储、Kafka 削峰、聚合计算与前端大盘由大数据/后端团队搭建，不作跨界归功；
  - `sendBeacon` 极端容灾、基于 IndexedDB 的离线续传及远程动态采样属于探索设计，未作为已上线事实；
  - 不捏造未经留档的吞吐 TPS 或降故障百分比数据。

### 项目 6：代码仓库 Agent Harness 与开源 Evidence 平台

#### 1. 公司项目研发提效：代码仓库 Agent Harness 实践

- **实践场景**：上海鼎歆内部代码研发提效。
- **前馈控制（Plan 阶段）**：针对长篇复杂 PRD，拒绝直接无脑丢给 LLM 生成。先由人工工程师将其解析并建模为高内聚的业务模型，再审核测试工序生成的具体任务清单（Tasking List），将两者作为高度聚焦的前馈上下文输入给 Agent。
- **反馈控制（Act 阶段）**：当单元测试或构建报错时，针对过长的测试与堆栈报告，指导模型即时生成提取脚本，由脚本进行确定性的信息压缩与关键行截取，保留精简的问题定位上下文供 Agent 修复。
- **实践效果**：有效抑制了模型的幻觉与漂移，显著减少了反复重传冗长文档带来的 Token 消耗，使单任务生成的一次通过率与稳定性得到定性提升（仅记录定性观察，不浮夸声称未经计量的效率倍数）。

#### 2. 开源 Evidence 交付系统：项目级与 Agent 级双层循环

- **项目定位**：个人主导设计并实现的领域建模与证据映射开源交付系统（覆盖 React Web、Java Server、Electron Desktop 与内嵌 Pi SDK）。
- **权威状态机与人机权责对等**：
  - **外层循环（Server 权威）**：通过精确的 Inbox Revision 固化输入，经历人工 Kickoff、Scenario 确认与 Desk Check，生成不可变 Story Revision 与 Approved Tasking Plan；人类掌握准入准出权与价值判断，Agent 仅扮演受限的提案（Proposal）提供者。
  - **内层循环（Pair 协作）**：以批准的任务清单驱动，编排短生命周期的 Test、Production、Refactor 三类 Pi Driver；绑定严格互斥的 Red/Green 命令与独立 Red Reviewer 门禁；只有完整 Diff Hash 通过核验且经人工批准后，才在本地生成 Conventional Commit。
  - **确定性失败路由**：对意外全绿（Unexpected Green）、伪红（Pseudo Red）、门禁失败与文件路径越界进行状态机强管控，仅允许有限且明确的恢复分支（如 `back_test`、`back_tasking`），杜绝 Agent 无限重试或私自篡改测试。
- **当前边界**：
  - 机制已在开源仓库完整落地，不等于已在大型生产集群规模化运行；
  - 严格保持客观事实，最新提交（b4b9ace）中 Desktop 37 个测试文件（143 项用例）及 Java 服务端编译均通过，但 CI 流水线因单一 Web UI 测试未全绿，不夸大宣传为“全绿通过”。
