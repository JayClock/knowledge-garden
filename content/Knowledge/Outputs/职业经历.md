## 二、核心工程能力框架

### 1. 复杂前端与编辑器架构

深度掌握现代富交互前端底座的设计与性能优化：

- **画布与图形**：基于原生 Canvas 与 React Flow 实现高响应度画布，覆盖缩放平移、视口变换、单选/多选/框选、节点拖拽挂载、Auto Layout 容器与吸附对齐。
- **变量编辑**：在低代码工作流引擎中使用 Tiptap 将变量引用渲染为不可拆分的标签，支持上游输出选择与执行协议序列化。
- **工程韧性**：系统性处理树形状态、浮动上下文菜单与弱网环境下的异常恢复。

### 2. 上游契约与领域建模

不把前端视作被动的 API 消费者，而是主动参与上游业务建模：

- 使用 **8X Flow** 与**四色建模法**澄清业务参与方、权责关系、关键事件与生命周期。
- 将业务模型映射为 RESTful 聚合边界、URI 体系、HATEOAS relation 状态机与 HAL-FORMS 动作契约，从根源上降低端侧维护业务状态分支的复杂度。

### 3. 关联对象建模方法

设计并落地**关联对象建模方法**：

- 将传统实体间的一对多或复杂多对多关联显式抽象并建模为独立的领域对象。
- 建立稳定的接口契约以彻底隔离领域语义与底层数据访问策略，在严守聚合根边界的同时，有效防止非聚合根 Repository 的持久化逻辑泄漏，并从架构层面规避 N+1 查询风险（通用建模思想，不绑定具体技术栈，并在开源代码中完成可验证落地）。

### 4. 渐进式架构与可恢复增强

坚持**渐进式增强（Progressive Architecture）**：

- 优先稳定核心业务模型、任务路径与通信协议基石；
- 将 HATEOAS relation/action、多框架适配、节点插件及 AI Proposal 等高变化能力隔离为可插拔、可退化演进的增强层；
- 配合运行时 Schema 校验、降级退路、状态版本控制与人工确认 Gate，严格限定局部失效的爆炸半径。

### 5. 契约消费路径与验证闭环

- **消费层建设**：提供面向下游的 React 适配 Hooks、强类型 TypeScript SDK、HAL/HAL-FORMS 规范解析器及 OpenAPI 契约草稿，抹平成本。
- **全链路验证**：串联单元测试、契约测试、E2E 测试、人工评审、运行日志追踪与前端全量监控，形成“需求建模 → 契约制定 → 实现消费 → 运行反馈 → 模型修正”的完整工程闭环。

### 6. AI 确定性交付与受控候选生成

深刻理解 LLM 的能力边界：将适合模型发挥的自然语言理解、候选方案（Proposal）生成，与必须由 DSL、Schema、版本控制和质量门禁保证的确定性执行严格解耦（如领域建模平台中 AI 仅生成结构化 Proposal 供人工逐项采纳，Figma AI 中多智能体生成 Fragment 须受 DSL、revision 与 Visual Harness 局部校验严格约束）。

### 项目 2：[[项目介绍：AI 辅助领域建模平台|AI 辅助领域建模平台]]（上海鼎歆）

- **项目性质**：公司级内部业务与研发平台（全栈独立主导并实现核心链路）
- **核心定位**：以 Evidence 建模方法论为基础，将参与方、角色、权责、事件、领域对象、关系及履约凭证等业务分析结果，落地并记录为可维护、可审核、可发布的结构化领域模型，作为前后端团队共同消费的业务语义契约。

#### 架构设计与技术实现

1. **方法论结果的结构化表达与记录**：
   - 将 Evidence 与 8X Flow 建模方法中的参与方、角色、权责、事件、领域实体、关联对象与履约凭证，显式映射为平台可维护的节点、连线关系与业务属性，基于 React Flow 提供可视化建模与模型记录能力；
   - 将原本分散在会议白板与口头讨论中的业务理解沉淀为可长期维护的结构化数字资产，通过草稿、版本快照与正式发布机制管理模型演进，支撑业务、产品、前端与后端围绕同一份模型展开讨论和审核。
2. **AI Proposal 与人工审核发布**：
   - 将 AI 输出组织为受元模型 Schema 严格约束的节点和关系 Proposal，提供对象高亮定位、可视化预览及逐项采纳／拒绝交互；
   - 经用户确认的提案进入模型草稿，再通过人工审核与版本发布形成正式模型，将候选生成与业务语义审核分层处理。
3. **MCP 本地同步与下游契约消费**：
   - 服务端按固定修订批量读取多表模型定义，确定性组装为包含模型元信息、实体及属性与引用、关系、规则及 bindings 的 FM JSON 对象分片快照；
   - 通过 MCP 导出工具返回包含修订、Schema 版本、文件路径、摘要与资源 URI 的快照清单，本地 MCP Client 通过 `resources/read` 获取同一快照的文件内容；
   - 本地同步程序下载至独立候选目录，校验文件摘要以及完整模型的 Schema、引用和 CEL 表达式，对照上次同步清单检查差异与本地修改；
   - 校验通过并获授权后，在读写锁下重查本地修改并更新模型文件与同步记录，删除仅作用于清单托管文件；下载校验失败或检测到本地修改冲突时保留当前有效模型；
   - 将建模产生的参与方、权责、事件和领域实体沉淀为正式业务契约，向下游导出 RESTful API 候选设计、OpenAPI 3.0 草稿以及正常／异常测试数据候选；
   - 在真实库销存（WMS/ERP）Agent 场景中，运用 8X Flow 从采购合同出发，完整建模参与方、发货/收货/退货履约权责及异常 Evidence，跑通业务分析、模型记录到接口契约消费的完整路径。

#### 交付与应用情况

- **内部持续使用**：平台在内部被业务、产品及研发团队持续使用，有效打通了业务需求到接口定义的沟通链路，成为记录业务认知和沉淀语义契约的核心载体。
- **全链路闭环交付**：完整打通了从方法论结果记录、可视化建模、AI 提案人工确认到模型审核发布、MCP 本地同步与下游契约消费的闭环。
- **质量与闭环验证**：单元测试、契约测试与基础 E2E 覆盖主流程；在企业库销存（WMS/ERP）等真实业务场景中完整跑通了采购合同履约建模与接口契约导出。

### 项目 3：[[项目介绍：HATEOAS 资源契约架构|HATEOAS TypeScript SDK 与资源动作契约消费层]]（上海易校）

- **项目性质**：大型低代码平台基础架构（企业 Monorepo 业务落地，后抽离为通用开源 npm 包）
- **核心定位**：彻底解决 PC Web、移动 Web 等多端应用中重复实现业务权限、状态机分支和操作按钮可用性判断的问题，实现“以服务端资源状态驱动多端一致行为”。

#### 架构设计与技术实现

1. **自研强类型客户端 SDK 体系**：
   - 从 0 到 1 架构并开发 `@hateoas-ts/resource` 与 `@hateoas-ts/resource-react`（基于 Nx / pnpm Monorepo 统一治理与发布，目前稳定版本 1.4.3）；
   - 封装 `Client`、`Resource`、`ResourceRelation`、`State`、`Action`、`StateFactory` 与 `CacheManager` 核心抽象；
   - 客户端通过 `follow()` 链式导航资源关系，通过 `action()` 消费 HAL-FORMS 动作模板，将传统前端分散的 API 请求升格为状态机驱动。
2. **精准缓存与并发去重**：
   - 实现飞行请求（in-flight request）合并去重；
   - 建立基于 URI 匹配、`invalidates` 声明、HTTP `Location` 和 `Content-Location` 的联动缓存失效机制，兼顾实时性与网络开销。
3. **React 深度适配与声明式消费**：
   - 提供 `ResourceProvider`、`useResource` 等 React Hooks，原生支持 React Suspense、错误边界以及基于 HAL `next` 关系的无限流式分页。
4. **渐进式演进与多端落地**：
   - 以低代码平台“工作区全局导航”为试点，在不重构底层数据表的前提下，于 API 表达层增加 `_links` 与 `_templates`，多端直接读取契约渲染菜单与操作项；
   - 架构上保留传统 BFF 作为回退路径，保证低风险平滑迁移。

#### 交付与应用情况

- **业务平滑升级**：支撑了上海易校大型低代码平台在多端一致性上的架构升级，以工作区全局导航等核心模块为试点稳定运行。
- **开源工程交付**：自研客户端 SDK 抽象并公开发布至 npm（`@hateoas-ts/resource` 与 `@hateoas-ts/resource-react`，当前稳定版本 1.4.3），包含 34 个测试套件、233 项自动化测试且全部通过，构建与发布流程完备。
- **前后端协同落地**：由本人主导领域模型、动作契约设计与完整客户端 SDK 研发，并与后端团队协同制定并落地服务端 API 表达层契约。

### 项目 4：[[项目介绍：企业级低代码工作流引擎|企业级低代码工作流引擎与复杂编排器]]（上海易校）

- **项目性质**：核心商业化平台基础设施（核心负责协议、执行引擎与复杂编辑器）
- **核心定位**：打造企业级低代码工作流调度引擎与可视化编排界面，支持内部员工、企业客户及研发人员编排复杂业务流与 AI 节点。

#### 架构设计与技术实现

1. **基于 Kahn 算法的执行调度内核**：
   - 独立实现 TypeScript 执行引擎：构建 `WorkflowEngine`、`GraphBuilder` 与 `ExecutionContext`；
   - 使用邻接表、反向邻接表与入度统计，基于标准 Kahn 拓扑排序算法实现高效的有向无环图（DAG）调度，并在初始化阶段进行死循环环路检测。
2. **条件分支动态剪枝算法**：
   - 设计 Condition 节点分支判定逻辑：执行期沿未命中分支向下递归遍历并排除死分支节点；
   - 引入下游汇合点入度保护机制，在剪枝过程中校验节点是否具有其他活跃入边，避免误伤公共汇合节点。
3. **微内核节点插件体系**：
   - 抽象 `NodeRegistry` 与 `BaseNodeExecutor` 标准接口，将节点输入校验、变量计算、耗时统计、错误隔离与上下文输出全面标准化，便于团队快速扩展自建节点与第三方 API 节点。
4. **Tiptap 结构化变量编辑器**：
   - 解决工作流参数引用的可读性与健壮性难题：基于 Tiptap 富文本开发专用变量节点，将 `${nodeId.variableName}` 渲染为不可拆分的结构化 Token 胶囊；
   - 支持通过 Slash (`/`) 菜单快速检索并插入上游可用变量，保存时自动序列化为规范协议，执行期递归解析嵌套变量。
5. **公式编辑器与 AST 求值链路**：
   - **公式编辑交互**：面向表单字段参与工作流计算的业务场景，实现字段与函数表达式的编辑交互，支持用户配置 `sum(金额1，金额2)` 等业务计算公式；
   - **自研解析与保存校验**：自行编写公式解析器，将表达式解析为抽象语法树（AST），并在保存时执行语法校验以拦截非法或错误公式；AST 中以稳定字段 ID 记录字段引用，将界面呈现的字段名称与底层引用标识解耦；
   - **运行时字段解析与求值**：在工作流节点执行阶段，通过全局变量按字段 ID 读取对应字段的完整信息，基于 AST 完成公式求值，实现从公式编辑、保存校验到运行时节点计算的完整闭环；编辑交互、解析校验与求值链路均由本人独立负责。
6. **执行反馈与可观测性打通**：
   - 集成前端监控 SDK，为工作流校验、测试运行和发布添加自定义事件，通过 `executionId` 关联前端操作与执行引擎日志；在代表性重实现中，将 Trace 面板由画布坐标排序优化为基于 Edge 的拓扑排序，使日志展示顺序与节点依赖保持一致；
   - 对接服务端 SSE 事件流与发布管理接口，提供测试运行、节点状态与错误日志的高保真执行反馈。

#### 交付与应用情况

- **核心链路闭环**：完整打通了从工作流协议、节点 Schema、画布交互、变量绑定、公式编辑与 AST 求值、图校验、拓扑调度到状态监控的完整业务链条。
- **全栈协议协同**：独立负责执行引擎、公式解析求值与端侧交互实现，并与后端协同完成 API 接口规范与实时执行反馈对接。
- **端到端可观测性打通**：通过前端监控 SDK 与执行日志的 `executionId` 关联机制，使画布编排与节点执行具备高可追溯性。

### 项目 5：[[项目介绍：前端埋点与监控 SDK|企业级前端全量监控 SDK（数据采集与上报侧）]]（上海易校）

- **项目性质**：平台公共基础设施（独立架构设计与核心代码实现）
- **核心定位**：服务于低代码平台全业务线的前端可观测性 SDK，以“下游故障定位与业务验收需要回答什么问题”反推事件设计，提供统一规范的事件协议。

#### 架构设计与技术实现

1. **下游驱动（Downstream-Driven）与多包工程**：
   - 告别盲目采集，紧密围绕网络排障、页面慢加载、JS 运行时崩溃与业务操作链路设计监控上下文模型；
   - 使用 pnpm 构建 Monorepo：细分为 `core`（通用调度协议、插件生命周期、内存队列）、`browser`（浏览器 API 封装）、`react` / `vue`（框架组件与生命周期集成）及 `types`。
2. **全面精准的数据采集**：
   - **性能指标**：基于 `PerformanceObserver` 接入 Google Web Vitals 标准，精准采集 FCP、LCP、CLS、TTFB 与 INP 指标；
   - **错误异常**：全面监听 `window.onerror`、`unhandledrejection` 以及资源加载错误；
   - **用户行为追踪**：透明劫持/包装 DOM 事件、原生 `Fetch` 与 `XMLHttpRequest`，在完全不侵入业务行为和返回值的原则下记录完整上下文。
3. **批量队列与弱网弹性上报**：
   - 事件先进入本地内存缓冲区，按设定的时间步长（Interval）、批次阈值或路由跳转动作批量触发上报；
   - 结合失败指数退避重试与弱网处理，兼顾端侧性能损耗、网络开销与上报可靠性。
4. **生产 Sourcemap 还原闭环**：
   - 协同打通 CI 产物构建与 Sourcemap 版本上传管线，使得监控后台能利用映射表将线上压缩堆栈精准反解为源码行列号。

#### 交付与应用情况

- **多技术栈全量接入**：监控 SDK 全面接入低代码平台所有前端模块（覆盖 Vanilla JS、React 和 Vue 多种技术栈），低代码工作流引擎是其典型的生产接入范例。
- **端侧链路闭环**：独立完成客户端采集 SDK、上报队列、重试机制与事件契约的落地，并打通 CI 产物与 Sourcemap 映射链路。
- **跨团队数据对接**：与大数据及后端团队协同制定事件上报协议，支持底层数据写入与可视化监控大盘。
