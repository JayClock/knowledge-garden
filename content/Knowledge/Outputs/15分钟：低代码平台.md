## 30 秒开场

这个项目不只是让用户在 React Flow 上连线，而是要把画布定义可靠地转成可校验、可执行、可追踪的工作流。我负责统一协议、TypeScript 执行引擎、插件化节点、React Flow 编辑器、Tiptap 变量编辑器和 PostgreSQL / Prisma 数据层；还接入监控 SDK，通过 `executionId` 把校验、测试运行和发布路径与节点执行日志关联起来。

## 2 分钟项目介绍

我负责工作流协议、React Flow 编辑器、Tiptap 变量编辑器、TypeScript 执行引擎，以及 PostgreSQL / Prisma 数据模型与持久化。项目先用 `WorkflowDefinition`、Node、Edge、节点 Schema 和变量协议统一编辑器与执行器，避免画布和运行时各维护一套结构。

运行前，验证器检查 Start、End、节点类型、配置和边引用；GraphBuilder 再建立邻接表、反向邻接表和入度表，通过环检测与 Kahn 算法生成拓扑顺序。Condition 节点命中分支后排除未选路径，但遇到公共下游时会检查其他活跃入边，避免误删仍应执行的节点。

跨节点数据由独立的 `ExecutionContext` 保存。`${nodeId.variableName}` 会被递归解析，前端则用 Tiptap 把变量显示成不可拆分标签。节点扩展采用 `NodeRegistry + NodeExecutor`，新增节点不需要修改核心调度器。

为了让验收和运行诊断能够判断用户在哪个环节失败，我还接入监控 SDK，为工作流校验、测试运行和发布添加自定义事件；节点状态、耗时和错误仍由执行引擎日志负责，两侧通过 `executionId` 关联。NestJS API 与 SSE 事件推送由后端同事实现，我负责共同协议和前端接入。当前不补写使用规模、下游使用方式或量化收益。

## 5 分钟主讲法

### 1. 先统一编辑和执行协议

工作流最容易出现的问题，是画布存一套结构，执行器再维护另一套结构。我把两边统一到 `WorkflowDefinition`、Node、Edge、节点 Schema 和变量协议。Node 保存类型与配置，Edge 表达数据流和条件分支，Schema 同时约束配置表单和执行器输入。

编辑器只负责生成合法定义，执行器负责运行；选中节点、画布坐标和拖拽草稿不会污染运行时。

### 2. 图结构必须在执行前验证

用户可以任意连线，所以不能只靠前端交互限制。验证器先检查 Start、End、节点类型、配置和边引用，再由 GraphBuilder 建立邻接表、反向邻接表和入度表。普通主图保持 DAG，环路会在进入执行前被拦截；合法图再通过标准 Kahn 算法获得拓扑顺序。

Kahn 是标准排序算法。我的工作是把校验、构图、动态分支和执行器调度完整接进运行时。

### 3. 条件分支不能简单删除下游

Condition 通过 `sourceHandle` 返回命中分支。未选分支会进入排除集合，但两个分支可能在后面汇合到同一个节点。递归排除前必须检查这个节点是否还有其他未排除的前驱；只要存在活跃入边，公共下游就要保留。

原文稿将这部分定义为动态调整执行队列：分支命中后重新计算可执行顺序，使未选路径不再执行，同时保留仍然应该运行的汇合节点。内部重实现不要求完整镜像这条公司项目链路。

### 4. 变量协议连接编辑器和运行时

每次执行创建独立 `ExecutionContext`，按 nodeId 保存输出和完成状态。节点运行前，`VariableResolver` 解析配置里的 `${nodeId.variableName}`，并递归处理字符串、数组和对象。找不到变量时保留原表达式，而不是静默替换成空字符串；当前没有独立证据支持进一步声称已经完成发布期变量存在性校验。

用户不需要手写这段字符串。Tiptap 把变量渲染成原子标签，通过 `/` 菜单列出上游输出；保存和回显时在标签与纯文本协议之间转换。展示名称可以修改，运行时仍依赖稳定 nodeId。

### 5. 节点扩展保持核心稳定

如果每增加一种节点都修改调度器，系统很快会堆满 `switch-case`。我把节点逻辑拆到 `NodeExecutor`，由 `NodeRegistry` 按类型查找。基础执行流程统一处理变量解析、配置校验、错误捕获、耗时和输出存储，具体节点只实现自己的行为。

新增节点时，需要增加配置类型与 Schema、执行器、验证器、前端节点和设置表单，再注册到对应注册表。核心图调度不需要跟着改变。

### 6. 从验收需求倒推反馈证据

下游验收不只需要看到编辑器功能完成，还要知道用户在校验、测试运行还是发布环节失败。因此我接入监控 SDK，为这三个关键路径添加业务自定义事件。TypeScript 引擎继续产生节点开始、结束、失败、耗时和日志事件，前端测试运行面板根据共同确认的 SSE 协议展示状态；两类证据通过 `executionId` 关联。

这里没有让浏览器埋点替代执行事实：前端 SDK 负责用户路径和关键结果，执行引擎日志负责节点状态、耗时和错误。NestJS API、认证和 SSE 事件推送由后端同事实现，我负责共同协议与前端接入。

当前完成的是协议、React Flow 编排、Tiptap 变量、图校验、拓扑调度、条件分支、插件化节点、PostgreSQL / Prisma 持久化、执行反馈，以及校验—测试—发布路径与节点日志的关联。内部重实现的开发 Bug 不等于公司生产事故；并发上限、节点幂等、服务恢复和 Loop 容器仍是后续方向。
