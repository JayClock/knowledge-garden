# 技术专题：公式编辑器

## 30 秒开场

通用公式编辑器要同时解决表达能力、输入体验和执行安全。设计上可以把公式解析成 AST，由白名单解释器执行，避免把用户输入直接交给 `eval`；编辑层再用 Tiptap 把字段引用做成原子标签，并提供语法提示。解析、执行和交互共用同一公式协议，错误才能在输入阶段定位。

## 2 分钟技术方案

如果低代码平台要让非研发人员配置计算、条件和跨字段校验，普通 textarea 很快会遇到两个问题：用户只能盲写字符串，错误要到运行时才暴露；直接使用 `eval` 或 `new Function` 又会把用户输入带进 JavaScript 全局执行环境。

一个更可控的方案是先定义公式语法，再经过 Lexer 和 Parser 生成 AST。解释器只处理允许的节点类型、操作符和白名单函数，变量从显式上下文读取，不能访问 `window`、`document`、`Function` 或原型链。这样安全边界由语法和解释器决定，而不是依赖关键词黑名单。

编辑层可以使用 Tiptap。字段引用做成不可拆分的原子节点，界面显示字段名称，持久化保存稳定字段 ID。输入函数、括号或变量时，根据当前 Token 与光标位置提供候选项；解析错误返回位置、期望 Token 和错误码，编辑器再映射成高亮与提示。

前后端如果都要执行公式，应该共享 AST Schema、函数语义和版本，不必共享同一种编程语言实现。异步跨表查询也不要伪装成普通同步函数，需要显式的异步节点、超时、批量和缓存策略。

验证重点包括解析正确性、执行白名单、深层嵌套、空值、除零、类型转换和原子节点交互，作为系统设计的重点考量。

## 5 分钟主讲法

### 1. 先确定公式能力的边界

公式编辑器面对的是受控业务规则，不是开放式 JavaScript。第一步要列出允许的字面量、变量、操作符、函数和条件表达式，再明确空值、类型转换、日期和数组的语义。

语法范围越大，测试和安全成本越高。跨表查询、远程调用和循环应当单独评估，不能默认塞进第一版表达式语言。

### 2. 解析和执行分开

Lexer 把字符串拆成变量、数字、操作符、函数和括号等 Token；Parser 再根据语法生成 AST。解析阶段可以提前发现括号不匹配、非法操作符和参数数量问题，并返回准确位置。

执行阶段遍历 AST，只允许访问显式传入的只读上下文和函数表。解释器为每种节点定义行为，不把原始字符串交给 JS 引擎。黑名单很难覆盖所有逃逸路径，白名单语法与节点解释更容易审计。

### 3. 资源和安全限制

受控解释器仍然需要限制最大 AST 深度、节点数量、字符串长度、函数调用次数和执行时间，避免恶意嵌套造成栈溢出或 CPU 消耗。递归执行可以改成显式栈，超出预算直接返回结构化错误。

函数注册表还要区分纯函数与有副作用函数。修改全局状态、访问网络或读取未授权字段的函数不能随意注册。

### 4. 编辑体验和持久化协议

普通 textarea 只能保存字符串，字段改名、部分删除和输入提示都很难控制。Tiptap 可以把字段引用建成原子 Node：界面显示“审批金额”，底层保存稳定 fieldId，用户只能整体选择和删除。

持久化时可以保存规范化公式文本或 AST，但需要版本字段。保存文本更容易查看和迁移，保存 AST 可以减少重复解析；无论选哪一种，编辑器、验证器和执行器必须遵守同一 Schema。

### 5. 语法提示和错误反馈

候选项需要结合当前 Token、光标位置、可用字段和函数签名。提示层通过 Tiptap selection 获取坐标，并处理滚动容器、弹窗和缩放。解析器返回的错误要包含位置、错误码和期望内容，让 UI 能定位到具体片段，而不是只弹一个“公式错误”。

原子节点还要覆盖退格、方向键、复制粘贴和 undo／redo，避免字段标签被删掉一半。

### 6. 异步与前后端复用

如果以后支持远程函数，AST 求值会变成异步。此时需要显式 Promise 传播、超时、取消、批量和缓存，不能把同步解释器简单改成到处 `await`。同一行公式中重复查询还可能产生 N+1，需要先收集依赖再批量执行。

前后端复用的重点是 AST Schema、函数名称、参数和语义一致。两端各自实现解释器时，还要通过共享用例验证相同输入得到相同结果。

### 7. 怎样验证设计

解析层测试合法和非法语法，执行层测试白名单、边界值、空值和类型转换，安全层测试深层嵌套与危险对象，编辑器测试原子节点、粘贴和撤销。属性测试或模糊测试可以补充人工没有想到的组合。

可用性、错误率和研发介入次数都需要真实记录。没有工程实现和测试结果之前，这些只能作为验证方案，不能写成项目成果。

## 深挖方向

- AST 怎样处理深层嵌套和执行预算。
- 异步函数怎样做批量、缓存、超时和取消。
- Tiptap 原子节点怎样处理光标、删除和粘贴。
- 提示层怎样跟随 selection 坐标。
- 前后端怎样共享 AST Schema 与函数语义。

## 收尾句

公式编辑器的设计重点，是把业务规则变成受控语法，再由解析器、解释器和编辑器共同消费。核心链路（自研 AST 解析、字段 ID 绑定、保存拦截与节点执行期求值）已在低代码工作流中落地，异步与复杂沙箱则作为演进设计储备。
