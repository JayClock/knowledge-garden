# 简历回答逐字稿：低代码变量编辑器与数据总线

关联：[[职业经历]]、[[全栈工程师简历]]、[[简历追问：低代码变量编辑器与数据总线]]、[[15分钟：公式编辑器]]。

> [!warning] 回答边界
>
> - 已确认的是 Tiptap 变量标签、`/` 菜单、`${nodeId.variableName}` 协议、纯文本序列化和 `VariableResolver + ExecutionContext`。
> - Lexer、Parser、AST、异步公式函数和 DataLoader 没有进入当前职业主档，不能说成已经完成。
> - NestJS 与 SSE 服务端由后端同事实现；这里讲的是前端编辑体验和相关 TypeScript 执行协议。

## 30 秒开场

变量编辑器解决的是工作流里的跨节点参数传递。直接手写 `${nodeId.variableName}` 容易输错节点 ID 和字段名，所以我基于 Tiptap 把变量显示成不可拆分的标签，并通过 `/` 菜单选择上游节点输出。

保存时把富文本还原成 `${nodeId.variableName}` 纯文本协议；运行时再由 `VariableResolver` 从 `ExecutionContext` 中按节点和变量名取值。这样编辑器体验和执行引擎消费的是同一份变量协议。

## 如果面试官问：为什么不用普通 textarea？

我会说 textarea 做起来快，但它只能存字符串，无法保证变量引用的结构稳定。

比如用户引用上游节点 A 的 `customerId`。Tiptap 中显示节点名称和变量名，保存时仍落成稳定的 `${nodeId.variableName}`。节点展示名可以变化，但执行协议依赖的是 nodeId，而不是展示文字。

另外，原子节点可以控制用户不能把变量删一半、改一半，这对低代码配置很重要。否则表面看是公式，实际运行时已经变成不可解析字符串。

## 如果面试官追：原子化胶囊怎么防止被破坏？

我会说主要靠 ProseMirror NodeSpec 和交互拦截。

项目通过自定义 `variableMention` 原子节点避免变量被拆开编辑。用户选择变量后插入完整标签，保存时再序列化为 `${nodeId.variableName}`。更细的跨文档粘贴和失效降级策略没有进入当前主档，不作为已完成能力展开。

## 如果面试官追：`${}` 和 `/` 菜单怎么实现？

我会这样回答：

输入 `/` 时触发 Tiptap Suggestion，展示上游节点可用的变量。用户选择后插入 `variableMention`，编辑器负责高亮显示；保存与回显时在 Tiptap 节点和 `${nodeId.variableName}` 纯文本之间转换。

弹层坐标、Portal 和 floating-ui 等实现细节没有进入当前确认范围，面试时不主动补充。

## 如果面试官追：为什么不用 `eval`？

我会说这个项目当前确认的变量协议不是通用公式语言，而是 `${nodeId.variableName}` 引用。运行时由 `VariableResolver` 解析并从受控的 `ExecutionContext` 取值，不需要执行任意 JavaScript，因此也不使用 `eval` 或 `new Function`。

Lexer、Parser、AST 和白名单函数可以作为未来扩展通用公式能力时的方案，但不能说成当前项目已经实现。

## 如果面试官追：跨节点数据总线怎么保证不串？

我会说每次流程执行都有一个 ExecutionContext，按 `nodeId` 隔离存储节点输出：

```ts
context.outputs[nodeId] = {
  status: 'SUCCESS',
  data: {...}
}
```

下游节点执行前，变量解析器读取配置中的 `${nodeId.variableName}`，按 nodeId 和变量名从 context 取值。每个节点输出存放在自己的 nodeId 下，避免不同节点的结果相互覆盖。

对于未命中分支的变量，最好在发布校验或运行时明确报错，不能默默解析成空字符串。否则问题很难排查。

## 如果面试官追：异步函数怎么办？

我会先说明当前变量协议只读取已经进入 `ExecutionContext` 的上游输出，没有实现 `GET_USER_INFO(id)` 这类异步公式函数。

如果未来扩展，需要单独设计异步求值、批量、缓存和超时，但这属于架构方向，不是当前交付事实。

## 收尾句

所以这块不是让用户直接手写易错字符串，而是让 Tiptap 负责可视化引用，让纯文本协议负责存储与传输，再由 `VariableResolver + ExecutionContext` 负责运行时取值。通用公式解析不在当前确认范围内。
