### HATEOAS 资源契约架构

项目简介

此项目聚焦企业级 SaaS 中复杂状态机、多角色、多端协作下的规则漂移问题，目标不是做一层请求封装，而是将散落在 Web、小程序、App 前端中的 `status / role / permission` 判断收敛为后端返回的资源动作契约，让前端从“解释业务规则”转向“消费当前资源状态下的合法动作”。

工作内容与成果

- **资源动作契约消费层设计**：主导前端 HATEOAS 消费层，将当前资源可执行的动作通过 `_links` / `_templates` 与资源状态一起返回，前端基于 relation 与 action 消费契约，降低状态机规则在多端重复实现带来的联动改动与测试回归成本。
- **TypeScript SDK 与类型安全约束**：设计基于 relation 图谱遍历的 TypeScript 客户端 SDK，封装 `follow()` 与 `action()` 等能力，并结合泛型约束与运行时校验，尽量让 relation、action 与 payload 在开发期可提示、运行期可被 zod 统一验证。
- **兜底状态与错误标准化处理**：围绕资源加载失败、动作缺失、契约缺失、链式导航中断等场景，区分资源不可用、动作不可执行、网络错误与鉴权失败等状态，为 UI 层提供一致的禁用、隐藏、重试与错误反馈策略。
- **Agent 友好与权责对等**： 动态注册 Agent 可调用工具，意图识别不会超出当前用户权限。基于 template 构建 self-Heal Loop 的 Payload 参数生成，避免出现 HTTP 400 参数错误。

### 低代码工作流引擎

项目简介

设计并开发内部工作流引擎，在支撑传统业务工作流之上支持 AI Agent 工作流扩展，解决内部低成本落地大模型应用的难题。

工作内容与成果

-  **引擎架构设计**：自主设计并实现了基于 **DAG (有向无环图)** 的业务工作流执行引擎，利用 **Kahn 算法** 实现节点拓扑排序与循环检测，支持复杂审批流与自动化业务逻辑编排。
- **核心模块开发**：设计了基于 **注册模式**和**策略模式**的节点/组件扩展系统，实现了 Start、Form（动态表单）、HTTP、Condition 等核心节点的执行器，遵循开闭原则，方便后续业务组件库的低成本扩充。
- **变量编辑器与数据总线构建**：基于 **Tiptap/ProseMirror** 自研了低代码动态变量编辑器，支持通过 `/` 或 `${}` 快捷唤起全局/上游节点变量菜单；设计了自研的表达式引擎，在运行时精准解析节点间的依赖引用，实现复杂业务场景下的跨节点参数传递与上下文状态管理。
- **高性能状态同步**：在 NestJS 中实现了 **SSE (Server-Sent Events) / WebSocket** 实时通信机制，支持长耗时业务节点（如批量数据处理、跨系统接口调用）的执行状态实时监控与日志流式推送，优化了开发者的调试体验。
- **工程化治理**：采用 **Monorepo** 架构集中管理前后端代码，通过 Docker 多阶段构建优化容器镜像体积，实现了从开发到生产环境的全链路 CI/CD 自动化部署。

### 全链路埋点与监控 SDK

项目简介

此埋点 SDK 面向轻流平台的前端数据采集与异常观测场景，目标不是做大而全的数据平台，而是沉淀一套低侵入、高可靠、可降级的前端 SDK，让业务事件、曝光事件、接口异常与公共上下文能够稳定回流到产品、研发、测试与运营反馈链路中。

工作内容与成果

- **SDK 架构与插件化设计**：设计并实现了基于“核心包 + 适配包”的监控 SDK 架构，通过插件化机制支持多前端框架（React、Vue、Vanilla JS）无缝集成，并支持业务方高度自定义监控项与功能扩展。
- **核心性能与异常采集**：构建了全方位的性能与异常数据采集方案，利用底层 API 结合全局事件拦截，全面覆盖 FCP、LCP、CLS 等核心 Web Vitals 性能指标以及复杂的 JavaScript 运行期异常。
- **SaaS 平台搭建与大盘可视化**：利用 React 与 shadcn/ui 搭建了现代化的高颜值 SaaS 监控控制台，结合底层 ClickHouse 列式存储的查询优势，实现了海量监控数据的多维度可视化展示与实时大盘监控，为业务决策提供了精准的数据支撑。

### Evidence｜领域建模、证据映射与 AI 辅助交付平台

个人项目（2026.05 ~ 至今）｜[GitHub](https://github.com/JayClock/Evidence)

项目简介

面向领域专家与业务分析师，独立设计并实现从来源收集、逻辑建模到 AI 辅助交付的全栈平台；以 `.evidence` YAML 沉淀 Evidence、Participant、Role、Context 等模型资产，以 Web / Server / Desktop 三个运行时提供关系图评审、工作空间协作和受控本地 Agent 能力。

工作内容与成果

- **领域模型与可视化投影**：将 LogicalEntity / LogicalRelationship 与 Diagram 投影分离，避免图状态与领域模型形成两套事实源；基于 React Flow / ELK 实现语义 Canvas 与自动布局，并通过 `.evidence/entities`、`.evidence/associations` 可读 YAML 支持模型审查和持续演进。
- **模块化全栈与契约架构**：基于 Nx / pnpm 构建 TypeScript Monorepo，React / Vite 前端同时服务 Browser 与 Electron renderer；NestJS Server 按 API、无框架 Domain、Persistence 分层，使用 Prisma / PostgreSQL 保存协作与交付状态，并以 HAL / OpenAPI 生成客户端、驱动黑盒契约测试。
- **可审计的人机协作交付流**：将 Inbox → Kickoff → Understand / TQA → Tasking / Desk Check → Pair 建模为显式状态机，以不可变来源 Revision、SHA-256、Frozen Intake、append-only 决策和乐观版本锁定防止需求漂移；Agent 只负责提案与受限执行，Story、Scenario、计划与编码结果均保留人工权威。
- **安全 Desktop 与本地 Agent 执行**：Electron 采用隔离 main / preload、受保护 renderer 协议与定向凭据注入，内嵌 Pi SDK 并按角色限制工具；每轮交付使用独立 Git worktree 和锁定质量命令，完整源码、diff、Prompt 与凭据保留在本地，仅人工验收后创建 commit，不自动 merge / push，并通过临时 PostgreSQL、Fake Provider 与打包 E2E 验证边界。
