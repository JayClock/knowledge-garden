## 核心项目

### 多人实时协同的 AI 辅助领域建模平台｜上海鼎歆信息科技有限公司

面向业务、产品和研发持续使用的内部建模场景，独立负责可视化建模、多人实时协同、AI 结构化提议及模型发布链路。公开重实现：[team-ai](https://github.com/JayClock/team-ai)（非公司原始源码）。

- **业务建模与收敛**：针对团队事件风暴和头脑风暴易发散、难收敛的问题，使用 8X Flow 从参与方权责关系出发约束讨论边界，并将结果沉淀为业务模型、接口候选和测试场景。
- **协同架构**：以 Yjs 作为共享状态源，通过 WebsocketProvider 和 Awareness 同步模型增量与在线状态；按工作负载拆分普通业务 API 与 NestJS WebSocket 协同服务，并通过 PostgreSQL 适配层持久化共享模型。
- **状态治理与验证**：通过链路日志与 `transaction.origin` 定位 React Flow 与 Yjs 双向绑定回环，移除整图全量回写，改为节点、关系和字段级增量同步；使用双浏览器联调确认一次本地操作只产生一次 Yjs transaction，远端更新不再回写。
- **AI 与模型消费边界**：AI 只生成可逐项采纳或拒绝的结构化 Proposal，确认后再进入草稿、版本和发布流程；在采购履约案例中，发布模型用于形成 RESTful API 上下文、OpenAPI 草稿和正常／异常测试数据，正式契约由人工审核。

### 多端一致性驱动的 HATEOAS 资源契约｜上海易校信息科技有限公司·轻流

针对低代码平台中 PC Web 与移动 Web 重复维护状态、角色、权限和导航规则的问题，主动推动 HATEOAS 改造；先以统一 TypeScript SDK 收敛多端消费，再向上游延伸到业务建模与 RESTful API 设计。

- **试点与方案推动**：最初在 `workspaces` 接口返回 `_links`，由 PC 侧边栏和移动端首页按 relation 消费导航；通过方案评审和案例演示说明改造只需停留在 API 表达层，不改库改表，必要时还可由 BFF 承接。
- **从契约倒推模型与 API**：在 relation 和 action 设计中识别资源边界与生命周期，使用四色建模梳理实体、角色和业务事件，再据此设计 RESTful URI 与编辑、发布、撤销等动作契约；与后端共同落地 API 表达。
- **契约消费与质量保障**：设计并实现 TypeScript SDK 和 React Hooks，将 relation、action、缓存与状态更新转化为多端易用接口，并使用泛型、Zod、单元测试、契约测试与 E2E 验证契约消费。
- **渐进迁移结果**：试点后，应用、表单和工作流继续沿用同一 API 表达方式迁移；后端调整权限或可访问页面时，多端前端不再分别修改对应规则。

个人从 0 到 1 独立开发 AI 驱动的桌面端 D2C / T2UI 设计工具，主导编辑器内核、Agent 生成、MCP 接入和桌面端工程；当前核心交付聚焦高质量设计 DSL 与可编辑设计文档。

- **设计 DSL 与编辑器**：以设计 DSL 统一 AI、React DOM 编辑器、`.fig` 导入和 MCP 读取的数据结构，设计 Frame、Rectangle、Ellipse、Icon、Text 等核心节点与正交属性模型；EditorSession 通过不可变文档替换和订阅通知同步图层、视口与属性面板。
- **Agent 生成与质量闭环**：实现 Codex Provider、Coordinator + Collaborator 分区生成、Generation Run 状态机、区域脚手架与 Fragment 串行合并，并使用 `expectedRevision`、JSON Schema 和运行时校验约束写入；以 `validate → repair → revalidate` Visual Harness 控制生成质量。
- **MCP 与桌面端工程**：实现 5 类只读 MCP 设计资产工具、内容寻址资源协议和 Sidecar / Bridge 进程通信，处理请求超时、消息上限、应用未启动及开发／打包路径差异，并完成 Electron 三入口构建与 Fuses 安全加固。

### 企业级低代码工作流引擎｜上海易校信息科技有限公司·轻流

面向公司内部人员、企业客户和研发团队建设企业级低代码工作流引擎，把应用生命周期模型与 RESTful / HATEOAS 契约继续转化为 Schema、工作流协议、可视化编辑器和 TypeScript 执行引擎，并与后端协作完成服务端落地。

- **生命周期与资源契约**：使用四色建模区分应用、可编辑工作流定义、不可变发布版本和执行记录，将模型映射为 RESTful / HATEOAS 资源与动作；发布记录保留版本 ID，使设计态、发布态和运行态能够按明确版本追溯。
- **执行引擎**：设计 `WorkflowDefinition`、`Node`、`Edge` 和变量协议，实现 `WorkflowEngine`、`GraphBuilder`、`ExecutionContext`、`VariableResolver`，使用 Kahn 算法完成拓扑排序、环检测及条件分支调度。
- **插件与编辑器**：通过 `NodeRegistry + NodeExecutor` 扩展 Start、HTTP、Condition、End 等节点；基于 React Flow 和 Tiptap 实现可视化编排、节点配置及 `${nodeId.variableName}` 变量编辑。
- **发布与执行反馈**：负责发布管理、测试运行和执行日志界面，按共同契约对接后端实现的 NestJS 与 SSE 服务，展示节点状态、日志和错误反馈。
