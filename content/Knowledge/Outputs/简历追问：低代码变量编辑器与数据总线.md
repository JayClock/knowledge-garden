# 简历追问：低代码变量编辑器与数据总线

关联：[[15分钟：低代码平台]]、[[简历回答逐字稿：低代码变量编辑器与数据总线]]、[[3.AI 工作流引擎编辑器与执行器架构设计与实践]]。

## 对应简历描述

> 基于 Tiptap 实现工作流变量编辑器，将 `${nodeId.variableName}` 渲染为不可拆分的原子标签，通过 `/` 菜单选择上游输出，并在保存与回显时完成富文本节点和纯文本协议之间的双向转换。

## 面试官真正想确认

你是否用稳定协议连接了编辑体验与运行时变量解析，而不是依赖易错的字符串拼接或 `eval`。

## 连续追问链

### 1. 编辑器模型

- 为什么普通 textarea 不适合混合普通文本和变量引用？
- 变量标签为什么必须是原子节点？
- 标签中显示什么，持久化时保存什么？
- 节点展示名修改后，为什么 nodeId 引用仍然稳定？

### 2. 输入与转换

- `/` 菜单怎样获取上游节点的输出定义？
- 用户选择变量后怎样插入 `variableMention`？
- 保存时怎样序列化为 `${nodeId.variableName}`？
- 回显时怎样把纯文本重新解析为 Tiptap 节点？

### 3. 执行上下文

- ExecutionContext 怎样按 nodeId 隔离输出？
- VariableResolver 怎样解析一个变量表达式？
- 怎样递归处理字符串、数组和对象里的变量？
- 为什么未解析变量保留原表达式，而不是静默替换为空字符串？
- 执行反馈怎样帮助定位保留下来的原始引用？
- 发布期静态校验与运行时动态解析在系统设计中如何权衡？

### 4. 架构延伸与安全

- 当前变量协议为什么不需要 `eval`？
- 若需支持高级计算，Lexer、Parser、AST 与沙箱执行该如何设计？
- 跨文档粘贴、节点删除后的失效提示和自动迁移是否有证据？

## 场景推演题

> HTTP 节点 B 的 URL 引用了 `${A.customerId}`。后来节点 A 修改了展示名称，但 nodeId 不变。请说明编辑器标签、持久化文本和运行时取值为什么不会受影响。

继续追：如果 B 引用了未命中分支的输出，为什么保留原表达式比静默空值更容易排查？如果以后增加发布校验，应怎样区分静态可判定引用和运行时分支结果？

## 准备证据

- Tiptap `variableMention` 节点结构。
- `/` 菜单插入变量的代码。
- 富文本与纯文本协议的序列化／反序列化示例。
- ExecutionContext 和 VariableResolver 代码。

## 面试注意事项

- 讲清 Tiptap 富文本标签与纯文本协议（`${nodeId.variableName}`）之间的序列化与反序列化机制，避免简单当成字符串替换。
- 说明变量依赖底层稳定 nodeId，实现界面呈现名称与底层引用标识的解耦。
- 说明 VariableResolver 递归解析结构化数据的安全求值过程。
- 阐明缺失变量保留原表达式的容错机制，便于在执行反馈中定位问题引用。
- 清楚区分富文本变量编辑器机制与复杂 AST 公式求值链路的边界。
