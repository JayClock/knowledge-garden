# 项目介绍：基于权责关系的领域建模与 API 设计

## 项目介绍

过去我们进行建模和需求理解的时候，使用的是头脑风暴的方式，这种方式会带来很多干扰项，导致最终的建模结果，强依赖于个人经验，很难再团队中推广和验证。

借此，我从财务经营视角出发，设计了一套以合同上下文为起点，寻找合同参与方，使用什么证据来证明双方完成了各自的权利与义务的方法。

以我们网上购物为例，我们之所以能拿到商品，是因为我们和商家签订了一份合同，称之为订单。而这份合同约定了，拿货是我们的权利，而发货是商家的义务。同样的，商家能正常收到钱，也是因为合同规定了，收钱是商家的权利，而付款时我们的义务。基于此我们再继续追溯可以用作证据的凭证，从而找到，通过第三方物流凭证证明了商家完成了发货义务，而第三方支付凭证，证明我们完成了付款的义务。

这是合同正常运作的情况，我们还有异常运作的情况，比如商家要求付款，但是用户没有付款，那么这个订单就会被取消。如果这个订单是个特殊的预订单，那么商家就有权不退预付款。同样的，如果商家没有按时发货，用户有权申请退款，如果这个退款流程依旧异常，往往意味着我们不得不通过法律流程，才能强制商家退款，这条权责关系链就结束了，不需要再往下

在这个过程人负责提供真实的业务约定，ai 不断追问这个约定需要什么证据证明达成，以及约定执行异常会带来什么新的权利和义务。

建模完成后，我们再从角色出发，按照时间顺序重新描述流程，让业务方确认模型是否符合实际做法。如果发现分歧，那么基于实际做法重新修订模型，继续核对。

在这样的方法下，由于有法律边界的存在，ai 的追问是有限的，而且几乎不会偏离真实的业务流程。我们对需求的讨论，从 2 个小时的无效会议，变成了半个小时就能得到多方可达成共识的理解。而有了清晰的领域模型，我们就可以设计 api 接口和测试数据，用于 ai coding 的 loop 验证结果，从而我们再验收的时候，可以专注于做的怎么样，而非有没有做对。
