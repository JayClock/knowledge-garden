# 简历追问：多人实时协同的 AI 辅助领域建模平台

关联：[[简历回答逐字稿：多人实时协同的 AI 辅助领域建模平台]]。

## 对应简历描述

> 将参与方、权责、事件、领域对象和关系沉淀为前端与后端共同审核、持续消费的业务语义契约；直接负责 React Flow 前端、Y.Doc／Awareness、NestJS WebSocket 协同服务与 PostgreSQL 持久化，并让发布模型支持 RESTful API、OpenAPI 草稿和测试数据候选。

## 面试官真正想确认

你能否解释这份前后端契约来自什么业务知识、由谁审核、怎样发布和消费，而不是把契约缩成接口文档；同时确认你真正理解共享内容、临时状态、连接生命周期、长期持久化、CRDT 收敛、AI Proposal 和正式模型发布之间的边界。

## 连续追问链

### 1. 前后端契约与个人范围

- 前端和后端原来分别在哪里重复解释业务对象、生命周期、关系和动作？
- 为什么领域模型是双方共同审核的语义契约，而不是前端交付给后端的一张图？
- 业务、前端、后端、AI 和发布版本分别拥有什么权威？
- 为什么把领域模型做成多人协同平台？
- React Flow、Yjs、Awareness、WebSocket Gateway 和 PostgreSQL 分别由谁实现？
- 真实业务场景（如 WMS 采购合同履约）在平台中跑通了哪些模型节点与业务契约？
- 协同建模平台在内部业务与研发团队之间的协作流转机制是怎样的？

### 2. 共享内容与临时状态

- 哪些建模数据进入 Y.Doc？
- 在线成员、光标和选区为什么进入 Awareness，而不是数据库？
- `messageSync` 与 `messageAwareness` 的职责如何区分？
- 客户端卸载时需要断开什么、移除哪些监听？

### 3. 连接、路由与文档生命周期

- 平台开发早期为什么会出现路由已切换、编辑器仍显示旧内容？
- `pageId` 应该怎样影响 Fragment、编辑器初始化和 Provider 生命周期？
- 服务端怎样按建模空间获取或创建 Y.Doc？
- 一个文档怎样管理自己的连接集合和广播范围？
- ping 检测、关闭事件和 Awareness 清理分别解决什么问题？
- 最后一个连接离开后，为什么要先持久化再释放文档实例？

### 4. 部署、同步与长期持久化

- 本地 WS 正常，部署到 HTTPS 后为什么需要 WSS？
- 为什么第一次改成 WSS 后仍要继续适配同源反向代理入口？
- 为什么没有直接使用 y-websocket 默认的 LevelDB？
- PostgreSQL 适配层在文档初始化和退出活跃状态时分别做什么？
- 高频增量同步与长期数据库保存为什么要分开？
- 如何处理数据库状态与内存 Y.Doc 的恢复边界？
- 哪些断线重连和服务重启恢复测试尚未完成？

### 5. CRDT 与领域正确性

- Yjs 的最终收敛能够保证什么，不能保证什么？
- 两个人同时修改同一领域对象后，为什么仍需模型评审？
- 技术一致性、业务语义正确性和发布版本治理怎样分层？

### 6. AI Proposal 与模型生命周期

- Proposal 包含哪些新增、修改和删除操作？
- 用户如何定位、预览、采纳和拒绝变更？
- 为什么 AI 不能直接覆盖正式模型？
- 草稿、版本、发布模型和知识图谱分别承担什么职责？

### 7. 8X Flow 与模型驱动交付

- 为什么库销存 Agent 需要先建立可审计的采购履约事实？
- 参与方、角色、请求、确认和 Evidence 怎样形成追溯链？
- 发布模型如何成为 OpenAPI 草稿和测试数据的上下文？
- 为什么 OpenAPI 必须人工审核后才能进入下游代码生成？

### 8. 稳定模型基线与受控增强

- 不使用 AI 时，人工建模、审核、版本和发布是否能完成完整主链路？有哪些验证？
- Yjs 协同对这个产品是基础能力还是增强能力？为什么不能只按技术名词判断？
- AI Proposal 为什么不能成为正式模型的唯一写入入口？
- AI 服务或协同服务不可用时，当前实现是回退、只读、单人模式还是直接失败？
- 哪些降级属于真实项目事实，哪些是后续补强建议？

## 场景推演题

> 用户从页面 A 切换到页面 B，URL 已经变化，但编辑器仍显示 A 的内容。请说明怎样从 React 路由、Fragment 标识、Y.Doc / Provider 生命周期和 Awareness 清理定位问题。

继续追：本地 WS 正常但 HTTPS 部署失败时，为什么只把协议改成 WSS 仍可能不够？修复后怎样验证页面切换没有重新引入旧内容？

## 准备证据

- Y.Doc 与 WebsocketProvider 的初始化和释放代码。
- 页面路由切换后的数据标识绑定与生命周期清理修复实现。
- 生产部署中 WSS 协议和反向代理同源 Upgrade 地址的配置与修复记录。
- Awareness 状态读取、监听和清理代码。
- `messageSync`、`messageAwareness`、连接集合、ping 与关闭处理代码。
- PostgreSQL 适配层的初始化恢复与最终写回代码。
- AI Proposal Schema、逐项采纳／拒绝界面和异常输出样例。
- 8X Flow 采购履约模型、OpenAPI 草稿和人工审核材料；没有材料时不补编细节。
- 领域建模、版本发布、OpenAPI 契约生成与下游测试数据样例。

## 面试注意事项

- 清楚区分技术层 CRDT 状态收敛与业务层领域语义正确性，说明人工 Gate 的必要性。
- 解释协同协议中 `messageSync`（文档协同）与 `messageAwareness`（临时状态）的分工，避免混同持久化。
- 阐明服务端基于连接生命周期的优雅释放与基于 PostgreSQL 的写回机制。
- 明确 AI 仅输出符合 Schema 的候选 Proposal，正式草稿与模型版本必须由人工审核确认。
- 准确定位开发联调阶段的路由生命周期与 WSS 部署调试经验，客观说明问题上下文。
- 说明模型驱动契约导出（OpenAPI 草稿、契约测试用例）的下游衔接流程。
