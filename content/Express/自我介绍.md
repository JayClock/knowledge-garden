> 懂建模、懂全栈架构、能主导复杂 AI 工程化平台设计的专家

面试官你好，我做了大约 5 年的前端开发与全栈架构设计，核心技术栈是 [[../Knowledges/React|React]]、TypeScript 以及 Node.js。相比在需求下来时直接开始堆砌页面，我更习惯先把业务的领域模型、系统边界和资源契约想清楚。因此，我通常在团队里负责**复杂前端系统、AI 智能体平台以及前端基础设施**的从 0 到 1 设计。

在过去的工作中，我主导和深度参与了几个比较有代表性的项目：

**第一个是以 Workspace 为中心的 [[./15分钟面谈：多智能体协同平台|多智能体（Multi-Agent）协同工作台]]**。这个项目要解决的核心问题是传统长任务 Agent 带来的“黑盒化”和“状态撕裂”。我没有把它做成一个简单的聊天外挂，而是系统性地落地了**AI 全栈的六层架构**：
在**编排和交互层**，我推行了 JSON Schema 驱动的动态 Agentic UI，并用双缓冲和交互锁解决了高频流式推送带来的 UI 抖动；在**运行时和观测层**，我深度借鉴了 React Fiber 的可中断渲染思想，将大模型长任务切分为可持久化的 Trace 实体支持断点重试，并用流式解析与虚拟化技术搞定了数十兆巨型 Trace 树的极速渲染；在**安全层**，我建立了基于“证据驱动”的 Review 门禁，用 Worker 下放 [[../Cards/Diff 算法|Diff 算法]]并结合严格的 DOMPurify 防范注入，真正做到了大模型生成代码的“可追溯、可观测、绝对安全”。

**第二条核心技术线是：[[15分钟面谈：HATEOAS 请求管理|基于 HATEOAS 的全栈资源契约架构]]**。为了解决传统 REST API 在复杂 SaaS 中导致的逻辑臃肿与接口硬编码，我让前端彻底退位为 `UI=f(state)` 的呈现层，所有按钮与操作完全由后端返回的超媒体链接（Links）动态驱动。这不仅实现了前后端契约的极度解耦，也为后续大模型自主调用接口（Tool Use）铺平了技术基石。

**第三块是低代码底座中的核心引擎——[[15分钟面谈：公式编辑器|复杂逻辑表达式编辑器]]**。为了让非技术人员安全地编排业务流转条件，我彻底抛弃了危险的 `eval`，手写 Lexer 与 Parser，在前端构建了纯粹的 AST 执行沙箱。并结合 Tiptap 实现了变量原子化插入与高精度光标跟随，大幅提升了平台的安全底线与表达能力。

**最后一块是前端基础设施建设——[[15分钟面谈：前端埋点与监控 SDK|高可靠无侵入埋点与监控 SDK]]**。我摒弃了高侵入的编程式埋点，基于 [[../Cards/React 合成事件|React 合成事件]]原理设计了声明式采集方案；并利用 IntersectionObserver、静默退避重试（Exponential Backoff）等技术，在极端弱网和海量长列表场景下，为公司打造了一个不阻塞主线程、99.9% 可靠的数据监控基座。

**总结我的核心优势：**
1. **具备极致的复杂系统抽象与架构能力**：不论是 AST 编译解析、[[低代码|低代码]] Schema，还是巨型数据的虚拟化渲染，都能快速转化为稳定落地的工程基建。
2. **端到端的全栈与建模视野**：深谙[[../Knowledges/领域驱动设计|领域驱动设计]]（DDD），能从根本上重塑前后端契约（如 HATEOAS），大幅降低跨团队沟通与大模型对接成本。
3. **对 AI 全栈落地有深刻的实战经验**：不仅会调大模型 API，更能从交互、编排、运行时、安全到观测层，完整把控多智能体协作的每一个工程痛点（如中断重试、防撕裂、大树渲染）。
