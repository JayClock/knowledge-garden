>懂建模、懂全栈架构、能主导复杂平台设计的工程师

面试官你好，我做了大约 5 年的前端开发，核心技术栈 是 [[../Knowledges/React|React]]、TypeScript 以及 Node.js。相比在需求 下来时直接开始堆砌页面，我更习惯在先把业务的领域模型、系统边界和资源契约想清楚，再去设计前端如何应用接口，管理数据。因此，我通常在团队里负责**复杂前端系统、平台型产品以及前端基础设施**的设计。

在过去的工作中，我主导和深度参与了几个比较有代表性项目分别是：

**第一个是以 workspace 为中心，[[15分钟面谈：多智 能体协同平台|基于 acp 的多智能体（Multi-Agent）软 件编码工具]]**。这个项目要解决的核心问题是分散在各处 AI 助手在真实研发中往往面临上下文超载和职责混乱。我没有把它做成一个简单的聊天外挂，而是引入了基于 Kanban（看板）的任务编排与职责分离机制，将需求拆 解、代码实现和审查流水线化。基于“证据驱动”的多层质量门禁，让多智能体协作真正的可追溯，确保代码的可信任性。

**在这个平台中，我还主导了第二条核心技术线：[[15分钟面谈：HATEOAS 请求管理|HATEOAS 资源契约升级]]** 。为了解决传统硬编码的 REST API 在复杂功能下的逻辑臃肿问题。我封装了完整的 TS 客户端，让前端按钮和操作完全由后端返回的链接动态驱动，实现了前后端对接的的极度解耦，也为 mcp，agent 等工具提供了一套统一的接口格式

**第三块是低代码编排平台中的核心组件——[[15分钟面谈：公式编辑器|公式编辑器]]**。为了让非技术人员能灵活编排复杂业务，我们在基于 JSON Schema 的低代码底座上，重点攻克了动态逻辑表达的难题。最具挑战的是，我基于 AST 实现了公式解析校验与安全执行沙箱，并利用 Tiptap 实现了变量的原子化插入与语法高亮，大幅提升了平台的表达能力与用户体验。

**最后一块是在前端基础设施建设上，我主导了全链路监控与[[15分钟面谈：前端埋点与监控 SDK|埋点 SDK]] 的开发**。这条线体现了我在工程化和数据治理上的思考。我没有采用高侵入的 UI 埋点，而是基于“领域事件”设计了声明式采集方案，并实现了弱网离线存储、断网续传和智能采样，在不对主业务造成性能影响的前提下，为平台提供了可靠的数据基座。

**我个人的核心优势呢，其实是**
首先是**具备复杂系统的抽象能力**，能快速将凌乱的业务逻辑转化为稳定的架构（如 AST 解析、低代码 Schema、事件模型）；
第二，**拥有端到端的全栈视野**，不排斥后端与建模，偏向于通过[[../Knowledges/领域驱动设计|领域驱动设计]]（DDD）用来降低沟通成本 和约束 ai 的行为；
第三，**对 AI 工程化有深度实践**，对如何管理多智能体协作上下文有成熟的落地经验。

 对于上面我讲**多智能体任务编排与上下文建模**、**HATEOAS 的自描述前端消费链路**、**低代码底座与 AST 公式引擎的设计**，以及**SDK 的领域事件埋点架构**。看您希望先从哪块开始聊？
