# 全栈工程师简历成品版（可直接改）

## 标题

全栈工程师

## 个人简介

偏前端出身的全栈工程师，具备复杂工作台、AI 上下文建模、配置化研发底座与前端基础设施的端到端研发经验。擅长先抽象业务对象、系统边界和资源契约，再落到工作台交互、schema / DSL、表达式引擎、监控埋点和性能治理等具体能力建设，能够从页面实现延伸到后端接口、上下文装配、状态同步与可观测治理。

## 技术栈

TypeScript、JavaScript、Java、React 19、Vite、Fastify、Spring Boot、Jersey JAX-RS、MyBatis、SQLite、PostgreSQL、HATEOAS、HAL / HAL-FORMS、Web Vitals、监控 / 埋点 SDK、知识图谱、DDD、Nx Monorepo、Gradle

## 项目顺序建议

1. Team AI
2. 轻流低代码平台与公式编辑器
3. 前端监控、埋点与性能治理
4. HATEOAS 请求管理（按岗位可选）

## Team AI

一句话：面向软件交付场景构建 AI 上下文建模平台，通过统一建模 goal / intake、spec、card、conversation、trace 和 resource，让 AI 在不同阶段获得稳定、可追溯、可程序化消费的交付上下文。

- 主导 Team AI 上下文建模抽象，围绕 project、goal、spec、board、card、conversation、trace、resource 等对象建立统一资源关系与状态骨架。
- 前端构建项目工作台、Kanban、卡片详情、会话与 trace 视图，后端参与资源契约、实时事件流、状态同步与治理规则，形成前后端一体化闭环。
- 将 intake、拆解、执行、review、结果回写串成可观测链路，让 AI 的理解、执行和回写落在同一套交付上下文里。

## 轻流低代码平台与公式编辑器

一句话：围绕 schema / DSL、插件化扩展、渲染运行时和表达式引擎，搭建服务通用 SaaS 场景的配置化研发底座。

- 主导轻流低代码平台核心能力建设，围绕复杂表单 schema、通用表格交互规范、仪表盘编辑器与渲染引擎推进平台化抽象。
- 主导公式编辑器关键能力建设，将业务表达式从输入框问题升级为词法分析、语法分析、AST 和安全执行的表达式引擎。
- 推动统一 JSON / schema 配置模型、插件化扩展机制与工程体系建设，提升复杂业务配置效率、规则复用能力和平台演进能力。

## 前端监控、埋点与性能治理

一句话：围绕监控 SDK、埋点 SDK、Web Vitals 和性能治理闭环，建设可采集、可校准、可告警、可防回归的前端基础设施能力。

- 设计并实现监控 SDK / 埋点 SDK 的核心能力，覆盖事件模型、上下文补充、批量上报、失败重试和 `sendBeacon` 兜底。
- 建立 `TTFB`、`FCP`、`LCP`、`INP`、`CLS` 等指标采集、校准、归因和告警机制，将性能问题从主观感知转成可观测数据。
- 结合性能排查、指标治理和防回归机制，推动团队从“修一次卡顿”升级到“持续性能治理”。

## HATEOAS 请求管理

一句话：面向多消费端场景的资源契约消费层，通过 HAL / HAL-FORMS 统一资源导航、动作发现和动态表单消费方式。

- 基于 Team AI 等多消费端场景沉淀并抽象 HATEOAS 请求管理库，支持基于 link / method / template 的资源导航与动作发现，降低前端对 URL 和接口结构的硬编码依赖。
- 封装链式 `follow(rel)` 调用、动作模板解析、分页关系消费、缓存与请求去重能力，减少页面层样板代码并提升资源访问一致性。
- 统一 Web 与其他客户端的权限和动作发现逻辑，为动态表单、资源驱动 UI 和 AI Agent 共用同一套 API 契约提供支撑。

## 一句收口

这份简历的核心不是展示我会多少前端技术，而是说明我已经能从工作台交互延伸到业务建模、上下文装配、schema 驱动配置化、表达式引擎、监控埋点与性能治理，具备偏前端出身但能把整条链路打通的全栈工程师能力。
