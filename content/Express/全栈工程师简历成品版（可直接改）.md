# 全栈工程师简历成品版（可直接改）

## 标题

全栈工程师

## 个人简介

偏前端出身的全栈工程师，具备复杂工作台、平台型系统、前端基础设施与资源驱动架构的端到端研发经验。擅长先抽象业务模型、系统边界和状态流，再落到工作台交互、执行控制面、表达式引擎、监控埋点和性能治理等具体能力建设，能够从页面实现延伸到后端接口、任务编排、状态一致性与可观测治理。

## 技术栈

TypeScript、JavaScript、Java、React 19、Vite、Fastify、Spring Boot、Jersey JAX-RS、MyBatis、SQLite、PostgreSQL、HATEOAS、HAL / HAL-FORMS、Web Vitals、监控 / 埋点 SDK、知识图谱、DDD、Nx Monorepo、Gradle

## 项目顺序建议

1. Team AI AI 原生工作台 / 多智能体协同交付平台
2. 轻流低代码平台与公式编辑器
3. 前端监控、埋点与性能治理
4. HATEOAS 请求管理（按岗位可选）

## Team AI 三条式

- 主导 Team AI 核心对象抽象，围绕 project、task、session、board、trace 等对象沉淀统一语义和执行链路。
- 前端基于 React 构建项目工作台、会话页、Kanban 和执行控制面，后端参与任务编排、实时事件流和治理能力建设，形成前后端一体化闭环。
- 将需求 intake、任务拆解、执行委派、Review 和结果回写串成闭环，提升 AI 在真实交付流程中的可用性和可治理性。

## 轻流低代码平台与公式编辑器三条式

- 负责低代码平台核心能力建设，围绕表单 schema、通用表格、仪表盘编辑器和渲染引擎推进平台化抽象，支撑多类 SaaS 场景复用。
- 主导公式编辑器关键能力建设，将业务表达式从输入框问题提升为词法分析、语法分析、AST 和安全执行的表达式引擎。
- 推动统一 JSON / schema 配置模型、插件化扩展机制与 Nx monorepo 工程体系建设，提升复杂业务配置效率和平台演进能力。

## 前端监控、埋点与性能治理三条式

- 设计并实现监控 SDK / 埋点 SDK 的核心能力，覆盖事件模型、上下文补充、批量上报、失败重试和 `sendBeacon` 兜底。
- 建立 `TTFB`、`FCP`、`LCP`、`INP`、`CLS` 等指标采集、校准、归因和告警机制，将性能问题从主观感知转成可观测数据。
- 结合性能排查、指标治理和防回归机制，推动团队从“修一次卡顿”升级到“持续性能治理”。

## HATEOAS 请求管理三条式

- 设计并实现基于 HAL / HAL-FORMS 的资源消费模型，抽象 Resource、Relation、Template 等核心对象，支持 follow(rel) 语义导航、模板解析、分页关系消费和缓存去重。
- 将前端请求逻辑从 URL 和 payload 硬编码提升为资源关系驱动，使 Web 与 AI Agent 能共用一套接口契约，降低前后端演进耦合。
- 基于 React Hooks 封装单资源读取、分页集合和动作模板消费能力，减少页面层样板代码并提升多端一致性。

## 一句收口

这份简历的核心不是展示我会多少前端技术，而是说明我已经能从工作台交互延伸到业务建模、执行控制面、表达式引擎、监控埋点与性能治理，具备偏前端出身但能把整条链路打通的全栈工程师能力。
