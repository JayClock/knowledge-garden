## 项目经历

### 配置化交付平台（低代码引擎 / 规则表达）

项目简介

此平台服务于轻流多条 SaaS 产品线（CRM / HRM / ERP）的配置化交付场景，目标不是做单一的搭页面工具，而是将表单、列表、详情、仪表盘与业务规则配置从“研发交付”转为“配置交付”，缓解业务扩张后重复页面研发与客户定制交付的线性成本问题。

工作内容与成果

☻ **Schema 协议与插件化渲染引擎设计**：主导基于 Schema 的插件化渲染引擎，将页面、字段、数据源、权限、校验与生命周期抽象为统一协议，核心引擎负责解析 Schema、调度生命周期与渲染插件，业务能力通过插件注册扩展，使常规配置类需求从「周级研发排期」压缩到「天级配置与验收」。
☻ **大表单精确渲染与联动性能优化**：围绕几百字段表单、复杂联动与动态校验场景，在 React 上层维护字段依赖收集图，避免字段变化触发整棵组件树重渲染，支撑复杂表单在高联动场景下的可用性能与稳定交互。
☻ **仪表盘海量数据分片更新**：针对多图表看板下的数据聚合与渲染压力，将重计算放入 Web Worker，主线程通过 `requestAnimationFrame` 与批处理队列分片更新，降低海量数据回传时的卡顿与内存膨胀风险。
☻ **AST 受控执行引擎与安全沙箱**：从零设计 Lexer → Parser → AST 的解析与执行链路，通过受控解释器替代直接 `eval`，并限制执行过程只访问显式注入的字段上下文、只读变量与白名单函数，使业务规则配置从字符串盲执行转为可解析、可校验、可测试的结构化能力。
☻ **基于 Tiptap 的规则编辑体验与复用设计**：基于 Tiptap / ProseMirror 将业务字段封装为原子化胶囊节点，配合实时语法高亮、函数提示、参数说明与错误定位降低非研发人员的盲写成本，并围绕 AST 结构、函数白名单与执行缓存设计前后端共享的规则表达模型，减少重复解析开销与前后端规则漂移风险。

### 全链路埋点与监控 SDK

项目简介

此埋点 SDK 面向轻流平台的前端数据采集与异常观测场景，目标不是做大而全的数据平台，而是沉淀一套低侵入、高可靠、可降级的前端 SDK，让业务事件、曝光事件、接口异常与公共上下文能够稳定回流到产品、研发、测试与运营反馈链路中。

工作内容与成果

☻ **声明式采集机制设计**：参考顶层事件委托思路，让业务通过 DOM 或组件配置声明事件语义，由 SDK 在统一监听入口结合 `event.composedPath()` 溯源事件与上下文，降低在业务函数中散落 `track()` 调用带来的侵入性、误删与漏采风险。
☻ **曝光采集与公共上下文补齐**：针对长列表与动态渲染场景，基于 `IntersectionObserver` 完成曝光判断、去重与批量队列处理，并自动补齐页面路径、来源、用户、租户、会话、版本等公共上下文，提升前端采集的一致性与数据可消费性。
☻ **可靠上报与离线续传链路**：建立 `sendBeacon → fetch keepalive → IndexedDB 离线队列续传` 的多级兜底链路，通过批次上报、退避重试、幂等 id 与限流策略，应对页面卸载、弱网、断网等场景下关键事件易丢失的问题。
☻ **运行隔离与接口异常观测**：对 Fetch / XHR 监控采用旁路封装，采集接口耗时、状态码、错误类型与页面上下文，同时保证不改变原请求 Promise、headers、body、AbortController 与错误抛出语义，使 SDK 自身异常只影响监控能力，不拖垮主业务链路。

### HATEOAS 资源契约架构

项目简介

此项目聚焦企业级 SaaS 中复杂状态机、多角色、多端协作下的规则漂移问题，目标不是做一层请求封装，而是将散落在 Web、小程序、App 前端中的 `status / role / permission` 判断收敛为后端返回的资源动作契约，让前端从“解释业务规则”转向“消费当前资源状态下的合法动作”。

工作内容与成果

☻ **资源动作契约消费层设计**：主导前端 HATEOAS 消费层，将当前资源可执行的动作通过 `_links` / `_templates` 与资源状态一起返回，前端基于 relation 与 action 消费契约，降低状态机规则在多端重复实现带来的联动改动与测试回归成本。
☻ **TypeScript SDK 与类型安全约束**：设计基于 relation 图谱遍历的 TypeScript 客户端 SDK，封装 `follow()` 与 `action()` 等能力，并结合泛型约束与运行时校验，尽量让 relation、action 与 payload 在开发期可提示、在运行期可验证。
☻ **兜底状态与错误标准化处理**：围绕资源加载失败、动作缺失、契约缺失、链式导航中断等场景，区分资源不可用、动作不可执行、网络错误与鉴权失败等状态，为 UI 层提供一致的禁用、隐藏、重试与错误反馈策略。
☻ **复杂列表性能与缓存一致性优化**：针对复杂列表下动作自发现的性能压力，配合后端批量权限预计算、前端按需展开与虚拟列表降低渲染成本，并通过资源缓存与依赖失效策略减少资源打散后的重复请求与状态不一致风险。

### 多智能体协同平台

项目简介

此平台面向 AI 参与软件交付后的治理问题，将需求理解、执行过程、测试证据、Review 与 Gate 显式建模为可观察、可审查、可接管的人机协作流程，解决 AI 代码生成速度提升后上下文缺失、审查成本后移和责任边界模糊的问题。

工作内容与成果

☻ **交付流程编排与责任边界设计**：将多智能体协作建模为 `Todo → Dev → Review → Gate` 的交付状态机，把结构化计划、验收标准、风险点、执行证据与放行条件绑定到阶段流转中，让 AI 协作从对话式输出转为可治理的软件交付流程。
☻ **Kanban 工作台与高频流式状态稳定化**：设计基于 Kanban 的人机协作界面，面向 SSE 高频推送的 token、工具调用、文件变更与状态切换，使用缓冲队列、批量合并与交互锁降低 UI 抖动、状态撕裂与信息乱序风险。
☻ **Trace / Evidence 观测与恢复能力建设**：将长任务拆解为可恢复步骤，沉淀输入、输出、依赖、耗时、工具结果与文件变更等 Trace 信息，让任务中断后可以基于证据链定位断点、恢复上下文并决定重试、回退或人工接管。
☻ **安全渲染与动态 Agentic UI**：基于 Schema 动态渲染不同 Agent 节点的输入输出表单，并对 Markdown、HTML 片段与代码 Diff 做安全渲染与高风险确认展示，降低大模型输出带来的 XSS 注入与审查误判风险。
