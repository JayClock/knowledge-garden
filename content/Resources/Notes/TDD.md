# 什么是 TDD
测试驱动开发将个体的开发活动，变成了工程化的研发过程。避免**无计划的手动验证**和**手动**的启发式定位（[[./Cynefin框架|Cynefin框架]]中的庞杂模式），它们替换为**有计划的自动化验证测试**和**有计划的逐模块自动化排查**([[./Cynefin框架|Cynefin框架]]中的复杂模式)
# 为什么要学 TDD
为了提高工程效能：软件开发过程中，至少一半以上的时间是在发现问题、定位问题、修复问题上。理论上来说，这些问题大部分不是根本性问题。而 TDD，不仅提供了可工作的代码，还额外提供了帮助定位问题的测试，以此来大幅提升工程效能。
# TDD 的难点
1. 理解需求，并将需求分解为功能点
	需求是否理解？
	对当前的架构是否了解？
	当前架构是否到了需要演化的时间节点
2. 核心要素：任务分解
