# TDD 的工程优势
> 在“理解需求，明白架构”是一切工程化软件开发的前提，那么 TDD 就是目前已知的**效能最高**的办法[^1]

1. 从“工程管理”的角度，降低了“判断一个人**是否理解了需求**”的成本：**看测试就行**
2. 从”工程管理“的角度，降低了”判断哪个需求应该从工程化交付模式进入探索模式“的成本：**看测试就行**
3. 通过**功能上下文以及任务项拆分的情况**，判断**成员是否认同并理解了架构**，架构只有成员**全体人员的共识**，才能真正发挥作用。
4. 通过**功能上下文以及任务项拆分的情况**，降低了判断当前架构是否能够当前实现成本，及时推进架构的演化。

[^1]: https://time.geekbang.org/column/article/496703
